> **编辑器测试在 `Assets/Tests/EditMode` 的分类子目录里，只留 Edit Mode 里直接能断言的。** `CatchMoon.Tests.asmdef` 留在该目录根上。结果写在 `Logs/TestResults.xml`。命令行跑测试时用 `-testResults Logs/TestResults.xml`。生命、体力、库存成败已经落在公开字段或 `bool` 返回值上。命中动画和镜头仍要等人看。0.x 不写用例。

## 现状

公开字段可以当结果读。计算写在 `MonoBehaviour` 上，调用前要先有同一物体上的 `CharacterManager`。

| 形态 | 代表 | 单独调用时还要什么 |
| --- | --- | --- |
| 资产上的数 | `Item`、`WeaponItem`、`SpellItem`、`FlaskItem`、`EnemyAISettings` | 只是字段。加减发生在持有它们的角色脚本里 |
| 有返回值的实例方法 | `CharacterStatsManager.TakeDamage` / `DeductStamina` / `DeductMP` / `AddHP`，`PlayerInventoryManager.TrySpendConsumable` / `TrySpendAmmo` / `AmmoRemaining` / `ConsumableRemaining`，`CharacterWeaponSlotManager.LoadWeaponOnSlot`，`State.Tick` | `Awake` 缓存的组件。玩家子类还会写 HUD |
| 静态过程 | `MeleeAttackSegment.Play` | 写 `lastAttack`、`attackType`，并调用 `PlayTargetAnimation` |
| Animator | `HandleRollState`、`HandleAttackState`、`HandleEmptyState`，以及 `CharacterAnimatorManager` 上给片段调用的 `DrainStamina`、`OpenDamageCollider`、`ApplyPendingDamage` | 状态机进入该状态。这些方法是 `void` |
| 物理回调 | `DamageCollider.OnTriggerEnter`，`SpellDamageCollider` / `BombDamageCollider.OnCollisionEnter`，`DamagePlayer.OnTriggerEnter`，`CriticalAttackAction` 的 `Physics.Raycast`，`IdleStateHumanoid` 的 `OverlapSphere` 与 `Linecast`，`PlayerLocomotionManager.HandleFall` 的落地射线 | 至少一步物理或一帧 `Update`。画面可以不看，回调必须发生 |

代表性入口：

- 伤害：`DamageCollider.DealDamage` → `CharacterCombatManager.ResolveIncomingHit` → `CharacterStatsManager.TakeDamage`。`PlayerStatsManager` 与 `EnemyStatsManager` 覆盖 `TakeDamage`，扣血之后写血条，生命到 0 时 `Death`。
- 战斗输入：`PlayerCombatManager` 在 `Update` 里读 `InputManager` 上的公开布尔，清掉后调用武器资产上的 `WeaponItemAction.PerformAction`。这些 `Handle_*` 是私有的。
- 物品：`PlayerInventoryManager.HandleUseConsumableInput` → `ConsumableItem.AttemptToConsumableItem`。血瓶是 `FlaskItem`，数量走 `TrySpendConsumable`。法术由 `MagicSpellAction` 比较 `currentMP`，再进 `ProjectileSpell.AttemptToCastSpell` 或 `HealingSpell.AttemptToCastSpell`。
- 敌人：`EnemyManager.HandleStateMachine` 调用 `currentState.Tick`，返回的 `State` 赋给私有字段 `currentState`。人形待机是 `IdleStateHumanoid.Tick`。换完之后读 `CurrentState`。

## 代理能读到的反馈

代理不需要打开 Game 视图，只要同一次运行里能读成员、读日志或读进程退出码。

已经能读的：

1. **返回值。** `TakeDamage`、`AddHP`、`DeductHP`、`AddStamina`、`DeductStamina`、`AddMP`、`DeductMP` 返回是否改了数值。`TrySpendConsumable`、`TrySpendAmmo` 返回是否扣到库存。`AmmoRemaining` 返回剩余箭数。`ConsumableRemaining` 返回这一件还剩几次。`EnemyManager.CurrentState` 返回当前状态。`LoadWeaponOnSlot`、`WeaponHolderSlot.LoadWeaponModel` 返回模型是否装上。直接调用 `State.Tick` 时，返回的 `State` 就是下一状态。
2. **随后落在公开字段上的数。** `currentHP`、`maxHP`、`currentStamina`、`currentMP`、`isDead`、`isInvulnerable`、`totalPoiseDefence`、`poiseResetTimer`、`soulCount`、`attackType`、`lastAttack`、`isBlocking`、`isAttacking`、`isInAir`、`isSprinting`、`moveDir`、刚体 `linearVelocity`。同一次入伤结束时读 `lastHitWasBlocked`、`lastHitBrokePoise`、`lastHitDamageTotal`。`AddSouls` 改 `soulCount` 时同时写灵魂数字。`healthLevel * 10` 这类换算发生在 `CharacterStatsManager.Awake`，之后读 `maxHP` 即可，换算方法是私有的。
3. **日志。** `PlayTargetAnimation` 在控制器里没有该状态时打 `Debug.LogError($"{name}: Animator 没有状态 {targetAnim}")`。`LoadWeaponOnSlot` 在模型为空时打 `"model is null."`。`EnemyManager.Start` 以及若干 UI 脚本在引用为空时打错误。这些进 Editor.log / Player.log。`TakeDamage` 里打印最终伤害的那一行已经注释掉，伤害数字不进日志。
4. **退出码。** 玩法代码不根据验收结果退出进程。编辑器 batchmode 跑测试时，非零退出码来自 Test Runner。现在的用例在 `CatchMoon.Tests`。

字段和日志里没有、需要对着时间轴或画面看的：

- 方向受击动画名在 `DamageCollider` 的 `protected` 字段 `currentDamageAnimation` 上，打完不另存。挡住、破韧和五段合计已在 `lastHitWasBlocked`、`lastHitBrokePoise`、`lastHitDamageTotal`。护甲折算后的合计仍是 `TakeDamage` 里的局部变量。
- 格挡、翻滚、落地、喝药播了哪一段：近战片段会写 `lastAttack`。其余 `PlayTargetAnimation` 只留下 `isInteracting`、`canRotate`，以及「没有该状态」的错误。片段内容、根运动位移要看角色。
- 粒子、血溅、HUD 填充、锁定框。血量在 `currentHP`。`PlayerStatsManager` 的覆盖还会调用 `healthBar.SetCurrentHP`；`healthBar` 为空时在改完字段之后、死亡判断之前空引用。基类在 `playHurtSound == false` 且动画名为 `null` 时可以只改生命。
- `CombatStanceStateHumanoid` 上 `willPerformBlock` 等决策仍是序列化私有字段。当前状态读 `CurrentState`。`currentState` 仍是带 `[SerializeField]` 的私有字段。
- `HandleMove`、`HandleFall`、`HandleRoll` 是私有的。`rollCost`、`jumpCost`、`backStepCost` 是序列化私有字段；`sprintCost`、`sprintNeedMinStamina` 是公开字段。冲刺可以直接读消耗常数。翻滚要在 `DeductStamina` 发生之后看 `currentStamina` 的差。

## 按行为核对

「读哪里」都是现有成员。卡点是这次调用离命令行判断还缺的那一步。

### 伤害与生命

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 是否扣血、是否因死亡或无敌被拒 | `TakeDamage` 的 `bool`；`currentHP` | 基类要已 `Awake` 的 `CharacterManager`。动画名非空时会 `PlayTargetAnimation`；`playHurtSound` 为真时要 `cSoundFX`。两个都关掉时，能只看生命 |
| 护甲后的伤害 | 调用前后的 `currentHP` 差 | 公式在 `TakeDamage` 内部。头 0.6、躯干 0.3、髋 0.1 的权重写在方法里。护甲折算后的合计仍是局部变量。`lastHitDamageTotal` 是进 `TakeDamage` 之前的五段合计 |
| 玩家是否因此死亡 | `isDead`，以及 `currentHP <= 0` 后 `PlayerStatsManager.TakeDamage` 调用 `Death` | 玩家覆盖先改 HUD。`healthBar` 为空则到不了后面的死亡判断 |
| 敌人死亡发灵魂、Boss 半血换阶段 | `soulCount`（`AddSouls`）；`isInvulnerable`、`isPhaseShifting`、`BossCombatStanceState.hasPhaseShifted` | `AddSouls` 同时写 `soulCount` 和灵魂数字。死亡发魂用 `Awake` 里留下的玩家。`UpdateBossHealthBar` 用同一处留下的 `WorldManager` 写 Boss 血条 |
| 近战是否命中 | 目标的 `currentHP`、`totalPoiseDefence` | `OnTriggerEnter` 才进 `DealDamage`。同一窗口没有「已命中」标记，重复进入会再结算。要有一步物理 |
| 法术弹、炸弹、环境伤害 | 同上，法术和炸弹走 `TakeDamage(..., fd: ...)` | `hasCollided` 在碰撞后吞掉后续。炸弹溅射是 `OverlapSphere`，并跳过直击那一个 `CharacterStatsManager`。入口是碰撞回调 |

`ResolveIncomingHit` 在 `applyBlockAndPoise == false` 时（背刺、反击）直接 `TakeDamage`。为真时先把指向攻击者的向量归一化，点积大于 0.3 再 `AttemptBlock` 并按格挡吸收减伤；`DeductStamina` 失败时先 `EmptyStamina`。否则扣 `totalPoiseDefence`，剩余高于本次 `poiseDamage` 时动画名为 `null`。这些分支随后体现在体力、生命、`isBlocking`、动画调用，以及 `lastHitWasBlocked`、`lastHitBrokePoise`、`lastHitDamageTotal` 上。

### 体力与蓝

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 扣体力、扣蓝是否成功 | `DeductStamina` / `DeductMP` 的 `bool` 和对应的 `current*` | 玩家覆盖成功后写 `staminaBar` / `focusPointsBar` |
| 自然恢复 | 间隔大于 1 秒后的 `currentStamina` | `RegenerateStamina` 看 `isInteracting`、`isSprinting`、`isBlocking` 和 `Time.deltaTime`。格挡中用 `staminaRegenerationAmountWhilstBlocking` |
| 攻击扣体力 | `AttackStaminaCost` 的返回值 | `DrainStamina` 仍只在动画事件里调用。测试不进这个事件，只断言静态公式 |
| 格挡是否被破 | `DeductStamina` 失败时 `EmptyStamina` 把 `currentStamina` 写成 0；之后 `<= 0` 时 `AttemptBlock` 把 `isBlocking` 写成 false，并播 `"Guard_Break"` | `AttemptBlock` 不返回破防与否。玩家的 `EmptyStamina` 和成功的 `DeductStamina` 都会刷新体力条 |
| 法术是否扣蓝 | `ProjectileSpell` 和 `HealingSpell` 都在 `DeductMP` 为真之后才继续 | `MagicSpellAction` 先要求 `currentMP >= focusPointCost`，加血仍要等动画事件 `SuccessfullyCastSpell` |
| 冲刺每步消耗 | `sprintCost`，以及 `HandleMove` 里冲刺分支对 `DeductStamina` 的调用 | `HandleMove` 在 `FixedUpdate`，且 `isInteracting` 或 `rollFlag` 时整段返回 |

### 物品

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 消耗品、箭是否扣掉 | `TrySpendConsumable` / `TrySpendAmmo` | 字典在 `Awake` 创建，数量初值是资产上的 `maxItemAmount` / `maxCnt`。玩家死亡时 `Update` 不再处理按键，这两个方法仍可调用 |
| 剩余箭、剩余次数 | `AmmoRemaining`、`ConsumableRemaining` | 已有公开读法。字典 `consumableLeft` 仍是私有的 |
| 喝血瓶是否加血 | 使用完成后的 `currentHP`（`FlaskItem.SuccessfullyUsedConsumable` → `AddHP`） | `Attempt` 成功只扣数量并 `PlayTargetAnimation`。加血在动画事件里。失败播 `"Shrug"`，方法是 `void` |
| 背包增减 | `items` / `weapons` / `armors` / `spells` / `consumables` 的内容 | `AddItem` / `RemoveItem` 是 `void`。之后看列表里有没有该引用 |
| 武器是否装上 | `LoadWeaponOnSlot` 的 `bool`，模型为空时的 `Debug.LogError` | 成功路径还会 `animator.Play`、挂伤害体。返回值只表示模型放进槽 |

### 出招、移动、敌人

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 轻击或重击选了哪段 | `MeleeAttackSegment.Play` 之后的 `lastAttack`、`cCombat.attackType`；体力耗尽或交互中时 `LightAttackAction.PerformAction` 直接返回 | 静态方法仍调用 `PlayTargetAnimation`。两手都没在用时，非连击只写下 `attackType`。哪只手由调用前的 `isUsingRightHand` 决定 |
| 输入有没有被吃掉 | `InputManager` 上的 `tap_e_Input` 等，处理过后会被写成 false | 处理函数是私有的，只在玩家未死亡的 `Update` 里跑。之后看 `currentItemBeingUsed`、`lastAttack`、`isInteracting` |
| 翻滚、后撤、跳跃是否起步 | `DeductStamina` 为真之后，`HandleRollState` / `HandleJumpState` 写入的 `isRolling` / `isJumping` | 消耗发生在 `PlayerLocomotionManager` 的私有方法里，旗标要等动画状态进入。两个时刻隔着一帧动画 |
| 人在地上还是空中、速度 | `isInAir`、`moveDir`、`rigidBody.linearVelocity` | `HandleFall` 用射线写 `isInAir`，并可能 `PlayTargetAnimation("Falling")` / `"Land"`。坡度系数在 `HandleMove` 里，不单独返回 |
| 敌人是否发现目标、下一状态是谁 | 直接调用时读 `Tick` 的返回值；运行中读 `CurrentState`、`currentTarget`、`distFromTarget` | 待机检测用 `OverlapSphere` 和 `Linecast`，层是 `LayerMask.player`。`SwitchToNextState` 写入私有 `currentState`，外面读 `CurrentState` |
| 背刺或反击是否开始 | `isPerformingBackSttbbed`、`isBeingBackStabbed`、`isPerformingRiposted`、`isBeingRiposted`，以及随后的 `currentHP` | `CriticalAttackAction.PerformAction` 先做 `Physics.Raycast`。点积和 `canBeRiposted` 的判断留在方法内部。`GetBackStabbed` 还要开协程改父子物体 |

## 以后若要让代理跑验收

0.x 不写用例。1.x 只给该版改动里、Edit Mode 直接能断言的行为写测试。程序集是 `CatchMoon.Tests`，引用 `CatchMoon`。不加事件总线、注入容器或另一套实体框架。`MeleeAttackSegment` 先不补用例。

1. **先读现成的。** 生命、体力、蓝、死亡、库存成败、剩余箭、`ConsumableRemaining`、武器槽的 `bool`、`lastAttack`、`attackType`、`Tick` 的返回值、`CurrentState`、`soulCount`、`lastHitWasBlocked`、`lastHitBrokePoise`、`lastHitDamageTotal`。玩家子类会写 HUD 时，对的是 `CharacterStatsManager` 上的数值字段。`AddSouls` 改灵魂数时同时写 HUD。HUD 引用缺失会在子类覆盖里抛错，这条错误已经会进日志。
2. **必须多留一点结果时，写在现有方法上。** 原先停在局部变量或私有字段上的三处，现在已经能读：
   - `CharacterCombatManager`：`lastHitWasBlocked`、`lastHitBrokePoise`、`lastHitDamageTotal`。护甲折算后的数字仍看 `currentHP` 的差。
