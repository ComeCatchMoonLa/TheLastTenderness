# 可测试性

> **编辑器测试在 `Assets/Tests/EditMode`，只留 Edit Mode 里直接能断言的。** 生命、体力、库存成败已经落在公开字段或 `bool` 返回值上。命中动画和镜头仍要等人看。0.x 不写用例。

基于当前 `Assets/Scripts`。调用关系见 [构架设计.md](构架设计.md)，公开入口见 [接口设计.md](接口设计.md)，改一处要看的文件见 [可维护性与性能.md](可维护性与性能.md)。

本仓库规则：0.x 不写单元测试。1.x 只给该版改动写测试，而且只写 Edit Mode 里现成就能断言的：调用不依赖 `Awake` 写进私有字段的引用，也不依赖已经初始化的 Animator（`HasState`、`SetBool`、`CrossFade`）。方法里本来就会打的 Error，用 `LogAssert.Expect` 接住。要先把角色拼起来、走物理回调或等一帧 `Update` 才能看到结果的，不写用例。断言用已经公开的返回值和字段。粒子、镜头、动画曲线靠人看。不另起一套战斗框架，不为了测试把方法改成 `virtual`，也不为了测试进入 Play Mode。历史的 0.x 脚本不回头补测试。

按这条留下的用例：1.2 瞄准进入和退出时玩家胶囊半径、非玩家的 `isAiming`；1.3 武器模型为空时 `LoadWeaponModel` 返回 false，已有模型还在；1.4 护甲有无时的模型和五段吸收；1.5 手动逐句开始后文本是全文且列表少一句；1.6 画质六档的文案、等级和环绕；1.7 帧率四档的文案、上限数字和环绕；1.8 后处理两档文案和切换两次回到原档；1.9 特效两档文案和切换两次回到原档。1.0 的 `ResolveIncomingHit`、1.1 的 `MeleeAttackSegment` 先不写。

## 仓库里实际有的测试

| 位置 | 内容 |
| --- | --- |
| `Assets/Scripts` | 运行时代码在程序集 `CatchMoon`。这里没有 `[Test]` |
| `Assets/Tests/EditMode` | `CatchMoon.Tests`。1.2 瞄准半径、1.3 缺模型、1.4 护甲换模和五段吸收、1.5 手动逐句的全文、1.6 画质六档与环绕、1.7 帧率四档与环绕、1.8 后处理两档文案、1.9 特效两档文案 |
| `Packages/manifest.json` | 没有直接依赖 `com.unity.test-framework`。`packages-lock.json` 里它由 `com.unity.feature.development` 带入（该 feature 声明 1.7.0） |

`Assets/Scripts` 里没有 C# `event`、`UnityEvent`、静态 `Instance`。跨物体查找用 `FindAnyObjectByType`，例如 `EnemyStatsManager` 找 `PlayerManager` 和 `WorldManager`。

## 现状

公开字段可以当结果读。计算写在 `MonoBehaviour` 上，调用前要先有同一物体上的 `CharacterManager`。

| 形态 | 代表 | 单独调用时还要什么 |
| --- | --- | --- |
| 资产上的数 | `Item`、`WeaponItem`、`SpellItem`、`FlaskItem`、`EnemyAISettings` | 只是字段。加减发生在持有它们的角色脚本里 |
| 有返回值的实例方法 | `CharacterStatsManager.TakeDamage` / `DeductStamina` / `DeductMP` / `AddHP`，`PlayerInventoryManager.TrySpendConsumable` / `TrySpendAmmo` / `AmmoRemaining`，`CharacterWeaponSlotManager.LoadWeaponOnSlot`，`State.Tick` | `Awake` 缓存的组件。玩家子类还会写 HUD |
| 静态过程 | `MeleeAttackSegment.Play` | 写 `lastAttack`、`attackType`，并调用 `PlayTargetAnimation` |
| Animator | `HandleRollState`、`HandleAttackState`、`HandleEmptyState`，以及 `CharacterAnimatorManager` 上给片段调用的 `DrainStamina`、`OpenDamageCollider`、`ApplyPendingDamage` | 状态机进入该状态。这些方法是 `void` |
| 物理回调 | `DamageCollider.OnTriggerEnter`，`SpellDamageCollider` / `BombDamageCollider.OnCollisionEnter`，`DamagePlayer.OnTriggerEnter`，`CriticalAttackAction` 的 `Physics.Raycast`，`IdleStateHumanoid` 的 `OverlapSphere` 与 `Linecast`，`PlayerLocomotionManager.HandleFall` 的落地射线 | 至少一步物理或一帧 `Update`。画面可以不看，回调必须发生 |

代表性入口：

- 伤害：`DamageCollider.DealDamage` → `CharacterCombatManager.ResolveIncomingHit` → `CharacterStatsManager.TakeDamage`。`PlayerStatsManager` 与 `EnemyStatsManager` 覆盖 `TakeDamage`，扣血之后写血条，生命到 0 时 `Death`。
- 战斗输入：`PlayerCombatManager` 在 `Update` 里读 `InputManager` 上的公开布尔，清掉后调用武器资产上的 `WeaponItemAction.PerformAction`。这些 `Handle_*` 是私有的。
- 物品：`PlayerInventoryManager.HandleUseConsumableInput` → `ConsumableItem.AttemptToConsumableItem`。血瓶是 `FlaskItem`，数量走 `TrySpendConsumable`。法术由 `MagicSpellAction` 比较 `currentMP`，再进 `ProjectileSpell.AttemptToCastSpell` 或 `HealingSpell.AttemptToCastSpell`。
- 敌人：`EnemyManager.HandleStateMachine` 调用 `currentState.Tick`，返回的 `State` 赋给私有字段 `currentState`。人形待机是 `IdleStateHumanoid.Tick`。

## 代理能读到的反馈

代理不需要打开 Game 视图，只要同一次运行里能读成员、读日志或读进程退出码。

已经能读的：

1. **返回值。** `TakeDamage`、`AddHP`、`DeductHP`、`AddStamina`、`DeductStamina`、`AddMP`、`DeductMP` 返回是否改了数值。`TrySpendConsumable`、`TrySpendAmmo` 返回是否扣到库存。`AmmoRemaining` 返回剩余箭数。`LoadWeaponOnSlot`、`WeaponHolderSlot.LoadWeaponModel` 返回模型是否装上。直接调用 `State.Tick` 时，返回的 `State` 就是下一状态。
2. **随后落在公开字段上的数。** `currentHP`、`maxHP`、`currentStamina`、`currentMP`、`isDead`、`isInvulnerable`、`totalPoiseDefence`、`poiseResetTimer`、`soulCount`、`attackType`、`lastAttack`、`isBlocking`、`isAttacking`、`isInAir`、`isSprinting`、`moveDir`、刚体 `linearVelocity`。`healthLevel * 10` 这类换算发生在 `CharacterStatsManager.Awake`，之后读 `maxHP` 即可，换算方法是私有的。
3. **日志。** `PlayTargetAnimation` 在控制器里没有该状态时打 `Debug.LogError($"{name}: Animator 没有状态 {targetAnim}")`。`LoadWeaponOnSlot` 在模型为空时打 `"model is null."`。`EnemyManager.Start` 以及若干 UI 脚本在引用为空时打错误。这些进 Editor.log / Player.log。`TakeDamage` 里打印最终伤害的那一行已经注释掉，伤害数字不进日志。
4. **退出码。** 玩法代码不根据验收结果退出进程。编辑器 batchmode 跑测试时，非零退出码来自 Test Runner。现在的用例在 `CatchMoon.Tests`。

字段和日志里没有、需要对着时间轴或画面看的：

- `ResolveIncomingHit` 里格挡是否成立（局部变量 `successfulBlocked`）、破韧与否、减伤后的五段伤害。方法是 `void`。方向受击动画名在 `DamageCollider` 的 `protected` 字段 `currentDamageAnimation` 上，打完不另存。
- 格挡、翻滚、落地、喝药播了哪一段：近战片段会写 `lastAttack`。其余 `PlayTargetAnimation` 只留下 `isInteracting`、`canRotate`，以及「没有该状态」的错误。片段内容、根运动位移要看角色。
- 粒子、血溅、HUD 填充、锁定框。血量在 `currentHP`。`PlayerStatsManager` 的覆盖还会调用 `healthBar.SetCurrentHP`；`healthBar` 为空时在改完字段之后、死亡判断之前空引用。基类在 `playHurtSound == false` 且动画名为 `null` 时可以只改生命。
- 消耗品剩余个数。箭有 `AmmoRemaining`。消耗品字典 `consumableLeft` 是私有的，对外只有 `TrySpendConsumable` 的成败。
- 运行中的敌人当前状态。`currentState` 是带 `[SerializeField]` 的私有字段。`Update` 里换状态不留公开字段。能直接读的是 `currentTarget`、`distFromTarget`、`targetDirAngle`、`enableAI`。`CombatStanceStateHumanoid` 上 `willPerformBlock` 等决策也是序列化私有字段。
- `HandleMove`、`HandleFall`、`HandleRoll` 是私有的。`rollCost`、`jumpCost`、`backStepCost` 是序列化私有字段；`sprintCost`、`sprintNeedMinStamina` 是公开字段。冲刺可以直接读消耗常数。翻滚要在 `DeductStamina` 发生之后看 `currentStamina` 的差。

## 按行为核对

「读哪里」都是现有成员。卡点是这次调用离命令行判断还缺的那一步。

### 伤害与生命

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 是否扣血、是否因死亡或无敌被拒 | `TakeDamage` 的 `bool`；`currentHP` | 基类要已 `Awake` 的 `CharacterManager`。动画名非空时会 `PlayTargetAnimation`；`playHurtSound` 为真时要 `cSoundFX`。两个都关掉时，能只看生命 |
| 护甲后的伤害 | 调用前后的 `currentHP` 差 | 公式在 `TakeDamage` 内部。头 0.6、躯干 0.3、髋 0.1 的权重写在方法里。最终伤害没有返回值，也没有字段 |
| 玩家是否因此死亡 | `isDead`，以及 `currentHP <= 0` 后 `PlayerStatsManager.TakeDamage` 调用 `Death` | 玩家覆盖先改 HUD。`healthBar` 为空则到不了后面的死亡判断 |
| 敌人死亡发灵魂、Boss 半血换阶段 | `soulCount`（`AddSouls`）；`isInvulnerable`、`isPhaseShifting`、`BossCombatStanceState.hasPhaseShifted` | `AwardSoulsOnDeath` 和 `UpdateBossHealthBar` 用 `FindAnyObjectByType` 找玩家和 `WorldManager`，并写 UI |
| 近战是否命中 | 目标的 `currentHP`、`totalPoiseDefence` | `OnTriggerEnter` 才进 `DealDamage`。同一窗口没有「已命中」标记，重复进入会再结算。要有一步物理 |
| 法术弹、炸弹、环境伤害 | 同上，法术和炸弹走 `TakeDamage(..., fd: ...)` | `hasCollided` 在碰撞后吞掉后续。炸弹溅射是 `OverlapSphere`，并跳过直击那一个 `CharacterStatsManager`。入口是碰撞回调 |

`ResolveIncomingHit` 在 `applyBlockAndPoise == false` 时（背刺、反击）直接 `TakeDamage`。为真时先把指向攻击者的向量归一化，点积大于 0.3 再 `AttemptBlock` 并按格挡吸收减伤；`DeductStamina` 失败时先 `EmptyStamina`。否则扣 `totalPoiseDefence`，剩余高于本次 `poiseDamage` 时动画名为 `null`。这些分支随后体现在体力、生命、`isBlocking` 和动画调用上。

### 体力与蓝

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 扣体力、扣蓝是否成功 | `DeductStamina` / `DeductMP` 的 `bool` 和对应的 `current*` | 玩家覆盖成功后写 `staminaBar` / `manaBar` |
| 自然恢复 | 间隔大于 1 秒后的 `currentStamina` | `RegenerateStamina` 看 `isInteracting`、`isSprinting`、`isBlocking` 和 `Time.deltaTime`。格挡中用 `staminaRegenerationAmountWhilstBlocking` |
| 攻击扣体力 | 攻击过后的 `currentStamina` | `DrainStamina` 只在动画事件里调用，读当前手的 `baseStaminaCost` 与 `laStaminaCostM` / `haStaminaCostM` |
| 格挡是否被破 | `DeductStamina` 失败时 `EmptyStamina` 把 `currentStamina` 写成 0；之后 `<= 0` 时 `AttemptBlock` 把 `isBlocking` 写成 false，并播 `"Guard_Break"` | `AttemptBlock` 不返回破防与否。玩家的 `EmptyStamina` 和成功的 `DeductStamina` 都会刷新体力条 |
| 法术是否扣蓝 | `ProjectileSpell` 在 `DeductMP` 为真之后才播动画；`HealingSpell` 调用 `DeductMP` 后仍播动画 | 治疗这条不看扣蓝的 `bool`。`MagicSpellAction` 先要求 `currentMP >= focusPointCost`，加血仍要等动画事件 `SuccessfullyCastSpell` |
| 冲刺每步消耗 | `sprintCost`，以及 `HandleMove` 里冲刺分支对 `DeductStamina` 的调用 | `HandleMove` 在 `FixedUpdate`，且 `isInteracting` 或 `rollFlag` 时整段返回 |

### 物品

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 消耗品、箭是否扣掉 | `TrySpendConsumable` / `TrySpendAmmo` | 字典在 `Awake` 创建，数量初值是资产上的 `maxItemAmount` / `maxCnt`。玩家死亡时 `Update` 不再处理按键，这两个方法仍可调用 |
| 剩余箭 | `AmmoRemaining` | 已有公开读法。消耗品剩余个数没有对应查询 |
| 喝血瓶是否加血 | 使用完成后的 `currentHP`（`FlaskItem.SucessfullyUsedConsumable` → `AddHP`） | `Attempt` 成功只扣数量并 `PlayTargetAnimation`。加血在动画事件里。失败播 `"Shrug"`，方法是 `void` |
| 背包增减 | `items` / `weapons` / `armors` / `spells` / `consumables` 的内容 | `AddItem` / `RemoveItem` 是 `void`。之后看列表里有没有该引用 |
| 武器是否装上 | `LoadWeaponOnSlot` 的 `bool`，模型为空时的 `Debug.LogError` | 成功路径还会 `animator.Play`、挂伤害体。返回值只表示模型放进槽 |

### 出招、移动、敌人

| 观测什么 | 从哪读 | 卡在哪 |
| --- | --- | --- |
| 轻击或重击选了哪段 | `MeleeAttackSegment.Play` 之后的 `lastAttack`、`cCombat.attackType`；体力耗尽或交互中时 `LightAttackAction.PerformAction` 直接返回 | 静态方法仍调用 `PlayTargetAnimation`。两手都没在用时，非连击只写下 `attackType`。哪只手由调用前的 `isUsingRightHand` 决定 |
| 输入有没有被吃掉 | `InputManager` 上的 `tap_e_Input` 等，处理过后会被写成 false | 处理函数是私有的，只在玩家未死亡的 `Update` 里跑。之后看 `currentItemBeingUsed`、`lastAttack`、`isInteracting` |
| 翻滚、后撤、跳跃是否起步 | `DeductStamina` 为真之后，`HandleRollState` / `HandleJumpState` 写入的 `isRolling` / `isJumping` | 消耗发生在 `PlayerLocomotionManager` 的私有方法里，旗标要等动画状态进入。两个时刻隔着一帧动画 |
| 人在地上还是空中、速度 | `isInAir`、`moveDir`、`rigidBody.linearVelocity` | `HandleFall` 用射线写 `isInAir`，并可能 `PlayTargetAnimation("Falling")` / `"Land"`。坡度系数在 `HandleMove` 里，不单独返回 |
| 敌人是否发现目标、下一状态是谁 | 直接调用时读 `Tick` 的返回值；运行中读 `currentTarget`、`distFromTarget` | 待机检测用 `OverlapSphere` 和 `Linecast`，层是 `LayerMask.player`。`SwitchToNextState` 只改私有 `currentState` |
| 背刺或反击是否开始 | `isPerformingBackSttbbed`、`isBeingBackStabbed`、`isPerformingRiposted`、`isBeingRiposted`，以及随后的 `currentHP` | `CriticalAttackAction.PerformAction` 先做 `Physics.Raycast`。点积和 `canBeRiposted` 的判断留在方法内部。`GetBackStabbed` 还要开协程改父子物体 |

## 以后若要让代理跑验收

0.x 不写用例。1.x 只给该版改动里、Edit Mode 直接能断言的行为写测试。程序集是 `CatchMoon.Tests`，引用 `CatchMoon`。不加事件总线、注入容器或另一套实体框架。`ResolveIncomingHit` 和 `MeleeAttackSegment` 先不补用例。

1. **先读现成的。** 生命、体力、蓝、死亡、库存成败、剩余箭、武器槽的 `bool`、`lastAttack`、`attackType`、`Tick` 的返回值、`soulCount`。玩家子类会写 HUD 时，对的是 `CharacterStatsManager` 上的数值字段。HUD 引用缺失会在子类覆盖里抛错，这条错误已经会进日志。
2. **必须多留一点结果时，写在现有方法上。** 这三处的结果现在停在局部变量或私有字段上：
   - `CharacterCombatManager.ResolveIncomingHit`：格挡是否成立、破韧与否、扣到 `currentHP` 上的最终伤害。
   - `PlayerInventoryManager`：与 `AmmoRemaining` 并列的消耗品剩余。字典已经存在。
   - `EnemyManager` 在 `Update` 里换状态之后：外界要能读到当前 `State`。直接调用 `Tick` 时返回值已经够用。
3. **输出落到代理能扫的地方。** 用 Unity Test Framework 时，失败写在断言消息里，Test Runner 的结果、日志和非零退出码都能看到。`PlayTargetAnimation` 的「Animator 没有状态」已经会进 Editor.log。
4. **画面类的结论留在手动验收。** 粒子、镜头、血条填充、动画曲线，字段和测试覆盖不到。

VRM 自带的测试目录已经不在磁盘上。
