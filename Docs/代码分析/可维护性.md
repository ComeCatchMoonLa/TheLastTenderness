# 可维护性

> **结论基于当前 `Assets/Scripts`（251 个脚本）。** 模块怎么连连同系统入口见 [构架设计.md](构架设计.md)，旗标、动画名和伤害签名见 [接口设计.md](接口设计.md)，帧内物理查询与堆分配见 [性能.md](性能.md)，测试边界见 [可测试性.md](可测试性.md)。

现有结构是 `MonoBehaviour`、Animator 的 `StateMachineBehaviour` 和 `ScriptableObject`。下面说的可扩展，都是在这三样已经有的挂钩上多加一条资产、一个状态或一处分支。

## 可读性

> **文件夹能看出模块，一条行为仍要同时看旗标、动画名和某个 Manager。** 没有手写函数达到约 300 行（最长 `SettingsWindowManager` 324 行、`PlayerCameraManager` 361 行；最长手写方法是 `ResolveIncomingHit` 约 93 行；生成的 `InputActions.cs` 1937 行不计）。

**平铺文件数偏多的目录。** 约定的舒适规模约一层 15 个，现在 `Character/NPC/` 34 个（根 17 + State 子目录）、`Items/` 85 个、`Character/` 根 26 个、`World/` 根 21 个。State 已按 General / Humanoid / Boss 分子目录，Items 已按 Actions / Equipment / Spells / Consumables / Interactions 分；继续加文件时优先放进现有子目录，而不是平铺。

公开方法 `SuccessfullyGetArrow` 与片段事件同名。粒子寿命写在预制体/粒子 Stop Action 上（旧的 `DestroyAuto` 已删）。

同一件事有多套名字：专注点是类 `FocusPointsBar`、HUD 字段 `focusPointsBar`、属性 `currentMP`、等级 `focusLevel`。下身换模类是 `HipsModelChanger`，装备是 `Hips`，槽枚举是 `armor_Hips_Slot`。

`PlayWeaponTrialFX` 转到 `WeaponFX`，播的是 `ParticleSystem`。

`CharacterManager` 上的公开布尔值由多处写入。读 `PlayerLocomotionManager.HandleMove` 要先知道 `isInteracting` 来自刚才哪一次 `PlayTargetAnimation`，还是 `HandleEmptyState` 已经清掉。冲刺在 `InputManager.HandleRollInput` 写，滞空在 `HandleFall` 写，跳跃和翻滚还要等对应的 `StateMachineBehaviour`。

**明显超长的脚本：**

- `PlayerCameraManager` 361 行：三种机位的切换、旋转和轴心偏移。跟随落点和撞墙距离在 `CameraRigMotion`，锁定扫描和换目标已拆到同物体的 `LockOnQuery`。
- `SettingsWindowManager` 324 行：画质、帧率上限、后处理和特效文案在 `DisplayQualityTable`、`FrameRateLimitTable`、`PostTreatmentQualityTable`、`SpecialEffectQualityTable`，套用逻辑抽到 `SettingsDisplayApply`。

伤害相关方法的参数个数明显超过约 5 个，改一次命中要在调用点对齐。五段 float 已打包成 `DamageSegments` / `IncomingDamage` 两个 struct，参数降下来了：

| 符号 | 参数 |
| --- | --- |
| `CharacterStatsManager.TakeDamage` | 动画名、`DamageSegments`、是否播受伤音（3 个） |
| `CharacterCombatManager.ResolveIncomingHit` | 攻击者、动画名、`IncomingDamage`、是否走格挡韧性、韧性伤害、破防系数、`spellFromFront`（7 个） |
| `CharacterAnimatorManager.PlayTargetAnimation` | 动画名、是否交互、`AnimationOptions`（旋转/镜像/根运动打包，3 个） |
| `MeleeAttackSegment.Play` | 角色、是否连击、`MeleeAnimations`（四段动画名打包）、两段 `AttackType`（5 个） |

注释多数复述下一行在做什么。`HandleMove` 里坡度系数 `2/sin(θ)-1` 的注释说明了下坡加速，是少见的在解释取舍。`Debug.LogError` 在缺槽、缺组件时于 `Start` 打出。快捷栏在 `QuickSlotsUI.ShowIcon` 里遇到空图标时清掉精灵并停用；槽位引用本身没接上时仍会报错。

## 可扩展性

> **加一种东西要改的位置是固定的，没有注册表。** 武器动作、法术和消耗品走 `ScriptableObject`；旗标和移动仍要进 Animator 状态或现有 `Handle*`。

| 想加的东西 | 现在要动的地方 |
| --- | --- |
| 一种新的轻击或重击 | 新的 `WeaponItemAction` 资产，在 `PerformAction` 里调用已有的 `PlayTargetAnimation`，武器槽填上这个资产。控制器里要有同名状态 |
| 第三下连击 | `AttackType`、`MeleeAttackSegment.Play`（现在只有第一段和第二段）、`DamageCollider.DealDamage`、`AttackStaminaCost`、动画字段 |
| 一个新法术学派 | `SpellType` 加成员，再写一个调用 `MagicSpellAction.PerformSpellAction` 的 Action 子类，做成资产填进武器槽。新效果还要新的 `SpellItem` 子类。投射物结算经 `CatalystMatch` 校催化器、`SpellMemory` 校记忆栏；复用 `ProjectileSpell` 时按 `spellType` 写五段中的一段。现有三系没有暗 |
| 一种消耗品 | 新的 `ConsumableItem` 子类，实现 `AttemptToConsumableItem` 和 `SuccessfullyUsedConsumable`。结算从动画事件 `SuccessfullyCastConsumable` 进来，优先读 `consumableBeingUsed` |
| 一个护甲部位 | 护手槽（第四部位）的字段与吸收已在，但没有护手模型切换：还要 `ModelChanger` 子类、`PlayerArmorManager.EquipAllArmorModels` 分支、`InventorySlotUI.EquipArmor`、装备窗槽位。再新部位则连 `ArmorType`、`EquipmentSlotType`、物品子类、五列吸收与 `TakeDamage` 的 60/30/10 一起动 |
| 一种伤害碰撞体 | 继承 `DamageCollider` 走触发器：`Start` 会把碰撞体设成 Trigger，命中进 `OnTriggerEnter`。走物理碰撞：像 `BombDamageCollider`、`SpellDamageCollider` 那样重写 `Start` 且不调基类，在 `OnCollisionEnter` 里自己做队伍判断 |
| 一种伤害属性 | `TakeDamage` 已有物理、火、魔、雷、暗五段（`DamageSegments`）。穿戴在 `EquipAllArmorModels` 写入，格挡在 `SetBlockingAbsorptionFromBlockingWeapon` 与 `SpellOnShield` 写入，近战碰撞体在 `LoadWeaponDamageCollider` 赋值。新段要在这三处再各接一次 |
| 一种新的移动 | Input Actions 订阅、`InputManager` 字段、一个 `Handle*`、通常再加一个 `StateMachineBehaviour` 写旗标。翻滚和跳跃还要放进 `PlayerManager.ResetCollider` 的排除条件，否则每帧会把胶囊写回默认尺寸 |
| 一种近战 AI 行为 | 待机、追击、转向在 General 的 `Tick` 上改；新规则优先做成静态纯函数（参照 `Territory`、`AllyCall`、`Leash`）。周旋仍是两套 `Tick`，选招走泛型化的 `AttackScore.PickIndex<T> where T : IAttackWindows` |
| 一种相机模式 | 在 `PlayerCameraManager.CameraPose` 和 `CurrentCameraPose` 加一支，再给跟随、旋转、偏移三个 `switch` 各加一案。偏移目标用三个 `CameraOffsetTarget`，缓动只在 `ApplyPivotOffset` |
| 一个画质档 / 帧率档 | `DisplayQuality_Options` + `DisplayQualityTable`，或 `FrameRateLimit_Options` + `FrameRateLimitTable`（`Label`/`Level`/`Next`/`Previous`） |

## 修改代价

> **同一条行为常常分成输入、动画状态、碰撞体和结算四段，各写在不同的 Manager 里。** 改伤害、物品效果或 AI 状态时，下面这些文件会一起动。

**旗标没有单一所有者。** `PlayTargetAnimation` 按参数（`AnimationOptions`）写下 `isInteracting`。全身层的 `HandleEmptyState` 在进入时清掉它；层名是 `Upper Body` 时直接返回，不清全身交互。`PlayerManager.ResetCollider` 在非翻滚、非跳跃时把胶囊中心和高度写回默认。`HandleAimingState` 在玩家进入瞄准时把半径写成 0.4，退出时写回。

**一次轻击或重击。** `PlayerCombatManager` 按按键顺序选 `oh_*` 动作，`LightAttackAction` / `HeavyAttackAction` 先判架势派生（`WeaponStance.TakeSwing`）和踢盾（`ShieldKick.IsKick`），再交给 `MeleeAttackSegment.Play` 选动画并写 `attackType`（成对武器由 `PairedWeapons.Select` 选手型）。`HandleAttackState` 进出时经 `AttackPoiseWindow.Open/Close` 管霸体。片段事件开 `DamageCollider`，命中在 `OnTriggerEnter`（先撞幻影墙、再过弹反帧窗 `ParryWindow`），格挡韧性在 `ResolveIncomingHit`，扣血在 `TakeDamage`。

**下落。** `HandleFall` 的射线、`PlayTargetAnimation("Falling")`、没有单独出口的 Falling 动画，以及 `HandleEmptyState` 清 `isInteracting`，是同一件事的四段。`"Land"` 只在这一物理步刚落地（`wasInAir`）时播放。

**瞄准。** 相机、移动、冲刺和准星读 `PlayerManager.aimingMode`。`AimAction` 在按住且有箭时把它写成 true，并写 `aimHeld` 供弓分快射/拉满（`BowShot`）。松开 Q、起跳、翻滚都会 `ClearAimingMode`。非玩家的 `HandleAimingState` 写 `CharacterCombatManager.isAiming`。

**喝药或扔炸弹。** X 键在 `PlayerInventoryManager.HandleUseConsumableInput`。数量先在 `TrySpendConsumable` 减，效果在动画事件。炸弹和血瓶按下时都把 `this` 记进 `consumableBeingUsed`。血瓶动画是否锁移动来自资产上的 `isInteracting`。

**穿一件甲。** `InventorySlotUI.EquipArmor` 按头、躯干、下身（护手槽暂不换模）分岔，旧件回背包、新件进装备格走 `ReplaceEquippedArmor`，再 `EquipAllArmorModels` 对各部位写五段吸收。`TakeDamage` 用 `CombinedArmorRate` 按头 60%、躯干 30%、下身 10% 合成。

**举盾。** `BlockAction` 把交互参数设为 false，并按当前手格挡吸收和稳定率。正面朝向在 `ResolveIncomingHit` 用点积大于 0.3 判；体力扣法在 `SpellOnShield.StaminaCost`。体力耗尽时 `EmptyStamina` 后破防，`GuardBreak.OpensRiposte` 把对方置为可制裁；踢盾命中（`ShieldKick`）直接清空被击者体力。格挡命中仍进 `TakeDamage`。

**背刺。** `CriticalAttackAction` 用 `BackstabLock` 做角度与一次性判定，立刻调 `GetBackStabbed`；后者用右手武器五段乘 `criticalAttackDM`，经 `ResolveIncomingHit`（不走格挡韧性）扣一次血。

**对话。** `Talk` 停掉大部分输入，不写 `isInteracting`。文案在 `DialogueTextData`，自动和跳过在 `GameSettingsData`。

**设置与暂停。** 改相机速度当场 `ApplyCameraSpeedSetting`；垂直同步写 `QualitySettings.vSyncCount`；画质/帧率/后处理/特效经 `SettingsDisplayApply` 写文案与引擎项。打开 ESC 窗口 `timeScale` 设 0，关回 1。

**换武器。** 切双手先改 `isTwoHandingWeapon` 再 `LoadWeaponsOnBothHands`。`modelPrefab` 为空时在销毁旧模型和取碰撞体之前返回。

**AI。** `EnemyManager.Update` 每帧跑当前状态 `Tick`。待机、追击、转向在 General 基类（人形状态继承它们）；选招统一走 `AttackScore.PickIndex<T>`；拉回放置点走 `Territory` + `Leash`，呼救走 `AllyCall`。

## 改内容仍要改代码

> **武器系数、AI 半径、台词正文、攻击列表、站位 `Transform`、界面层级已经在资产或预制体上。** 改一个数、一句玩家能看见的字、一条声音，或重排一种已有行为，下面这些位置仍要改 C#。交接合同在 [`../程序工作流解耦指导/README.md`](../程序工作流解耦指导/README.md)。注意：解耦指导要求新枚举从 1 或哨兵 0 起，而本仓 `EnumsTypes.cs` 的 21 个枚举与新增的 `CatalystKind`、`UpgradePath` 等仍全部从合法首项 0 起（仅 `CatalystKind.none=0` 带哨兵语义）——新代码应遵守指导，旧枚举编号不改。

**方法里的数。** 头、躯干、下身权重 60/30/10 在 `CharacterStatsManager.CombinedArmorRate`。`MemorySlotCount` 用一串 `if` 把集中力档位写成格数，`MemorySlotBonus.Total(focusLevel, bonuses[])` 再加戒指格。Boss 转阶段用资产 `phaseThreshold` 经 `BossPhase.ShouldShift`，不再写死半血。人形/通用周旋的绕圈系数 3f/1.4f 仍在方法里。

**玩家能看见的字。** `TalkUI.SetTalkerStatus` 在玩家说话时把名字写成 `"你"`；`"启用"`/`"禁用"` 在设置静态方法里。对白只读 `DialogueTextData.text`。

**声音。** `CharacterSoundFXManager` 持 `AudioClip`；空数组时 `PlayRandomDamageSoundsFX`、`PlayRandomWeaponWhoosh` 直接返回，否则 `PlayOneShot`（受伤音量 0.4）。篝火音在 `CampFireInteractable.campFireActivationSFX`。

**选招。** 距离和角度的 `attackScore` 加总后交给 `AttackScore.PickIndex`，下标再喂两套出手字段（人形 `ItemAttackWindows`、General/Boss `EnemyAttackWindows`），两者不并。

**缺了仍继续。** 缺槽、缺组件时 `Start` 打 `Debug.LogError` 后继续；`PlayTargetAnimation` 缺状态时报物体名和状态名。这套「吞不抛」与解耦策划数据合同（进入内容前拒绝非法配置）尚有距离，是后续要还的债。
