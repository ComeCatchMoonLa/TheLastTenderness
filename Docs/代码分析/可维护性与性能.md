# 可维护性与性能

> **结论基于当前 `Assets/Scripts`。** 模块怎么连在一起见 [构架设计.md](构架设计.md)，旗标、动画名和伤害签名见 [接口设计.md](接口设计.md)，测试边界见 [可测试性.md](可测试性.md)。

现有结构是 `MonoBehaviour`、Animator 的 `StateMachineBehaviour` 和 `ScriptableObject`。下面说的可扩展，都是在这三样已经有的挂钩上多加一条资产、一个状态或一处分支。

## 可读性

> **文件夹能看出模块，一条行为仍要同时看旗标、动画名和某个 Manager。** 超长的地方集中在设置窗口和相机；没有函数达到约 300 行。单文件夹脚本数量没有明显超过约 15 个。

公开名字有一批写进序列化、和含义对不上的拼写，改名会牵场景和预制体：目录 `Perfabs`，`SucessfullyGetArrow`、`SucessfullyUsedConsumable`，类名 `InputAcitons`。`timeUntilDestoryed` 仍写在两份特效预制体上，不在这一批名单里。

同一件事有多套名字：专注点是类 `FocusPointsBar`、HUD 字段 `manaBar`、属性 `currentMP`、等级 `focusLevel`。护甲换模类是单数 `HipModelChanger`，装备是 `Hips`，槽枚举是 `armor_Toros_Slot`。

字段注释和写入点不一致：

- `InputManager.rollFlag` 的注释写成「是否在翻滚」。写入点在 `HandleRollInput`，表示左 Shift 按下不足 0.5 秒后松开的一次性标记。翻滚状态是 `CharacterManager.isRolling`。
- `horizontal` 的注释写「垂直偏移」，`vertical` 的注释写「水平偏移」。
- `CharacterEffectsManager.Ammo` 的提示写飞行中的弹药。赋值在 `CharacterAnimatorManager.SucessfullyGetArrow`，放的是 `loadedItemModel`。飞出去的模型是 `ShootArrowAction` 里的 `liveItemModel`。
- `PlayWeaponTrialFX` 转到 `WeaponFX`，播的是 `ParticleSystem`。

`CharacterManager` 上的公开布尔值由多处写入。读 `PlayerLocomotionManager.HandleMove` 要先知道 `isInteracting` 来自刚才哪一次 `PlayTargetAnimation`，还是 `HandleEmptyState` 已经清掉。冲刺在 `InputManager.HandleRollInput` 写，滞空在 `HandleFall` 写，跳跃和翻滚还要等对应的 `StateMachineBehaviour`。

明显超长的脚本：

- `SettingsWindowManager` 约 470 行。画质、帧率上限、后处理和特效文案在静态方法里，切换再调用套用。
- `PlayerCameraManager` 约 510 行。锁定查询、三种机位和跟随写在同一个类里，改锁定范围会碰到跟随和碰撞。

伤害相关的参数个数明显超过约 5 个，改一次命中要在调用点把这些参数对齐：

| 符号 | 参数 |
| --- | --- |
| `CharacterStatsManager.TakeDamage` | 动画名、五段伤害、是否播受伤音 |
| `CharacterCombatManager.ResolveIncomingHit` | 攻击者、动画名、倍率、是否走格挡和韧性、韧性伤害、破防系数、五段伤害 |
| `CharacterAnimatorManager.PlayTargetAnimation` | 动画名、是否交互，以及旋转、镜像、根运动三个可选参数 |
| `MeleeAttackSegment.Play` | 角色、是否连击、四段动画名、两段 `AttackType` |

注释多数复述下一行在做什么。`HandleMove` 里坡度系数 `2/sin(θ)-1` 的注释说明了下坡加速，这是少见的在解释取舍。`Debug.LogError` 在缺槽、缺组件时于 `Start` 打出。快捷栏在 `QuickSlotsUI` 里遇到空图标直接返回，格子留着上一张图；槽位引用本身没接上时仍会报错。

## 可扩展性

> **加一种东西要改的位置是固定的，没有注册表。** 武器动作、法术和消耗品走 `ScriptableObject`；旗标和移动仍要进 Animator 状态或现有 `Handle*`。

| 想加的东西 | 现在要动的地方 |
| --- | --- |
| 一种新的轻击或重击 | 新的 `WeaponItemAction` 资产，在 `PerformAction` 里调用已有的 `PlayTargetAnimation`，武器槽填上这个资产。控制器里要有同名状态 |
| 第三下连击 | `AttackType`、`MeleeAttackSegment.Play`（现在只有第一段和第二段）、`DamageCollider.DealDamage`、`AttackStaminaCost`、动画字段 |
| 一个新法术学派 | `SpellType` 加成员，再写一个调用 `MagicSpellAction.PerformSpellAction` 的 Action 子类，做成资产填进武器槽。新效果还要新的 `SpellItem` 子类。复用 `ProjectileSpell` 时，玩家结算按 `spellType` 把 `baseDamage` 写入 `fd`、`md` 或 `ld` 之一，另外四段写 0。现有三系没有暗 |
| 一种消耗品 | 新的 `ConsumableItem` 子类，实现 `AttemptToConsumableItem` 和 `SucessfullyUsedConsumable`。结算从 `PlayerAnimatorManager.SuccessfullyCastConsumable` 进来，优先读 `consumableBeingUsed`，否则读 `currentConsumable` |
| 一个护甲部位 | `ArmorType`、`EquipmentSlotType`、物品子类、`ModelChanger` 子类、`PlayerArmorManager.EquipAllArmorModels` 的分支、`InventorySlotUI.EquipArmor`、装备窗槽位、`CharacterStatsManager` 上该部位五列吸收，以及 `TakeDamage` 里写死的 60/30/10 |
| 一种伤害碰撞体 | 继承 `DamageCollider` 并走触发器：`Start` 会把碰撞体设成 Trigger，命中进 `OnTriggerEnter`。走物理碰撞：像 `BombDamageCollider`、`SpellDamageCollider` 那样重写 `Start` 且不调用基类，在 `OnCollisionEnter` 里自己做队伍判断和 `TakeDamage` |
| 一种伤害属性 | `TakeDamage` 已有物理、火、魔、雷、暗五段。穿戴在 `EquipAllArmorModels` 写入，格挡在 `SetBlockingAbsorptionFromBlockingWeapon` 写入，近战碰撞体在 `LoadWeaponDamageCollider` 赋值。新段要在这三处再各接一次 |
| 一种新的移动 | Input Actions 订阅、`InputManager` 字段、一个 `Handle*`、通常再加一个 `StateMachineBehaviour` 写旗标。翻滚和跳跃还要放进 `PlayerManager.ResetCollider` 的排除条件，否则每帧会把胶囊写回默认尺寸 |
| 一种近战 AI 行为 | 在 Humanoid 那组 `State` 上加一个，从现有 `Tick` 返回它。待机、追击、战斗姿态、攻击之间用具体类型互相 `GetComponent`，字段类型要跟着改 |
| 一种相机模式 | 在 `PlayerCameraManager.CameraPose` 和 `CurrentCameraPose` 加一支，再给 `FollowPlayer`、`HandleCameraRotation`、`SetCameraPosOffset` 三个 `switch` 各加一案。偏移目标用 `AimingCameraOffsetTarget`、`LockedCameraOffsetTarget`、`DefaultCameraOffsetTarget`，缓动只在 `ApplyPivotOffset` |
| 一个画质档 | `DisplayQuality_Options`，以及 `DisplayQualityLabel`、`DisplayQualityLevel`、`NextDisplayQuality`、`PreviousDisplayQuality` |
| 一个帧率档 | `FrameRateLimit_Options`，以及 `FrameRateLimitLabel`、`FrameRateLimitValue`、`NextFrameRateLimit`、`PreviousFrameRateLimit` |

`BossCombatFXManager` 只被 `EnemyAnimatorManager.InstantiateBossParticleFX` 引用，后者没有别的调用方。成就窗口可以翻页，没有解锁逻辑。这些不是当前近战或当前 HUD 的扩展点。

## 修改代价

> **同一条行为常常分成输入、动画状态、碰撞体和结算四段，各写在不同的 Manager 里。** 改伤害、物品效果或 AI 状态时，下面这些文件会一起动。

**旗标没有单一所有者。** `PlayTargetAnimation` 按参数写下 `isInteracting`。全身层的 `HandleEmptyState` 在进入时清掉它；层名是 `Upper Body` 时直接返回，不清全身交互。`PlayerManager.ResetCollider` 在非翻滚、非跳跃时把胶囊中心和高度写回默认。`aimingRadiusApplied` 为真时不写半径（0.20）。`HandleAimingState` 在玩家进入瞄准状态时把半径写成 0.4，并在退出时写回进入前的值。

**一次轻击或重击。** `PlayerCombatManager` 按按键顺序选 `oh_*` 动作，`LightAttackAction` / `HeavyAttackAction` 交给 `MeleeAttackSegment.Play` 选动画并写 `attackType`（跟实际播放的第一段或第二段走）。控制器上的 `HandleAttackState` 写 `isAttacking` 并在退出时停粒子。片段事件调用 `OpenDamageCollider`，命中在 `DamageCollider.OnTriggerEnter`，吸收和格挡在 `ResolveIncomingHit`，扣血在 `TakeDamage`。左右手由调用前的 `UpdateWhichHandCharacterIsUsing` 决定。体力消耗在 `DrainStamina`：先选右手或左手武器，轻重击的数字在 `AttackStaminaCost`（1.14）。敌人双手走 `ItemBasedAttackAction` 的 `th_*`；玩家双手仍读 `oh_*`。

**下落。** `HandleFall` 的射线、`PlayTargetAnimation("Falling")`、没有单独出口的 Falling 动画，以及 `HandleEmptyState` 清 `isInteracting`，是同一件事的四段。`"Land"` 只在这一物理步刚从空中落到地上（`wasInAir`）时播放。`rayStartPointHeight` 只在 `Start` 采样一次。

**瞄准。** 相机、移动、冲刺和准星读 `PlayerManager.aimingMode`。`AimAction` 在按住且有箭时把它写成 true。`PlayerCombatManager.Handle_Hold_Q_Input` 在 Q 未按住的分支里每个 `Update` 把 `isBlocking` 和 `aimingMode` 都清掉，所以按住期间每个 `Update` 会再进一次 `PerformAction`。`HandleJumpState` 和 `HandleRollState` 进入时也清 `aimingMode`。非玩家的 `HandleAimingState` 写的是 `CharacterCombatManager.isAiming`。准星 `HUDWindowsManager.UpdateCrosshair` 只看 `aimingMode`。

**喝药或扔炸弹。** X 键在 `PlayerInventoryManager.HandleUseConsumableInput`，不看 `isInteracting`。数量在 `TrySpendConsumable` 里先减。效果在动画事件 `SuccessfullyCastConsumable`。炸弹和血瓶按下时都把 `this` 记进 `consumableBeingUsed`（血瓶是 0.21）。血瓶动画是否锁移动来自资产上的 `isInteracting`；炸弹把该参数写成 true。

**穿一件甲。** `InventorySlotUI.EquipArmor` 仍按头、躯干、下身分岔，旧件回背包、新件离包和放进装备格走 `ReplaceEquippedArmor`（1.12），再调用 `EquipAllArmorModels`。后者对三个部位各写物理、火、魔、雷、暗。属性面板上的五路吸收有写入。`TakeDamage` 仍用 `CombinedArmorRate` 按头 60%、躯干 30%、下身 10% 合成吸收。

**举盾。** `BlockAction` 把 `PlayTargetAnimation` 的交互参数设为 false，并按当前使用手抄武器上的五路格挡吸收和稳定率。正面朝向判断在 `ResolveIncomingHit`：指向攻击者的向量先归一化，点积大于 `0.3` 才算挡住（0.17）。`AttemptBlock` 在 `DeductStamina` 返回 false 时调用 `EmptyStamina`，精力写成 0 后再破防（0.16）。格挡命中仍会进 `TakeDamage`；受伤音只在这次结算后体力已经耗尽时播放。破防动画名是 `"Guard_Break"`。

**背刺。** `CriticalAttackAction.AttempBackStab` 立刻调用 `GetBackStabbed`。后者用攻击者右手武器的五段伤害乘 `criticalAttackDM`，经 `ResolveIncomingHit` 扣一次血。`ApplyPendingDamage` 仍会在 `pendingCriticalDamage` 非 0 时再扣物理伤害；全仓库没有给这个字段赋值，预制体上是 0。

**对话。** `Talk` 停掉大部分输入，不写 `isInteracting`。开始和进行中都进 `TalkUI.AdvanceDialogue`，里面仍按自动、逐字分到两段协程和两个手动方法。写一句时 `SetTalkerStatus` 改名字和 `talkWithSB`，`PlayTalkerEmptyPose` 另播空动画（1.13）。文案在 `DialogueTextData`，自动和跳过在 `GameSettingsData`。`talkWithSB` 为真且当前未交互时，`CharacterManager.RollForAnimation` 另挑一条对话动画。

**设置与暂停。** 改相机速度输入框时，`SaveCameraLeftAndRightSpeedSetting` 和 `SaveCameraUpAndDownSpeedSetting` 当场调用 `ApplyCameraSpeedSetting`。垂直同步在 `VSYNC_ApplyCurrentOption` 写入 `QualitySettings.vSyncCount`。画面品质的前进和后退只改 `displayQuality_Options`，再由 `DisplayQuality_ApplyCurrentOption` 写文案和 `SetQualityLevel`。帧率上限的前进和后退只改 `frameRateLimit_Options`，再由 `FrameRateLimit_ApplyCurrentOption` 写文案和 `targetFrameRate`。后处理切换只改 `postTreatmentQuality_Options`，再由 `PostTreatmentQuality_ApplyCurrentOption` 写文案。特效切换只改 `specialEffectQuality_Options`，再由 `SpecialEffectQuality_ApplyCurrentOption` 写文案。打开 ESC 窗口时 `EscWindowsManager.Open` 把 `timeScale` 设为 0，`Close` 设回 1。玩家已死亡且窗口还开着时，`PlayerUIManager.Update` 仍处理返回键。

**换武器。** 玩家切换双手时先改 `isTwoHandingWeapon`，再 `LoadWeaponsOnBothHands`。敌人在 `EnemyInventoryManager.Start` 里先按右手类型写双手标记，再进入基类 `Start` 装武器。`modelPrefab` 为空时，`LoadWeaponModel` 和 `LoadWeaponOnSlot` 在销毁旧模型和取碰撞体之前返回。左手在空手、法术、弓、盾上提前返回，并把 `leftWeaponFX` 写成空（0.26）。

**AI。** `EnemyManager.Update` 每帧调用当前状态的 `Tick`。Humanoid 待机到攻击这一圈的类型互相引用。General 那组状态是另一套 `Tick`，改近战 Humanoid 不会改到它。

## 改内容仍要改代码

> **武器系数、AI 半径、台词正文、攻击列表、站位 `Transform`、界面层级已经在资产或预制体上。** 改一个数、一句玩家能看见的字、一条声音，或重排一种已有行为，下面这些位置仍要改 C#。交接合同在 [`程序工作流解耦指导`](../程序工作流解耦指导/README.md)。枚举从 0 起、漏配落到第一项，见 [`接口设计.md`](接口设计.md)「数据契约」。

**方法里的数。** 头、躯干、下身的权重仍是上文「穿一件甲」的 60/30/10，方法是 `CharacterStatsManager.CombinedArmorRate`。`MemorySlotCount` 用一串 `if` 把集中力档位写成格数；没有调用方，见 [`正确性.md`](正确性.md)「物品与法术」的 FR-法术。Boss 在 `EnemyStatsManager.UpdateBossHealthBar` 里用 `currentHealth <= maxHealth * 0.5f` 调用 `ShiftToSecondPhase`。`OpenChest` 等 1 秒，再把物品放到本地坐标 `(0, 0.5, 0)`。`PlayTargetAnimation` 的 `CrossFade` 混合时间是 `0.2f`。人形 `CombatStanceStateHumanoid.WalkAroundTarget` 用 `3f` 和 `1.4f`，通用 `CombatStanceState.WalkAroundTarget` 用 `1.4f`。`EnemyAISettings` 上的半径见接口设计「数据契约」。

**玩家能看见的字。** `TalkUI.SetTalkerStatus` 在玩家说话时把名字写成 `"你"`。垂直同步文案是 `"启用"` 和 `"禁用"`（`SettingsWindowManager.VSYNC_ApplyCurrentOption`）。画质、帧率、后处理和特效的中文在静态方法里，见上文「可读性」。对白只读 `DialogueTextData.text`。脚本里没有给物品、设旗标这一类命令。

**声音。** `CharacterSoundFXManager` 持有 `AudioClip`。`takingDamageSounds` 长度为 0 时 `PlayRandomDamageSoundsFX` 返回；多于一条时 `PlayOneShot` 的音量是 `0.4f`。挥刀片段字段是 `WeaponItem.weaponWhooshesSound`（见接口设计「数据契约」）。`PlayRandomWeaponWhoosh` 在数组长度为 0 时返回，否则 `PlayOneShot`。篝火片段是 `CampFireInteractable.campFireActivationSFX`，由这段脚本 `PlayOneShot`。

**选招。** `CombatStanceState.GetNewAttack` 与 `CombatStanceStateHumanoid.GetNewAttack` 把距离和角度都满足的 `attackScore` 加总，再按这个和随机。`attackScore` 字段见接口设计「数据契约」。两套 `Tick` 见上文「AI」。第二阶段的血量线在 `EnemyStatsManager`。

**缺了仍继续。** 缺槽、缺组件时 `Start` 打 `Debug.LogError` 之后继续，见上文「可读性」。`OpenChest` 在 `animator` 为空时打的是空字符串。`TalkUI` 在 `talkContent` 为空时返回。右手武器为空时 `GetBackStabbed` 与 `GetRiposte` 返回，见 [`接口设计.md`](接口设计.md)「伤害与碰撞消息」。`PlayTargetAnimation` 在缺少状态时打出物体名和状态名，见 [`可测试性.md`](可测试性.md)「代理能读到的反馈」。

## 性能

> **没有测过帧时间。** 下面只保留每帧都会发生的堆分配，或每次更新里数量随场景物体增长的物理查询。单次、无分配的射线不单列。

### 交互检测

`PlayerManager.Update` 在玩家未死亡时调用 `CheckForInteractableObject`。`OverlapSphereNonAlloc` 写入角色上同一块长度为 1 的数组（0.25），不再每次 `new`。范围内有交互物时再 `GetComponent<Interactable>`，并刷新交互提示。

### 锁定开启后每帧做一次无层遮罩的球形查询

`PlayerCameraManager.Update` 调用 `UpdateLockOnTargets`。`lockOnMode` 为假时立刻返回。为真时，每个显示帧：

- `OverlapSphereNonAlloc`（半径 `maxLockOnDist`，默认 30，层遮罩 `~0`，对应原来不传层）。数组留在组件上，装满才加倍（0.29）
- 每个碰撞体一次 `GetComponent<CharacterManager>`
- 每个尚在扇形内的候选人一次 `Linecast`
- `lockableTargets` 先 `Clear` 再 `Add`
- 已有当前目标时，`HandleChangeLockOnTarget` 可能再打一条 `Linecast`

查询量跟着半径 30 内的碰撞体数量走。

### 近战待机每帧探测玩家

`EnemyManager.Update` 在未死亡时调用当前状态的 `Tick`。当前状态是 `IdleStateHumanoid` 时，AI 开着、未在交互，则每次 `Tick` 对玩家层做一次 `OverlapSphereNonAlloc`（数组留在状态上，装满才加倍，0.29），命中后再可能 `GetComponent<CharacterManager>` 和 `Linecast`。这是每个显示帧一次，没有单独的 AI 节拍。`IdleState.Tick` 同样复用数组。锁定和这两处待机都调用 `OverlapQuery.CollectOverlaps`（1.11）。`AmbushState.Tick` 也调用 `OverlapQuery.CollectOverlaps`，数组从 16 起（0.30）。

### 查过、不单列的热路径

这些路径每帧或每个物理步都会跑，次数固定，没有在代码里看到堆分配或随场景物体数增长的查询：

- `PlayerLocomotionManager.FixedUpdate` 里的移动、转向和 `HandleFall`：人在地上也打向前、向下各一次 `Raycast`，并 `Debug.DrawRay`。向前那次不传层。`"Land"` 只在刚着陆的那一步播放。
- 非瞄准时 `HandleCameraCollisions` 每个 `LateUpdate` 一次环境层 `SphereCast`（半径 0.2）。
- `FindAnyObjectByType` 用在开局（玩家找相机、相机找玩家、敌人血条找玩家、敌人属性找 `WorldManager`）和敌人死亡时再找一次玩家。武器槽的 `GetComponentsInChildren` 在 `Awake`，换武器时的 `GetComponentInChildren<DamageCollider>` 在装载。输入循环没有每帧 `GetComponent`。工程内没有 `LINQ`，也没有 `SendMessage`。
- 动画参数：`UpdateAnimatorValues` 两次阻尼 `SetFloat`，`CharacterManager.UpdateBoolsValue` 每帧三次 `SetBool`，`UpdateHandIKWeight` 每帧写双手 IK 权重。代码里没有 `SetLayerWeight`。
- 拿着箭且未瞄准时，`PlayerEffectsManager.Update` 对 Animator 第 4 层调用两次 `GetCurrentAnimatorStateInfo`，并用字符串比较 `"Get Arrow"` 和 `"Aiming - Start"`。
- `PlayerStatsManager.RegenerateStamina` 在不交互、不冲刺、已过 1 秒且未满时，每个显示帧改体力并写一次体力条。
- 命中时才发生的分配：血溅、法术、炸弹、弹药嵌入的 `Instantiate`。炸弹溅射的 `OverlapSphere` 在碰撞回调里。小怪血条脚本挂在自身 `Slider` 上，藏起来之后该物体不活动。FPS 文本每 300 帧拼一次字符串。
