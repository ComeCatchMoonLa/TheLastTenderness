# 接口设计

> **本文按 `Assets/Scripts/` 当前源码记录模块之间实际怎么交谈。** 模块如何分层见 [`构架设计.md`](构架设计.md)，改动代价见 [`可维护性.md`](可维护性.md)，帧内开销见 [`性能.md`](性能.md)，现有行为怎么验证见 [`可测试性.md`](可测试性.md)。

类型之间没有独立的接口层。手写的 C# `interface` 有两个：`PopUpInterface`（`Assets/Scripts/UI/Player UI/Pop Up Windows/PopUpInterface.cs`，只声明 `PopUp()`，三个实现是 `ViewInfoUI`、`TalkUI`、`CampFireLitPopUpUI`）和选招用的 `IAttackWindows`（`AttackScore.cs`）。生成的 `InputActions.cs` 另带 5 个输入回调接口。角色之间靠 `CharacterManager` 上的公开字段、动画状态名字符串、`DamageSegments` 五段伤害，以及武器资产上的 `WeaponItemAction` 槽传递。

玩家身上的 `pCombat` 与 `CharacterManager.cCombat` 指向同一个 `PlayerCombatManager`。`CharacterManager.Awake` 用 `GetComponent<CharacterCombatManager>()` 取到它。敌人侧的 `eCombat` 同理，类型是空的子类 `EnemyCombatManager`。

## 跨模块入口

### 玩家控制

`InputManager`（`Assets/Scripts/Character/Player/InputManager.cs`）把键和轴收成公开字段，自己不播动画。移动轴是 `horizontal`、`vertical`、`moveAmount`，镜头轴是 `mouseX`、`mouseY`。点按留下 `space_Input`、`interacte_Tap_Input`、`f_Input`、`y_Input`、`x_Input`、`tap_e_Input`、`hold_e_Input`、`tap_q_Input`、`hold_q_Input`、`tap_r_Input`、`tap_z_Input` 以及方向键和 UI 操作旗标。翻滚和后撤的门闩是 `rollFlag`、`backStepFlag`。冲刺旗标写在角色上：`HandleRollInput` 写 `PlayerManager.isSprinting`。格挡中、瞄准中、体力低于 `PlayerLocomotionManager.sprintNeedMinStamina`、松开 Shift，都会把 `isSprinting` 写成 false。`BlockAction` 不写这个字段。

`PlayerLocomotionManager`（`Assets/Scripts/Character/Player/PlayerLocomotionManager.cs`）在 `FixedUpdate` 里依次处理移动、转向、坠落、跳跃、翻滚、后撤。`isInteracting` 为 true，或 `rollFlag` 仍为 true 时，`HandleMove` 停写速度。`HandleRotate` 先看 `aimingMode`，再看 `canRotate`；锁定且未冲刺、未翻滚时朝 `PlayerCameraManager.curLockOnTarget` 转。`HandleFall` 在 `isJumping` 为 true 时整段返回。落地射线的层是声明处常量 `groundCheckLayer = LayerMask.environment | LayerMask.npc | LayerMask.player`（`CatchMoon.LayerMask`，`Assets/Scripts/Layer.cs`）。上一物理步的 `isInAir` 决定要不要加下落力；射线命中后写成 false，未命中写成 true，并在未交互时播 `"Falling"`。从空中落到「落差够大」播 `"Land"`，落差不够播 `"NonCombat Whole Body Empty"`。翻滚、后撤、跳跃在 `DeductStamina` 成功后分别播 `"Rolling"`、`"Backstep"`、`"Jump"`。瞄准时跳跃直接返回。

移动旗标的写入点：

| 字段 | 谁写成 true | 谁写成 false |
| --- | --- | --- |
| `isRolling` | `HandleRollState.OnStateEnter` | 同一状态 `OnStateExit` |
| `isJumping` | `HandleJumpState.OnStateEnter` | 同一状态 `OnStateExit` |
| `isInAir` | `PlayerLocomotionManager.HandleFall` 射线未命中 | 同一方法射线命中 |
| `isSprinting` | `InputManager.HandleRollInput` | 同一方法里格挡、瞄准、体力不足、松开 Shift |

`HandleRollState`、`HandleJumpState` 在 `characterType == CharacterType.player` 时把对象转成 `PlayerManager`，调 `ClearAimingMode()`，并改胶囊体的 `center` / `height`。尺寸读 `PlayerLocomotionManager` 上的 `rollingCollider*`、`jumpingCollider*`。`PlayerManager.ResetCollider` 在非翻滚、非跳跃时把中心和高度恢复成 `defaultCollider*`；`aimingRadiusApplied` 为真时不写半径。

交互检测在 `PlayerManager.CheckForInteractableObject`。`Physics.OverlapSphereNonAlloc` 半径是 `interactRadius`（默认 2），层是 `LayerMask.interactable | LayerMask.npc`，再要求 Tag `"Interactable"`。命中物必须带 `Interactable`，提示文字来自 `interactTipText`，确认键走 `Interact(PlayerManager)`（`Assets/Scripts/Items/Interactions/Interactable.cs`）。

### 战斗与武器动作

`PlayerCombatManager.HandleCombatInput`（`Assets/Scripts/Character/Player/PlayerCombatManager.cs`）每个 `Update` 按固定顺序调用六段按键，顺序决定谁能打断谁：按住 E、按住 Q、点按 E、点按 R、点按 Q、点按 Z。点按 E 在左手是弓时走左手的 `oh_tap_e_action`，否则走右手的 `oh_tap_e_action`。按住 E 和点按 R 只读右手的 `oh_hold_e_action`、`oh_tap_r_action`。点按 Q / Z 在双手时读右手的 `oh_tap_q_action` / `oh_tap_z_action`，单手时读左手同名槽。按住 Q 在「双手且左手不是弓」时读右手 `oh_hold_q_action`，否则读左手 `oh_hold_q_action`。同一次按住只经 `ShouldEnterHoldAction` 进入一次。松开 Q（`hold_q_Input` 为 false）时把 `isBlocking` 写成 false，并调用 `ResetBlockingAbsorption()` 和 `ClearAimingMode()`。

调用 `PerformAction` 之前，玩家先 `UpdateWhichHandCharacterIsUsing(bool usingRightHand)`，把 `isUsingRightHand` / `isUsingLeftHand` 收成互斥，再把该武器记到 `CharacterInventoryManager.currentItemBeingUsed`。

`WeaponItemAction.PerformAction(CharacterManager character)`（`Assets/Scripts/Items/0 Item Actions/WeaponItemAction.cs`）是武器动作的统一入口。玩家实际会走到的子类：

| 类 | 对外做的事 |
| --- | --- |
| `LightAttackAction` / `HeavyAttackAction` | 体力大于 0 才继续；能连击时先把 `canDoCombo` 写成 false，再交给 `MeleeAttackSegment.Play` |
| `BlockAction` | 已在交互、已在格挡、或体力不大于 0 则返回；否则 `isBlocking = true`，`SetBlockingAbsorptionFromBlockingWeapon()`，播 `"Block - Start"`（`isInteracting` 传 false，`canRotate` 传 true） |
| `ParryAction` | 武器带 `stanceArt` 时是架势武器：只切 `stanceHolding` 并返回，不播弹反（派生走轻重击）；否则非双手播 `weapon_art`（默认 `"Parry"`），同时记弹反开窗帧 `parryOpenedFrame` |
| `AimAction` | 只处理玩家；必须双手且 `currentAmmo` 非空才把 `aimingMode` 写成 true；交互中会再写成 false |
| `ShootArrowAction` | 玩家须已瞄准且体力大于 0，并 `TrySpendAmmo`；然后 `animator.Play("Shoot Arrow")`。伤害按 `PlayerManager.aimHeld` 经 `BowShot.FullDraw/Damage` 分快射与拉满两档（拉满时间与两档伤害在 `AmmoItem`）。NPC 分支同样播这个状态名 |
| `CriticalAttackAction` | 从 `criticalAttackRayCastStartPoint` 沿前方射线，距离 `criticalAttackRange`（默认 0.9），层 `LayerMask.player \| LayerMask.npc`；角度与一次性由静态 `BackstabLock` 判定，制裁还要过帧窗 `ParryWindow` |
| `SorcerySpellAction` / `PyromancySpellAction` / `MiracleSpellAction` | 交给 `MagicSpellAction.PerformSpellAction`，学派分别是 `SpellType.sorcery`、`pyromancy`、`miracle` |

`MeleeAttackSegment.Play`（`Assets/Scripts/Items/0 Item Actions/MeleeAttackSegment.cs`）签名是 `(CharacterManager, bool combo, MeleeAnimations animations, AttackType firstType, AttackType secondType)`；`MeleeAnimations` 是结构体，打包单手一/二段与双手一/二段四个动画名。两手都没在用时，非连击只记下 `attackType` 就返回。选哪一型由静态 `PairedWeapons.Select(...)` 决定：成对武器且持成对装时走成对/双手段，普通双手走双手段，其余走单手段（左手镜像）。连击且 `lastAttack` 等于第一段时播第二段。最后经 `AnimationOptions{Mirror=...}` 调 `PlayTargetAnimation` 并写入 `attackType`。动画名来自 `CharacterAnimatorManager` 的 `ohLightAttack1` 等字段，默认 `"OH_Light_Attack_01"`、`"TH_Heavy_Attack_02"` 这一组。

`CriticalAttackAction` 用点积区分反击和背刺（角度判定与「这次已用过」在静态 `BackstabLock`）。目标 `canBeRiposted`（弹反成功由 `ParryWindow` 置真、或破防由 `GuardBreak.OpensRiposte` 置真）且点积在 `[0.8, 1]` 时，攻击者播 `"Riposte"` 并调 `GetRiposte`。点积在 `[-1, -0.8]` 且背刺锁成立时播 `"Back Stab"` 并调 `GetBackStabbed`。距离是双方胶囊体半径之和。攻击者同时把 `isPerformingRiposted` 或 `isPerformingBackStabbed` 和 `isInvulnerable` 写成 true。

`oh_hold_r_action`、`oh_hold_z_action`，以及全部 `th_hold_*`，在 `WeaponItem` 上有槽，当前脚本没有调用方。`th_tap_*` 只由人形 AI 的 `ItemBasedAttackAction` 调用。

### 武器槽

`CharacterWeaponSlotManager`（`Assets/Scripts/Character/CharacterWeaponSlotManager.cs`）在 `Awake` 里用子物体上的 `WeaponHolderSlot.slotType` 填 `leftHandSlot`、`rightHandSlot`、`backSlot`。`CharacterInventoryManager.Start` 把当前左右武器交给 `LoadWeaponsOnBothHands()`。

`LoadWeaponOnSlot(WeaponItem weaponItem, bool isLeft)` 要求 `modelPrefab` 非空。模型挂到 `WeaponHolderSlot.overrideParentWhileHolding`，并 `ResetLocal()`。左手空手播 `"Left Arm Empty"`；弓再播 `offHandIdleAnimation`（`WeaponItem` 默认 `"Left_Arm_Idle_01"`），并把 `runtimeAnimatorController` 换成 `weaponController`。右手在左手已是弓时改挂背部并播 `"Right Arm Empty"`，否则换右手控制器。双手时左手模型挪到背部，左手槽记成 `unarmed`。

近战伤害体只在模型加载后赋值。空手、触媒（`faithCaster` / `pyromancyCaster` / `spellCaster`）、弓、单手盾不给左手装 `DamageCollider`；右手只跳过空手和触媒。装上之后写入：

- `leftHandDC.character` / `rightHandDC.character` = 父级 `CharacterManager`
- `teamID` = `character.cStats.teamID`
- `poiseBreak`、`pd`、`fd`、`md`、`ld`、`dd` 来自这把 `WeaponItem`

`PlayerWeaponSlotManager.LoadWeaponOnSlot` 在基类成功后多一步 `QuickSlotsUI.UpdateCurrentWeaponIcon`。`EnemyWeaponSlotManager` 没有自己的方法。双手武器（`WeaponType.melee_TH`）再从模型上取 `LeftHandIKTarget`、`RightHandIKTarget`，交给 `SetHandIKForWeapon`。

切双手的入口在 `PlayerInventoryManager.HandleTwoHandInput`（Y 键）。右手是 `melee_TH` 或 `melee_THL`，或左手是 `bow` 时，翻转 `isTwoHandingWeapon` 并重新 `LoadWeaponsOnBothHands`。

### 受击、生命与界面血条

`CharacterStatsManager.TakeDamage`（`Assets/Scripts/Character/CharacterStatsManager.cs`）：

```csharp
public virtual bool TakeDamage(
    string damageAnimation,
    DamageSegments damage,
    bool playHurtSound = true)

// DamageSegments 是结构体：Physical、Fire、Magic、Lightning、Dark 五段 float
```

`isDead` 或 `isInvulnerable` 时返回 false，不扣血。五段各自乘护甲剩余率后相加：头 0.6、躯干 0.3、髋 0.1，单部位吸收率是 `headArmorPDA` 这一组。冻伤爆发期间另乘 `Frostbite.Taken` 受伤系数，火伤会解除冻伤。`damageAnimation != null` 时 `PlayTargetAnimation(damageAnimation, true)`。`playHurtSound` 为 true 时播 `PlayRandomDamageSoundsFX`。

`PlayerStatsManager` 覆写后刷新 `hud.healthBar`，`currentHP <= 0` 时 `Death(player)`，默认死亡动画 `"Death"`。`AddHP` / `DeductHP` / `AddStamina` / `DeductStamina` / `AddMP` / `DeductMP` 成功时分别推血、体、蓝条。`EmptyStamina` 把 `currentStamina` 写成 0，玩家覆写同时推体力条。`DeductAttackStamina` 把体力减到不低于 -60，玩家覆写同时推体力条。`AddSouls(int souls)` 加 `soulCount`，并写 `hud.soulCountUI.SetSoulCountText`。体力回复在 `RegenerateStamina`：交互或冲刺把计时清零；空闲超过 1 秒后，格挡用 `staminaRegenerationAmountWhilstBlocking`（默认 20），否则用 `staminaRegenerationAmount`（默认 300），再乘 `deltaTime`。

`EnemyStatsManager.TakeDamage` 同样先走基类。非 Boss 更新子物体上的 `UIEnemyHealthBar`（`SetCurrentHealth`、`ShowBar`）；Boss 走 `UpdateBossHealthBar`，进而 `world.wUI.bossHealthBar.SetBossCurrentHealth`。转阶段门槛改读资产 `phaseThreshold`，经 `BossPhase.ShouldShift(current, max, threshold, already)` 判断；触发时播 `"Phase Shift"`，`isPhaseShifting` 置真，且仅在 `phaseBlocksHits` 为真时写 `isInvulnerable`，再把 `BossCombatStanceState.hasPhaseShifted` 写成 true。死亡时用 `Awake` 里拿到的玩家，先调 `world.wEvent.BossHasBeenDefeated()`（Boss），再 `AwardSoulsOnDeath`；若正在锁定则 `Unlock()` 并 `UpdateLockOnTargets()`。尸体去向分三种（`MeleeRest`）：非 Boss 近战立即 `SetActive(false)`（休息时复活回位回满），Boss 延时 `destoryWaitTime`（默认 3 秒）后 `SetActive(false)`，非近战远程才 `Destroy(gameObject, destoryWaitTime)`。`BreakGuard()` 播 `"Guard_Break"`。

`PlayerUIManager`（`Assets/Scripts/UI/Player UI/PlayerUIManager.cs`）对外挂四个窗口：`hud`、`escWin`、`tapWin`、`popUps`，再用 `openedWin`（`EscWinOpenedWinType`）表示 ESC 层级。血条方法在 `HealthBar.SetMaxHP` / `SetCurrentHP`，体力是 `StaminaBar.SetCurrentStamina`，蓝是 `focusPointsBar`（类型 `FocusPointsBar`）的 `SetCurrentMP`。Boss 条由 `WorldUIManager.ActivateBossBar(EnemyStatsManager)` 打开。

### 物品：法术、消耗品、护甲

三条使用路径的基类互相不继承。

| 路径 | 基类与方法 | 谁调用 | 完成时 |
| --- | --- | --- | --- |
| 武器动作 | `WeaponItemAction.PerformAction(CharacterManager)` | `PlayerCombatManager` 或 `ItemBasedAttackAction` | 动作自己播动画；命中在伤害体 |
| 法术 | `SpellItem.AttemptToCastSpell(CharacterManager)` / `SuccessfullyCastSpell(CharacterManager)` | 武器槽上的学派 Action | 动画事件 `SuccessfullyCastSpell` |
| 消耗品 | `ConsumableItem.AttemptToConsumableItem(PlayerManager)` / `SuccessfullyUsedConsumable(PlayerManager)` | X 键，`PlayerInventoryManager` | 动画事件 `SuccessfullyCastConsumable` |

法术门禁在 `MagicSpellAction.PerformSpellAction`，依次过四关：①该法术已在篝火记忆栏（`SpellMemory`，没记忆放不出）；②`currentSpell.spellType` 与手上催化器匹配（`CatalystMatch`）；③属性关 `AttributesAllowCast` 看 `requiredIntelligence`、`requiredFaith`，不够播 `"Shrug"` 返回；④`currentMP >= focusPointCost`，蓝不够也播 `"Shrug"`。`HealingSpell.AttemptToCastSpell` 在 `DeductMP` 返回 false 时返回，不播 `spellAnimation`（0.31）；`ProjectileSpell` 在 `DeductMP` 返回 false 时停住。投射物真正生成在 `SuccessfullyCastSpell`：玩家分支给 `SpellDamageCollider` 写 `teamID` 与五段（先 0，再按 `spellType` 把 `baseDamage` 写入 `pyromancy→fd`、`sorcery→md`、`miracle→ld`）。碰撞时五段全传；目标正面举盾时改走 `ResolveIncomingHit` 的法术格挡分支（`spellFromFront: true`，吸收与扣体见 `SpellOnShield`）。NPC 的 `SuccessfullyCastSpellWithAI` 方法体整段被注释掉。

消耗品数量由 `PlayerInventoryManager` 的字典记账，初值读资产 `ConsumableItem.currentItemAmount`（夹取到 0 与 `maxItemAmount` 之间）；箭走 `TrySpendAmmo` / `AmmoRemaining`，初值读 `AmmoItem.cnt`，`maxCnt` 只作上限。`TrySpendConsumable`/`TrySpendAmmo` 成功则减 1 并返回 true。`FlaskItem` 与 `BombItem` 都先看 `isUsingConsumable`，失败播 `"Shrug"`。成功时卸下右手模型，把 `itemModel` 挂到 `rightHandSlot.overrideParentWhileHolding`，引用放进 `PlayerEffectsManager.instantiatedFXModel`，并把自身记到 `consumableBeingUsed`。血瓶另外记下 `currentParticleFX = recoveryFX`。炸弹在动画事件里再生成 `liveBombModel`，给 `BombDamageCollider` 写 `teamID`、`explosionDamage = baseDamage`、`explosionSplashDamage = explosiveDamage`。

护甲没有动作类。`PlayerArmorManager.EquipAllArmorModels` 按 `HeadArmorItem` / `TorsoArmorItem` / `HipsArmorItem` 换模（`ModelChanger.EquipModelByName(transformName)`），并把五段吸收率写进 `headArmorPDA`、`torsoArmorPDA`、`hipsArmorPDA` 这一组。空槽写 0；躯干和髋的空槽改穿 `nakedTorsoModelName`、`nakedHipsModelName`。

### 敌人与 NPC 状态机

`State.Tick(EnemyManager enemy)` 返回下一个 `State`，返回 `null` 或 `this` 表示留在当前状态。`EnemyManager.HandleStateMachine`（`Assets/Scripts/Character/NPC/EnemyManager.cs`）每个 `Update` 调用它。`enableAI`、`currentTarget`、`distFromTarget`、`aiSettings` 是状态之间共用的公开数据。

两套状态图都挂在敌人同一个物体上，互相 `GetComponent` 具体子类：

- 人形：`IdleStateHumanoid`、`PursueTargetStateHumanoid`、`RotateTowardsTargetStateHumanoid`、`CombatStanceStateHumanoid`、`AttackStateHumanoid`。攻击资产是 `ItemBasedAttackAction`，`PerformAttackAction(EnemyManager)` 按 `isLightAttack`、`isRightHandAction`、`NPCCombatStyle` 去调武器槽里的 `oh_tap_*` 或 `th_tap_*`。
- 通用：`IdleState`、`PursueTargetState`、`RotateTowardsTargetState`、`CombatStanceState`、`AttackState`，另有 `AmbushState`。攻击资产是 `EnemyAttackAction`，直接 `PlayTargetAnimation(actionAnimation, true)`，手别由 `isLeftHandedAction` 决定。
- 人形、General 和 Boss 的选招下标都由 `AttackScore.PickIndex` 写出。Boss 站桩是 `BossCombatStanceState : CombatStanceState`。`hasPhaseShifted` 为 true 后，选招改读 `sencondPhaseAttacks`。

人形战斗姿态在 `willPerformBlock` 为 false 且 `isBlocking` 仍为 true 时，把格挡清掉并播 `"Block - End"`（`isInteracting` 传 false）。察觉用 `EnemyAISettings.detectionRadius`，追击和脱离用 `aggroRadius`。

剧情对话走 `Talk : Interactable`，角色侧的开关是 `CharacterManager.talkWithSB`。为 true 且未交互时，`RollForAnimation` 从序列化列表 `talkAnimations` 里抽一条，交给 `PlayTargetAnimation`。`TalkUI.SetTalkerStatus` 在轮到谁说话时改双方的 `talkWithSB` 和名字。`PlayTalkerEmptyPose` 再对另一方 `Play("NonCombat Whole Body Empty")`（1.13）。结束时 `HandleTalkEnd` 仍对双方各 `Play` 一次。

### UI、设置与世界

玩法读设置的路径是 `player.ui.escWin.GetSettingWin().gameSettingsData`。`GetSettingWin()` 返回 `SettingsWindowManager`，上面的公开字段 `gameSettingsData` 类型是 `GameSettingsData`。

| 字段 | 谁读 |
| --- | --- |
| `auto`、`wordForWord`、`skip` | `TalkUI.AdvanceDialogue` 按自动和逐字挑选播放；`skip` 仍由 `PlayerManager.Update` 调 `Handle_SkipTalk_Input` |
| `enableFps` | `HUDWindowsManager.UpdateFPS` |
| `autoChangeLockOnTarget` | `LockOnQuery` 的锁定扫描与切换 |
| `cameraLeftAndRightSpeed`、`cameraUpAndDownSpeed` | 设置窗启动时套到镜头速度 |
| `frameRateLimit_Options`、`displayQuality_Options` | 启动和切换时写到引擎 |
| `vsync_Options`、后处理、特效品质 | 设置窗改选项标签和对应引擎项 |

`PlayerCameraManager` 由玩家 `FindAnyObjectByType` 拿到。锁定相关的公开字段是 `lockOnFlag`、`lockOnMode`、`curLockOnTarget`、`changeLockOnTargetMode`（默认 `ChangeLockOnTargetMode.nearest`）。扫描和换目标由同物体上的 `LockOnQuery` 写，球查询层是 `LayerMask.npc`。`HandleChangeLockOnTarget` 只在 `LockOnQuery` 内部调用。外部仍调 `PlayerCameraManager.UpdateLockOnTargets`（转给 `LockOnQuery`）和 `Unlock`。敌人死亡和换成弓时会 `Unlock`。

`WorldManager` 公开字段是 `player`、`wEvent`、`wUI`。Boss 开场碰撞体通过 `WorldEventManager` 找到它。`EventColliderBeginBossFight` 挂在世界物体下，用父级拿到 `WorldManager`。

2.x 新增的世界交互都走「`Interactable` 子类 + 同名纯函数静态类」：规则在静态类里（可直接 Edit 测试），MonoBehaviour 只搬场。

| 静态契约 | 规则 | 场景侧调用 |
| --- | --- | --- |

## 数据契约

外部往资产和预制体上填的字段，调用方按下面这些名字读取。主要枚举在 `Assets/Scripts/EnumsTypes.cs`（21 个，全部从 0 起），另有少量枚举散在 `EnumsOptions.cs`、`BagPages.cs`、`ScaleInfusion.cs`、`WeaponStance.cs`、`CatalystKind` 等文件里，也都从 0 起。漏配会落到第一个成员。

### 物品与武器

`Item`：`itemType`、`itemIcon`、`itemName`、`transformName`（换模用这个字符串）。`EquipmentItem` 再加 `equipmentType`。

`WeaponItem`（`Assets/Scripts/Items/Equipment/Weapons/WeaponItem.cs`）里真正进入玩法的字段：

- 模型与控制器：`modelPrefab`、`weaponController`、`offHandIdleAnimation`（默认 `"Left_Arm_Idle_01"`）、`weaponType`
- 伤害：`pd` `fd` `md` `ld` `dd`，以及 `laFirstPhaseDM`（1）、`laSecondPhaseDM`（1.2）、`haFirstPhaseDM`（1.6）、`haSecondPhasDM`（1.8）、`criticalAttackDM`（2.4）
- 韧性：`poiseBreak`（默认 25）、`offensivePoiseBonus`（动画事件 `GrantWeaponAttackingPoiseBonus` 加到 `totalPoiseDefence`）
- 格挡吸收：`physicalDA` `fireDA` `magicDA` `lightningDA` `darkDA`，以及 `blockingStabilityRating`。`SetBlockingAbsorptionFromBlockingWeapon` 把它们抄到角色的 `blockingPDA` 等字段
- 体力：`baseStaminaCost`、`laStaminaCostM`、`haStaminaCostM`。`DrainStamina` 按当前手和 `attackType` 把「基础值 × 轻重系数」交给 `DeductAttackStamina`，最低 -60
- 按键槽：`oh_tap_e_action` 到 `oh_tap_z_action`，以及 AI 会读的 `th_tap_e_action`、`th_tap_r_action`、`th_tap_q_action`、`th_tap_z_action`
- 挥刀音：`weaponWhooshesSound`

`WeaponItem.guardBreakM`、`DamageCollider.offensivePoiseBonus`、`CharacterStatsManager.offensivePoiseBonus` 在脚本里没有读取方。格挡扣体力用的是伤害体上的 `guardBreakModifider`（默认 1），装武器时没有把 `guardBreakM` 赋给它。武器 `stability`（默认 0.67）在格挡扣体力时乘进结算（`SpellOnShield.StaminaCost`）。

`ArmorItem`：`armorType`，以及五段 `physicalDA` 到 `darkDA`。`AmmoItem`：`forwardVeclocity`、`upwardVeclocity`、`mass`、`useGravity`、`maxCnt`、`physicalDamage`、`loadedItemModel`、`liveItemModel`、`penetratedModel`。`SpellItem`：`spellWarmUpFX`、`spellCastFX`、`spellAnimation`、`focusPointCost`、`spellType`、`requiredIntelligence`、`requiredFaith`。`ProjectileSpell` 另要 `baseDamage`、`projectileForwardVelocity`、`projectileUpwardVelocity`、`projectileMass`、`isEffectByGravity`。`HealingSpell` 要 `healAmount`。`ConsumableItem`：`maxItemAmount`、`itemModel`、`consumeAnimation`、`isInteracting`（血瓶把它传给 `PlayTargetAnimation` 的第二个参数）。`FlaskItem` 要 `healthRecoverAmount`、`focusPointsRecoverAmount`、`recoveryFX`。`BombItem` 要 `liveBombModel`、`baseDamage`、`explosiveDamage`、`forwardVelocity`、`upwardVelocity`。

### 敌人配置

`EnemyAISettings`：`isBoss`、`rotationSpeed`、`maxViewAngel`、`minViewAngel`、`allowAIToPerformCombos`、`comboLikeHood`、`aggroRadius`、`detectionRadius`、`combatStyle`，以及格挡 / 闪避 / 弹反三组 `allow*` 与 `*LikelyHood`。

`EnemyAttackAction`：`actionAnimation`、`isLeftHandedAction`（基类 `EnemyActions`），加上 `canCombo`、`comboAction`、`attackScore`、`recoveryTime`、`maxAttackAngle`、`minAttackAngle`、`maxDistNeededToAttack`、`minDistNeededToAttack`。`ItemBasedAttackAction` 用 `isLightAttack`、`isRightHandAction` 和同一组距离、角度、分数、恢复时间。

`EnemyManager.aiSettings` 为空时 `Start` 打错误日志。Boss 必须在子物体上挂 `BossCombatStanceState`，普通敌人必须挂 `UIEnemyHealthBar`。

### 角色预制体上要接好的引用

`CharacterManager.Awake` 要求同一物体上有 `Animator`、`Rigidbody`、`CapsuleCollider`，以及动画、战斗、特效、库存、属性、武器槽、音效七个 Manager。玩家再要 `InputManager`、`PlayerUIManager`（子物体）、场景里的 `PlayerCameraManager`，以及瞄准机位 `cameraTransformWhileAiming`。`noArmor` 为 true 时允许没有 `PlayerArmorManager`。库存的 `leftWeapon`、`rightWeapon` 和 `unarmed` 要在 `Start` 前填好，否则装武器失败。

层号以 `Layer` 为准：`interactable` 7，`environment` 8，`npc` 9，`characterCollisionBlocker` 10，`player` 11。`CatchMoon.LayerMask` 与 `UnityEngine.LayerMask` 同名，所以落地检测的字段类型写成 `UnityEngine.LayerMask`。

有定义、分支里没有对应成员用法的枚举：`WeaponType` 的 `melee_OH_LH`、`melee_OH_RH`（`melee_OH_DualWield` 现由 `PairedWeapons.IsPaired` 读取）；`AttackType.critical`（反击和背刺走 `CriticalAttackAction`，不写这个枚举）；`ChangeLockOnTargetMode.minHP`（镜头只比较 `nearest`）；`NPCType` 与 `StateMachineBehaviourType` 没有调用方。`AmmoType` 只有资产字段，使用逻辑不读它。`FlaskType` 由库存的 `TryGetFlaskSip` 区分血瓶和灰瓶。

### 播动画入口

`CharacterAnimatorManager.PlayTargetAnimation`（`Assets/Scripts/Character/CharacterAnimatorManager.cs`）：

```csharp
public void PlayTargetAnimation(
    string targetAnim,
    bool isInteracting,
    AnimationOptions options = default)

// AnimationOptions 是结构体：CanRotate、Mirror、RootMotion 三个 bool
```

任一 Animator 层上找不到该状态（短名或 `层名.状态名`）就打错误并返回。找到之后：`applyRootMotion = isInteracting || options.RootMotion`，写 `isInteracting`、`canRotate`、`isRotatingWithRootMotion`、`isMirrored`，再 `CrossFade(targetAnim, 0.2f)`。`isInteracting` 为 true 时移动让路，坠落也不会重播 `"Falling"`。

脚本里写死的状态名包括：`"Jump"`、`"Rolling"`、`"Backstep"`、`"Falling"`、`"Land"`、`"NonCombat Whole Body Empty"`、`"Shrug"`、`"Block - Start"`、`"Block - End"`、`"Block - Hit"`、`"Parried"`、`"Riposte"`、`"Riposted"`、`"Back Stab"`、`"Back Stabbed"`、`"Guard_Break"`、`"Phase Shift"`、`"Death"`、`"Left Arm Empty"`、`"Right Arm Empty"`、`"Pick Up Item"`、`"Open Chest - Start"`、`"Chest Open"`、`"Shoot Arrow"`、四方向 `"Damage_ForwardRight_01"` 这一组，以及转向 `"Turn Left"`、`"Turn Right"`、`"Turn Around Left"`、`"Turn Around Right"`。箱子物体自己的 Animator 播 `"Chest Open"`。轻重击名字在组件字段上，不在调用点写死。

`animator.Play` 与 `CrossFade` 并存。换武器的 `"Left Arm Empty"` / `"Right Arm Empty"`、射箭 `"Shoot Arrow"`、对话结束的 `"NonCombat Whole Body Empty"`、开箱 `"Chest Open"` 用 `Play`。其余多数走 `PlayTargetAnimation`。

### 动画事件

这些方法在 `CharacterAnimatorManager` 上，没有 `public`，供动画片段按方法名调用。片段上的名字或参数对不上时，编译器不会报。

| 方法 | 随后做什么 |
| --- | --- |
| `OpenDamageCollider` | `isUsingLeftHand` 则打开左手伤害体，`isUsingRightHand` 则打开右手，然后 `PlayRandomWeaponWhoosh` |

| `GrantWeaponAttackingPoiseBonus` / `ResetWeaponAttackingPoiseBonus` | 把 `currentItemBeingUsed` 转成 `WeaponItem`，加减 `offensivePoiseBonus`；重置直接回到 `armorPoiseBonus` |
| `EnableIsVulnerable` / `DisableIsVulnerable` | 写 `isInvulnerable`。方法名带 Vulnerable，赋值是 `isInvulnerable = true / false` |

## 伤害与碰撞消息

近战、箭、处决走 `CharacterCombatManager.ResolveIncomingHit`。法术、炸弹、环境伤害直接调 `CharacterStatsManager.TakeDamage`（或玩家、敌人的覆写）。

`ResolveIncomingHit`（`Assets/Scripts/Character/CharacterCombatManager.cs`）签名：

```csharp
public void ResolveIncomingHit(
    CharacterManager attacker,
    string damageAnimation,
    IncomingDamage incoming,
    bool applyBlockAndPoise,
    float poiseDamage,
    float guardBreakModifider,
    bool spellFromFront = false)

// IncomingDamage 是结构体：DamageSegments Segments（五段乘完段位系数后）+ float Multiplier
```

`applyBlockAndPoise` 为 false 时直接 `TakeDamage(damageAnimation, incoming.Segments)` 并返回。为 true 时：

1. `attacker` 非空、自己 `isBlocking`、指向攻击者的向量归一化后 `Dot(..., self.forward) > 0.3`（法术还要 `spellFromFront`，由 `SpellOnShield.UseShield` 判）视为正面格挡。
2. 格挡成功则 `AttemptBlock`。扣体力在 `SpellOnShield.StaminaCost`（五段和 × `guardBreakModifider` × 稳定率，武器 `stability` 默认 0.67，先右手再左手）。`DeductStamina` 失败先 `EmptyStamina`；体力因此不大于 0 时关格挡、清吸收、播 `"Guard_Break"`，并经 `GuardBreak.OpensRiposte` 把对方置为可制裁。随后五段乘格挡吸收 `TakeDamage(null, ...)`。
3. 未格挡则 `totalPoiseDefence -= poiseDamage`，够就只扣血、动画名 null，不够就播传入的方向动画。方法末尾 `try/finally` 调 `EnemyManager.BreakReturnIfStillInRange()`：归家中的敌人若其实还在接战范围，转回追击。

`DamageCollider.DealDamage`（`Assets/Scripts/Damage/Damage Collider/DamageCollider.cs`）按当前手和 `AttackType` 取武器的段位系数（`laFirstPhaseDM` 到 `haSecondPhasDM`），然后：

```csharp
damageTarget.cCombat.ResolveIncomingHit(
    character, damageAnimation, incoming, true,
    poiseBreak, guardBreakModifider);
```

`OnTriggerEnter` 先要求对方 Tag 是 `"Player"` 或 `"Enemy"`，再 `GetComponent<CharacterManager>()`。自己打自己，或 `damageTarget.cStats.teamID == teamID`，直接返回。接下来分支：

| 条件 | 调用 |
| --- | --- |
| 撞上幻影墙 | 先 `IllusionWall.Strike()`（打或翻滚都显形），不结算 |
| 对方 `isParrying` 且在弹反帧窗 `ParryWindow.Open(...)` 内 | 攻击者播 `"Parried"`，`canBeRiposted = true`，这条不进 `DealDamage`；不在帧窗则按普通命中继续 |
| `isBlocking` | 点积算正面时 `DealDamage(..., "Block - Hit", ...)`，否则先选方向受击名再 `DealDamage` |
| 其余 | `isInvulnerable` 则返回。否则播 `PlayBloodSplatter`，按双方 forward 的有符号角选四方向 `Damage_*_01`，再 `DealDamage` |

近战同一次伤害窗口用 `hitThisWindow` 记下已经打过的角色，同一人再进不再结算。`EnableDamageCollider` 和 `DisableDamageCollider` 都会清这份名单。收招仍靠 `CloseDamageCollider` → `DisableDamageCollider`。

| 入口 | 回调 | 是否进 `DealDamage` / `ResolveIncomingHit` | 实际传入 |
| --- | --- | --- | --- |
| `DamageCollider` | `OnTriggerEnter` | 是，`applyBlockAndPoise: true` | 武器装上时写入的五段，再乘段位系数 |
| `AmmoDamageCollider` | 先调基类 `OnTriggerEnter` | 是，与近战同一条 | 之后按是否打中角色决定生成 `penetratedModel`，然后销毁箭 |
| `SpellDamageCollider` | `OnCollisionEnter` | 正面举盾时是（走 `ResolveIncomingHit` 且 `spellFromFront: true`），否则否（直接 `TakeDamage`） | 五段全传；对应段由 `ProjectileSpell` 按学派写 `baseDamage` |
| `BombDamageCollider` | `OnCollisionEnter`，再 `OverlapSphere` | 否。同样找 `CharacterStatsManager` | 直击 `TakeDamage("Damage_ForwardRight_01", fd: explosionDamage)`；溅射 `TakeDamage(null, fd: explosionSplashDamage)`，并跳过直击那一个 `CharacterStatsManager` |
| `DamagePlayer` | `OnTriggerEnter`，只认 Tag `"Player"` | 否。要 `PlayerStatsManager` | `TakeDamage("Damage_ForwardRight_01", fd: damage)`，`damage` 默认 25 |
| `GetBackStabbed` / `GetRiposte` | 处决动作直接调 | `ResolveIncomingHit`，`applyBlockAndPoise: false` | 动画名 `"Back Stabbed"` / `"Riposted"`，系数 `criticalAttackDM`，五段来自攻击者 `rightWeapon`。右手武器为空时不扣血，站位协程已经启动 |

法术和炸弹用 `hasCollided`，撞墙或撞队友也会吃掉这一发。箭的嵌入逻辑在基类结算之后执行。脚本里没有用 `LayerMask` 过滤这些伤害回调，过滤是 Tag 加上 `teamID`。近战要对方有 `CharacterManager`；法术和炸弹要 `CharacterStatsManager`；`DamagePlayer` 要 `PlayerStatsManager`。

伤害体字段默认 `teamID = 0`，角色默认 `teamID = 2`。近战在 `LoadWeaponDamageCollider` 里改成持有者的 `teamID`。法术和炸弹在生成时写成施放者的 `teamID`。

## 耦合方式

运行时没有单例类型，也没有事件总线。常见的接法有四种。

**同一物体上的具体类。** `CharacterManager.Awake` 和 `PlayerManager.Awake` 用 `GetComponent` 把各 Manager 填进公开字段。UI 多数用 `transform.root.GetComponent<PlayerManager>()`。人形和通用状态机用 `GetComponent` 拿同物体上的下一个具体 `State`。伤害体用 `GetComponent<CharacterManager>()`、`GetComponent<CharacterStatsManager>()` 或 `GetComponent<PlayerStatsManager>()`。武器模型上再 `GetComponentInChildren<DamageCollider>()`、`WeaponFX`、IK 目标。

**场景查找。** `PlayerManager` 找 `PlayerCameraManager`；`PlayerCameraManager`、`WorldManager`、`UIEnemyHealthBar` 找 `PlayerManager`；`EnemyStatsManager` 在 `Awake` 里找 `WorldManager` 和玩家，死亡沿用这份玩家引用；`WorldUIManager` 找 `UIBossHealthBar`。这些调用在 `Awake` 或死亡回调里，不在每帧移动里。

**硬编码的具体类型。** 下面这些边界，调用方写死了对方的类和字段名：

- `PlayerCombatManager` 按键名直接读 `WeaponItem` 的 `oh_tap_e_action` 等槽，并依赖 `PlayerManager.input`。
- `ItemBasedAttackAction` 按 `NPCCombatStyle` 写死 `th_tap_e_action`、`oh_tap_q_action` 这些槽。
- `DamageCollider` 依赖 `CharacterCombatManager.isParrying`、`isBlocking`、`attackType` 和具体的 `AttackType` 段位。
- `PlayerStatsManager` 直接调用 `player.ui.hud` 上的 `healthBar`、`staminaBar`、`focusPointsBar`（`FocusPointsBar`）。
- 设置只从 `PlayerManager.ui.escWin.GetSettingWin().gameSettingsData` 读取。
- `HandleRollState`、`HandleJumpState`、`HandleAimingState`、`HandleUseComsumableState` 把 `CharacterManager` 转成 `PlayerManager`；`HandlePhaseShiftState`、`HandleTurnState` 直接要 `EnemyManager`。
- `ProjectileSpell`、`FlaskItem`、`BombItem`、`ShootArrowAction` 分别转到 `PlayerManager` 或 `EnemyManager`，并点名武器槽、镜头、特效字段。
- 通用 AI 与人形 AI 是两套具体状态类，没有共用的攻击接口。通用侧播 `EnemyAttackAction.actionAnimation`，人形侧走进武器动作槽。

**已经稳定、调用方可以按签名对接的边界：**

- `CharacterAnimatorManager.PlayTargetAnimation` 的五个参数，以及它同步的 `isInteracting`、`canRotate`、`applyRootMotion`。
- `CharacterStatsManager.TakeDamage` 的动画名加五段伤害加 `playHurtSound`，返回值表示这次有没有扣血。
- `CharacterCombatManager.ResolveIncomingHit` 的格挡与韧性开关。
- `WeaponItemAction.PerformAction(CharacterManager)`。
- `SpellItem` 的 `AttemptToCastSpell` / `SuccessfullyCastSpell`，`ConsumableItem` 的 `AttemptToConsumableItem` / `SuccessfullyUsedConsumable`。
- `Interactable.Interact(PlayerManager)`，`State.Tick(EnemyManager)`。
- `PopUpInterface.PopUp()`。
- 武器装上后，`DamageCollider` 上会被写到的 `character`、`teamID`、`poiseBreak` 和五段伤害。

动画片段上的方法名、写死的状态名、以及按键到 `oh_*` 槽的对应关系，改名字不会由编译器帮调用方改。
