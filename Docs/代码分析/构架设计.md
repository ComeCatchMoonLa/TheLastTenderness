# 构架设计

> **一个角色是同一物体上的 `CharacterManager` 加七个 Manager，旗标挂在 `CharacterManager` 上。** 当前 `Assets/Scripts/` 有 251 个脚本。角色组件落在 MonoBehaviour、Animator 的 `StateMachineBehaviour` 和 ScriptableObject 上。不挂物体的静态纯函数类现有约 90 个，代表有 `AttackScore`、`OverlapQuery`、`AttackPoiseWindow`、`ParryWindow`、`LockMark`、`WalkSpeed`、`Leash`、`Territory`、`MemorySlotBonus`、`PhantomEntry`、`Elevator`、`NewCycle`、`EndingChoice`。命名空间是 `CatchMoon`；`Animator/HandleState/` 下的 10 个状态行为在全局命名空间，用 `using CatchMoon` 拿到角色。生成的 `InputActions` 也在全局命名空间。

本文按现在的代码写模块如何分层、状态归谁、运行时怎么拼、数据怎么流。公开方法清单见 [接口设计.md](接口设计.md)，调用代价与改一处要看几处见 [可维护性.md](可维护性.md) 与 [性能.md](性能.md)，测试缺口见 [可测试性.md](可测试性.md)。

项目设置里没有脚本执行顺序配置，但 `ElevatorPlatform` 挂了 `[DefaultExecutionOrder(-200)]`，是全工程唯一一处代码级执行顺序指定。

## 目录与模块

```text
Assets/Scripts/
  Character/          角色根与七个 Manager；Player/、NPC/
  Animator/           StateMachineBehaviour、双手 IK
  Items/              物品资产、武器动作、装备槽、消耗品、法术、交互物
  Damage/             武器触发器、弹药、法术、炸弹、环境伤害
  UI/                 玩家界面树，以及敌人血条、Boss 血条
  World/              世界事件、Boss 血条接线、开战碰撞体
  Camera/             跟随、旋转；锁定扫描 LockOnQuery
  Input/              生成的 InputActions
  Sounds/             角色身上的一个 AudioSource
  SomeData/           文案与设置资产
  EnumsTypes.cs       物品、战斗、界面共用枚举（21 个，另有数个新枚举散在 UI/物品文件里）
  Layer.cs            层号 7–11 与对应 LayerMask
  Func.cs             Transform.ResetLocal；OverlapQuery.CollectOverlaps
```

根目录只有这三个文件；旧的 `DestroyAuto.cs` 已删（粒子销毁改由粒子系统 Stop Action 处理）。

| --- | --- |

## 运行时如何拼起来

构建列表里只有 `Assets/Scenes/Game.unity`。玩家、相机、地图是分开的场景物体，靠 `Awake` 互相查找，没有场景级装配器。

**玩家。** 根物体上有一份 `Assets/Prefabs/Player/Player.prefab`（场景里名叫 Player）。同一物体上有 `Animator`（`Humanoid.controller`）、`Rigidbody`、`CapsuleCollider`、`AudioSource`、`RigBuilder`，以及 `PlayerManager` 与玩家侧的动画、输入、护甲、战斗、特效、库存、移动、属性、武器槽。`CharacterWeaponSlotManager.Awake` 在子物体里按 `ItemSlotType` 收集左手、右手、背三个 `WeaponHolderSlot`。`PlayerManager.Awake` 用 `GetComponentInChildren<PlayerUIManager>()` 找到嵌套的 `Assets/Prefabs/#/UI.prefab`（根物体名 `UI`，上面挂 `PlayerUIManager`）。`PlayerCameraManager` 不在这个预制体上。

**相机。** 场景根上的 `Player Camera` 挂 `PlayerCameraManager` 和 `LockOnQuery`。玩家 `Awake` 用 `FindAnyObjectByType` 找到相机组件，相机 `Awake` 再找 `PlayerManager`，并用 `GetComponent` 取同物体上的 `LockOnQuery`。`Update` 里相机调用 `LockOnQuery.UpdateLockOnTargets`，球形查询只向 `npc` 层要碰撞体，半径用 `maxLockOnDist`。跟随和旋转仍在 `LateUpdate`。

**现在开着的交互地图。** 根物体 `Test Map - Interacte` 处于激活。它下面的 `Interactables` 也激活，拾取、箱子、篝火、查看挂在这层之下。

**现在开着的战斗地图。** 根物体 `Test Map - Combat` 处于激活。它下面的 `Test A.I` 放着三份 `Assets/Prefabs/Humanoid A.I - Melee.prefab`，场景名是 `Humanoid A.I - Melee (0/1/2)`，实例上 `enableAI` 为真。预制体根上是 `EnemyManager` 与敌人侧七个 Manager，同样使用 `Humanoid.controller`。子物体 `Enemy States` 仍挂人形五状态，`currentState` 指向 `IdleStateHumanoid`。待机、追击、转向的判定在 General 基类上，这三个人形子类只把周旋指到 `CombatStanceStateHumanoid`。子物体 `Navmesh Agent` 上的 `NavMeshAgent` 在 `EnemyManager.Start` 里关掉。`Test Map - Locomotion` 仍未激活。

**剧情与世界事件。** 根物体 `NPCs - Story` 未激活，下面是 `Assets/Prefabs/NPC/Default Story NPC.prefab` 的实例（0.33）。根物体 `World` 未激活，上面挂 `WorldManager`，子物体有 `WorldEventManager`。雾墙、开战碰撞体在这棵树里。`FogWall.Start` 会把自己关掉；`EventColliderBeginBossFight` 进入时调用 `WorldEventManager.ActivateBossFight`。`Assets/Scenes/Game_Before_0.7.unity` 不在构建列表里，其中有 `Boss (Simple A.I)`。`BossCombatStanceState` 与 `State/General A.I/` 的具体类型仍留在工程里。构建场景里的人形近战挂的是子类，待机、追击、转向的 `Tick` 用基类。`sencondPhaseAttacks` 仍在 `BossCombatStanceState`。攻击和周旋仍是两套。

一帧里和角色有关的阶段，按 Unity 生命周期分开，同阶段脚本之间没有指定先后：

1. `PlayerLocomotionManager.FixedUpdate` 按移动、转向、坠落、跳、翻滚、后撤的顺序写刚体，并把速度长度记到 `currentSpeed`。
2. Input System 回调只改 `InputManager` 上的布尔量和向量。
3. `Update`：`InputManager` 读移动和翻滚键；`PlayerCombatManager` 读战斗键；`PlayerInventoryManager` 读换武器、换法术、换消耗品和双手切换；`PlayerManager` 做交互检测并推进对话；`EnemyManager` 在未死亡时跑恢复计时、`State.Tick` 和目标距离；`PlayerCameraManager` 调用 `LockOnQuery.UpdateLockOnTargets`；`PlayerUIManager` 处理分页窗、准星和 Esc。
4. Animator 播放到带行为的状态时进入/离开 `StateMachineBehaviour`。根运动走 `OnAnimatorMove`：玩家和敌人都只在 `isInteracting` 时写速度。追击和回家的水平速度来自导航的 `desiredVelocity`。
5. `LateUpdate`：`InputManager` 清方向键、交互点按和 Esc；`PlayerCameraManager` 做跟随与旋转；每个敌人把子物体上的导航代理本地变换拉回零。

## 状态所有权

| 状态 | 放在哪 |
| --- | --- |
| 交互、转向、滞空、跳、翻滚、冲刺、左右手、双手、连击、背刺弹反过程 | `CharacterManager` 公开布尔。每帧 `UpdateBoolsValue` 把 `isBlocking`、`isDead`、`isTwoHandingWeapon` 写进 Animator；玩家再写 `aimingMode` |
| 移动量、鼠标、点按布尔、`rollFlag`、`backStepFlag` | `InputManager`。`moveAmount` 在输入组件上。冲刺过程是 `CharacterManager.isSprinting`，由 `HandleRollInput` 写入。`sprintFlag` 只有声明 |
| 攻击类型、攻防瞄准施法用药等过程旗标、霸体窗口 | 过程旗标在 `CharacterCombatManager`；攻击霸体窗口由静态 `AttackPoiseWindow` 开/关（`HandleAttackState` 进出时持有 token），格挡吸收五段和稳定率写在 `CharacterStatsManager`，由 `SetBlockingAbsorptionFromBlockingWeapon` 按当前手抄武器（法术格挡抄录在 `SpellOnShield`）。弹反帧窗在 `ParryWindow`，背刺一次性锁在 `BackstabLock`。背刺和弹反不留待结算伤害 |
| 血、体力、专注、等级、护甲吸收、韧性、队伍、死亡、无敌 | `CharacterStatsManager`。上限在 `Awake` 里由等级乘 10。玩家子类另有 `soulCount`、死亡残留 `hasSoulRemnant`/`soulRemnant` 与结局记录 `recordedEnding`，受伤后写 HUD |
| 当前左右武器、快捷法术、消耗品、弹药、武器数组 | `CharacterInventoryManager`。玩家子类另有分类列表，以及消耗品、弹药的剩余数字典。`Start` 取出当前左右武器后调用 `LoadWeaponsOnBothHands` |
| 当前手持武器模型与 `DamageCollider` | `WeaponHolderSlot.currentWeaponModel` 是运行时实例；`CharacterWeaponSlotManager` 缓存左右伤害体 |
| 护甲部位 | `PlayerArmorManager` 的头、躯干、护手、下身引用。穿上后 `EquipAllArmorModels` 把头、躯干、下身（含护手槽）的物理、火、魔、雷、暗五段吸收写进属性，空槽写 0；护手换模还没接 |
| AI 当前状态、目标、距离、转向角、恢复计时 | `EnemyManager`。感知与连击概率在 `EnemyAISettings` 资产。同一子物体上仍是人形五状态，`Tick` 返回下一个状态。待机、追击、转向的 `Tick` 在 General 基类；攻击和周旋的 `Tick` 仍在 `CombatStanceStateHumanoid`、`AttackStateHumanoid`，General 另有一套 |
| 锁定扫描、换目标、锁定标记 | 相机物体上的 `LockOnQuery`。球形查询只向 `npc` 层要碰撞体，半径用 `maxLockOnDist`。当前锁定目标、`lockOnFlag`、`lockOnMode` 和相机角仍在 `PlayerCameraManager`。标记由 `HUDWindowsManager` 按 `LockMark.Shown` 画到 `lockOnTransform`。瞄准模式是 `PlayerManager.aimingMode` |
| 窗口开到哪一层 | `PlayerUIManager.openedWin`。血条数值在属性变化时由 `PlayerStatsManager` 写入 `HUDWindowsManager` 的条，条自己不读属性 |
| 对话与查看文案、音画选项 | `DialogueTextData`、`TextData`、`GameSettingsData`。设置从 `player.ui.escWin` 上的窗口读 |

`CharacterManager.Update` 在死亡后直接返回。玩家移动、战斗、库存各自再查一次自己的 `isDead`。

敌人攻击不自己读键盘。选招计分只由 `AttackScore.PickIndex` 写。人形周旋 `CombatStanceStateHumanoid.GetNewAttack` 把选中下标写进 `AttackStateHumanoid.currentAttack`，出手时 `ItemBasedAttackAction` 标左右手并调用武器上的 `WeaponItemAction`。General 的周旋同样调用 `PickIndex`，攻击数据仍是 `EnemyAttackAction`。`BossCombatStanceState` 继承 `CombatStanceState`，转阶段后把 `sencondPhaseAttacks` 交给 `PickIndex`。已经有招时，General 和 Boss 不改当前招；人形仍可以换成这一下。两种出手字段不并。

暂停只发生在 `EscWindowsManager`：`Open` 关掉游戏动作图、打开 `UIOperation`，并写 `Time.timeScale = 0`；关回根窗口时写回 1。分页窗只开关物体。

## 动画与逻辑

播放入口是 `CharacterAnimatorManager.PlayTargetAnimation`。它先在各层查找状态名，找不到就打日志并返回，此时不改旗标。找得到则写下 `applyRootMotion`、`isInteracting`、`canRotate`、`isMirrored`、`isRotatingWithRootMotion`，再 `CrossFade`（过渡 0.2 秒）。移动混合由 `PlayerAnimatorManager.UpdateAnimatorValues` 写成 `Vertical` / `Horizontal`。

轻重击的动画名配置在 `CharacterAnimatorManager` 上（`ohLightAttack1` 这一组）。`LightAttackAction` 与 `HeavyAttackAction` 把这些字符串交给 `MeleeAttackSegment.Play`，由它按双手、左右手和上一击 `lastAttack` 决定播第一段还是第二段，并写下 `CharacterCombatManager.attackType`。

进行中的开关由动画状态上的 `StateMachineBehaviour` 改，逻辑脚本不在播到一半时自己清这些旗标：

| 行为 | 进入 | 离开 |
| --- | --- | --- |
| `HandleEmptyState` | 全身层：允许转向，清交互、无敌、左右手、攻击、背刺弹反，镜像复位。层名是 `Upper Body` 时整段返回 | — |
| `HandleRollState` / `HandleJumpState` / `HandleAimingState` | 置对应旗标，并改玩家胶囊 | 只清旗标 |
| `HandleAttackState` | `isAttacking = true` | 清攻击，停左右武器拖尾 |
| `HandleUseSpellState` / `HandleUseComsumableState` | 置施法或用药 | 清掉 |
| `HandleTurnState` | — | 把 `turnAngle` 乘进当前旋转 |
| `HandlePhaseShiftState` | 敌人 `isPhaseShifting` | 清掉 |
| `HandleChestOpenState` | — | 箱子开完后的收尾 |

命中窗、体力、可连击、无敌、可弹反，由动画事件调用 `CharacterAnimatorManager` 上的同名方法：`OpenDamageCollider`、`CloseDamageCollider`、`DrainStamina`、`EnableCombo`、`EnableIsVulnerable`、`EnableIsParrying`（弹反只开窗帧 `parryOpenedFrame`，命中判定再由 `ParryWindow.Open` 比对）等。攻击霸体的进出由 `HandleAttackState` 经 `AttackPoiseWindow.Open/Close` 管，同名动画事件内部也改走它。法术与消耗品的结算也是事件：`PlayerAnimatorManager.SuccessfullyCastSpell` 转给 `currentSpell`；`SuccessfullyCastConsumable` 取按下时记下的 `consumableBeingUsed`。背刺和弹反处决走 `GetBackStabbed` / `GetRiposte`。

根运动：玩家 `OnAnimatorMove` 只在 `isInteracting` 时用 `deltaPosition / deltaTime` 覆盖刚体速度。敌人 `WritesHorizontalRootVelocity` 现在只在 `isInteracting` 时返回真，非交互动画不写水平根速度。`isRotatingWithRootMotion` 仍单独改朝向。平时地面移动写刚体速度，落地改高度，转向改 `transform.rotation`。双手 IK 的目标来自武器模型；`UpdateHandIKWeight` 在双手近战且未交互时把权重量成 1。

## 数据资产

物品树的根是 `Item`（ScriptableObject）。`EquipmentItem` 下是 `WeaponItem`、`ArmorItem`（头、躯干、下身、手四个空子类）、`AmmoItem`。`SpellItem` 下是 `ProjectileSpell` 与 `HealingSpell`。`ConsumableItem` 下是 `FlaskItem`、`BombItem`、`EmberItem`，以及回城道具 `HomewardBoneItem`、`DarkSignItem`、`CoilFragmentItem`（后一个继承回城骨）。`Item` 上另有 `isRing`、`isCovenantMark`、`isKey` 标志，戒指与印记不单开物品子类。

武器怎么响应按键，由武器资产上的 `WeaponItemAction` 引用决定。`PerformAction(CharacterManager)` 是抽象方法。法术再分两层：武器上的 `SorcerySpellAction`、`PyromancySpellAction`、`MiracleSpellAction` 核对学派（`CatalystMatch`）、记忆栏（`SpellMemory`）、属性和蓝量；生成弹体或加血在 `SpellItem` 子类，并且要等动画事件。

背包窗口画的是 `PlayerInventoryManager` 里的武器、护甲、法术、消耗品列表，列表元素是同一份资产引用。数量在该玩家组件的字典里，`Start` 时消耗品读资产 `currentItemAmount`、箭读 `cnt`，各自夹取到上限内。`TrySpendConsumable` / `TrySpendAmmo` 扣这份运行时数字。护甲换模由角色身上的 `ModelChanger` 按 `Item.transformName` 开关直接子物体，头、躯干、下身各有 `ModelChanger` 子类；护手槽已参与五段吸收，但还没有护手模型切换。

AI 参数是 `EnemyAISettings`。人形出招是 `ItemBasedAttackAction`，General 出招是 `EnemyAttackAction`。查看用 `TextData`，对话用它的子类 `DialogueTextData`。音画与对话节奏在 `GameSettingsData`，挂在设置窗口上，相机速度和自动锁定也从这里读。

## 一次轻击到扣血

点按写进 `InputManager.tap_e_Input`。同一帧稍后 `PlayerCombatManager.HandleCombatInput` 按按住 E、按住 Q、点按 E、点按 R、点按 Q、点按 Z 的顺序各看一次。点按 E 时，左手是弓就执行左手武器的 `oh_tap_e_action`，否则执行右手的。调用前会 `UpdateWhichHandCharacterIsUsing`，并把该武器记到 `currentItemBeingUsed`。

`LightAttackAction.PerformAction` 在体力大于 0 时放行。已有连击窗就走下一段；否则 `isInteracting` 为真就返回。`MeleeAttackSegment` 选出动画名和 `AttackType`，再 `PlayTargetAnimation(..., isInteracting: true)`。状态进入后 `HandleAttackState` 把 `isAttacking` 置真。动画事件 `OpenDamageCollider` 打开当前手的 `DamageCollider` 并播挥刀音。

武器上的触发器在 `OnTriggerEnter` 里认 `Player` 与 `Enemy` 标签。同对象或同 `teamID` 直接返回。目标正在弹反则让攻击者播被弹反并允许反击；正在格挡则带着 `"Block - Hit"` 进去；否则按朝向选受伤动画名，并在接触点放血。`DealDamage` 按 `attackType` 取该手武器的阶段系数，再调用受击者的 `CharacterCombatManager.ResolveIncomingHit`。

`ResolveIncomingHit` 先在 `IncomingDamage` 上乘段位系数。`applyBlockAndPoise` 为假时直接 `TakeDamage`。格挡朝向成立（或 `spellFromFront` 的法术）则 `AttemptBlock` 扣体力，体力耗尽就播 `"Guard_Break"`、经 `GuardBreak.OpensRiposte` 把对方置为可制裁，并清吸收，然后按吸收再乘一次并扣血。朝向不成立时先减韧性：减完仍高于这次破韧就只扣血，否则扣血并播受击。`TakeDamage` 按头 60%、躯干 30%、下身 10% 折掉护甲后再减 `currentHP`，并在同一步结算冻伤受伤系数。玩家覆写在血量到 0 时调用 `Death`。全身层回到带 `HandleEmptyState` 的空状态时，交互和攻击旗标被清掉，移动恢复。

法术与炸弹的 `SpellDamageCollider`、`BombDamageCollider` 重写 `Start` 且不调用基类，命中走 `OnCollisionEnter`：炸弹直击与溅射直接 `TakeDamage`；法术在目标正面举盾时改走 `ResolveIncomingHit`（`SpellOnShield`），否则直接 `TakeDamage`。环境伤害是 `DamagePlayer` 上的触发器。

## 已固定的入口

后续改动沿这些入口接，不另起一套角色核或伤害核。

- 角色识别与旗标走 `CharacterManager`。七个 Manager 与 `Animator`、`Rigidbody`、`CapsuleCollider` 在同一物体上，用 `GetComponent` 接好。玩家特有逻辑放 `Player*` 子类，敌人特有逻辑放 `Enemy*` 子类。
- 播一个具名动作只走 `CharacterAnimatorManager.PlayTargetAnimation`。移动混合走 `PlayerAnimatorManager.UpdateAnimatorValues`。随动画段落翻转的旗标挂在现有 `Handle*State` 上，随片段时刻翻转的开关挂在动画事件调用的同名方法上。
- 玩家战斗键只选武器资产上的 `WeaponItemAction` 并调用 `PerformAction`。人形 AI 先由周旋里的 `AttackScore.PickIndex` 选下标，再走 `ItemBasedAttackAction`，最终仍落到武器动作。General 与 Boss 的列表仍是 `EnemyAttackAction`，Boss 第二阶段仍读 `sencondPhaseAttacks`。消耗品走 `ConsumableItem.AttemptToConsumableItem`，法术效果走 `SpellItem`，结算留在现有动画事件。
- 近战命中窗是武器模型上的 `DamageCollider`，由 `OpenDamageCollider` 开关。带格挡和韧性的入伤走 `ResolveIncomingHit`，扣血和死亡仍在 `CharacterStatsManager.TakeDamage` / `Death`。背刺与弹反走受击者的 `GetBackStabbed` / `GetRiposte`。
- 换武器模型只走 `CharacterWeaponSlotManager.LoadWeaponOnSlot`（以及它调用的 `WeaponHolderSlot.LoadWeaponModel`）。槽位用 `ItemSlotType`，用手的挂点，不按物体名叫 `Hand_L` 还是 `Hand_R` 来认。
- 敌人决策是挂在角色子物体上的 `State`，由 `EnemyManager.HandleStateMachine` 执行 `Tick`。待机、追击、转向的判定在 General 基类。感知半径、角度、连击权重放 `EnemyAISettings`。
- 场景交互实现 `Interactable.Interact`，由 `PlayerManager.CheckForInteractableObject` 的球体查询点按调用。Boss 开战、雾墙、Boss 血条走 `WorldEventManager` 与 `WorldUIManager`。
- 新物品是 `Item` 子类资产。运行时数量、当前快捷栏、护甲穿戴写在玩家组件上。界面从这些字段刷新；暂停只改 `EscWindowsManager` 里的 `timeScale` 与输入动作图。层号继续用 `Layer` / `LayerMask`。
