# 世界与界面

> **没有大出入。** 敌人、燃火休息与死亡惩罚、战斗 HUD 里标成「当前已有」的可观察结果，和 `Assets/Scripts` 里正在跑的路径一致。标成待补的条目，以及挂在未激活父节点下、进游戏看不到的物件，没有当成偏离。

只对这三篇需求：[`敌人.md`](../需求文档/功能需求/敌人.md)、[`燃火休息与死亡惩罚.md`](../需求文档/功能需求/燃火休息与死亡惩罚.md)、[`战斗HUD.md`](../需求文档/功能需求/战斗HUD.md)。调研和需求不一致时，以需求里已经写明的「当前已有 / 待补」为准，并点出调研篇目。

`Game` 里实际在跑的是玩家，以及 `Test A.I` 下三只 `Humanoid A.I - Melee`（`(0)` `(1)` `(2)`，`enableAI` 为真）。这三只预制体的 `currentState` 是 `IdleStateHumanoid`，状态机是 Humanoid 那五个状态。右手武器是单手剑（`melee_OH_RH`），左手是盾。`EnemyInventoryManager.Start` 会在 `base.Start` 装载武器之前，按右手类型决定要不要写 `isTwoHandingWeapon`；这三只不是双手武器，标记保持为假，攻击走 `oh_*`。

## 场景里进不去

这些物体自己可以是激活的，但父节点关掉了，进游戏看不到。脚本留在工程里，没有把「未激活」写成实现错误。

| 物体 | 父节点 | 父节点状态 |
| --- | --- | --- |
| `Camp Fire`（`CampFireInteractable`） | `Interactables` | 未激活 |
| `Chest` | `Interactables` | 未激活 |
| `Fog Wall` | `World` 下的 `World Event Manager` | `World` 未激活 |
| `Default Story NPC` | `NPCs - Story` | 未激活 |

## 查过、对得上的条目

### 敌人

| 编号 | 要的结果 | 代码实际 |
| --- | --- | --- |
| FR-敌人-01 | 正面进入发现范围且没有挡住时转向并追；背后或被挡住时待机；`enableAI` 为假则待机 | `IdleStateHumanoid.Tick`：先看 `enableAI`、死亡、交互。`OverlapQuery.CollectOverlaps` 用 `detectionRadius`（这三只的配置是 30），夹角在 `minViewAngel` / `maxViewAngel`（-62 到 62）内，再 `Linecast`。挡住就留在待机；够到了才写 `currentTarget` 并切到追击。三只的 AI 是开的 |
| FR-敌人-02 | 发现后向玩家移动；进入攻击距离后停追并出手，玩家生命可以下降；中距离仍跟着 | `PursueTargetStateHumanoid` 在距离大于 `aggroRadius`（5）时把 `Vertical` 写成 1，并给导航设终点；不大于时切到交战。`CombatStanceStateHumanoid` 再按攻击数据的距离和角度选招，交给 `AttackStateHumanoid`。出手走 `ItemBasedAttackAction` 的单手点按 |
| FR-敌人-03 | 破韧则受击并停追或停攻，血仍掉；韧性够则动作继续、血仍掉。挥空后回到交战或追击。交战里有时举盾、闪避、弹反 | 受击是否播动画走 `CharacterCombatManager.ResolveIncomingHit`，和玩家同一套比较：结算后的 `totalPoiseDefence` 不再大于本次 `poiseBreak` 才把受击动画名传进 `TakeDamage`。追击、待机、转向在 `isInteracting` 时留在当前状态。`AttackStateHumanoid` 在打出的同一次 `Tick` 返回转向，转向再按距离回追击或交战。举盾、闪避、弹反是交战里的掷选（这三只配置了概率，不是必现） |
| FR-敌人-04 | 生命到 0 播死亡，不再追和打；玩家灵魂增加；当时锁着它则解除或改锁；过一会儿从场景消失 | `EnemyStatsManager.Death` 先走基类：生命写成 0、播 `"Death"`、`isDead` 为真。`EnemyManager.Update` 见死亡就返回。`HandleEnemyDeathEvent` 在 `lockOnFlag` 为真时先 `Unlock` 再把 `lockOnMode` 写成真并 `UpdateLockOnTargets`（已死的目标会被跳过）。`AwardSoulsOnDeath` 调用 `AddSouls`，并 `SetSoulCountText`。`Destroy` 等待 `destoryWaitTime`（预制体上是 3 秒）。这和 [FR-镜头-06](../需求文档/功能需求/镜头与锁定.md) 写的「先解除再重新查找」一致 |

FR-敌人-05（走远后放弃并回家）需求自己标成待补。`PursueTargetStateHumanoid` 在距离大于 `aggroRadius` 时继续追，没有回待机、也没有清 `currentTarget`。调研 [`敌人与头目.md`](../调研文档/敌人与头目.md) 写的是黑魂 3 会离开活动范围后走回放置点。需求已把这件事划出「当前已有」，不记成偏离。

### 燃火休息与死亡惩罚

| 编号 | 要的结果 | 代码实际 |
| --- | --- | --- |
| FR-燃火-01 | 对未点燃的燃火交互：拾取动作、燃起提示、火焰可见，再次靠近的提示是「休息」 | `CampFireInteractable`：`hasBeenActived` 为假时提示是「点火」；`Interact` 播 `"Pick Up Item"`、弹出 `CampFireLitPopUpUI`、打开并播放 `fireFX`、把标记和提示改成已点燃 / 「休息」。`hasBeenActived` 为真时方法体是空的。场景里这盏火在未激活的 `Interactables` 下，进不去 |
| FR-燃火-08 | 生命到 0 播死亡，`isDead` 为真，不能再移动、翻滚、攻击、喝药 | `PlayerStatsManager.TakeDamage` 在生命不大于 0 时调用基类 `Death`。`InputManager`、`PlayerLocomotionManager`、`PlayerCombatManager`、`PlayerInventoryManager` 看见死亡就返回 |

FR-燃火-02 到 07 需求标成待补：休息回满、复活敌人、补药、死亡把灵魂写成 0 并留下可交互残留、捡回、再死丢掉旧残留。代码里没有把 `soulCount` 归零，也没有血迹或灵魂残留类型。`AddSouls` 只做加法。调研 [`世界与篝火.md`](../调研文档/世界与篝火.md) 写的是坐下结算和死亡血迹；[`本仓库对照.md`](../调研文档/本仓库对照.md) 也把血迹、归零、重生点写成缺口。需求已标待补，不记成偏离。篝火菜单四项不在本篇。

### 战斗 HUD

| 编号 | 要的结果 | 代码实际 |
| --- | --- | --- |
| FR-界面-01 | 同时看见生命、精力、专注；受伤血条变短，喝血变长，冲刺精力变短，停手回复变长；到上限为满，到 0 为空 | `PlayerStatsManager.Start` 写入三条的上限和当前值。受伤、加血、扣血写 `HealthBar`；扣精力、加精力，以及停下超过 1 秒后的 `RegenerateStamina` 写 `StaminaBar`；加减专注写 `FocusPointsBar`（字段名是 `manaBar`）。条用 `Slider`，不每帧自己去读属性 |
| FR-界面-02 | 换右手武器、当前法术或当前消耗品后，对应格子换成新图标；没有图标的格子保持空白 | `PlayerWeaponSlotManager.LoadWeaponOnSlot` 成功后 `UpdateCurrentWeaponIcon`。换法术、换消耗品分别调用 `UpdateCurrentSpellIcon`、`UpdateCurrentConsumableIcon`。图标为空时这两处直接返回，不启用那一格 |
| FR-界面-03 | 打中近战敌人后头上出血条，长度对应当前生命；停手约两秒后隐藏；再打中则重新出现 | 非头目的 `EnemyStatsManager.TakeDamage` 写当前生命并 `ShowBar`（默认 2 秒）。`UIEnemyHealthBar` 计时到点后把同一物体上的 `Slider` 关掉；下一次 `ShowBar` 再打开。血条和 `Slider` 在预制体的同一个 `Health Bar` 上 |
| FR-界面-04 | 走进可交互范围出现提示，离开后消失；燃火未点燃和已点燃的提示不同 | `PlayerManager.CheckForInteractableObject` 在范围内 `PopUpInteractInfoUI`，否则 `CloseInteractInfoUI`。燃火提示见上一节，场景里进不去 |

锁定标记不在本篇编号里。需求把它指到 [FR-镜头-07](../需求文档/功能需求/镜头与锁定.md)，并标成待补。`HUD Windows` 下没有读 `curLockOnTarget` 的标记；`HUDWindowsManager` 的准心只跟瞄准。调研 [`界面与场景交互.md`](../调研文档/界面与场景交互.md) 写的是目标身上的白点。待补，不记成偏离。

FR-界面-05（任意途径改灵魂都刷新数字）、FR-界面-06（快捷栏显示回复剩余次数）需求标成待补。击杀这条已经会改字，见 FR-敌人-04。`AddSouls` 单独调用时不改文字。没有回复次数的显示。不记成偏离。
