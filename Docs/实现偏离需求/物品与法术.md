# 物品与法术：实现偏离需求

> **有两条大出入。** 投射法术打中时不按学派进不同伤害段；装备窗选中护甲槽后再点背包里的武器，武器会离开背包，手上却没有新模型。

对照范围是装备与道具、回复类消耗品、法术、箭矢与弩，以及已经写在代码里的三项上限公式。以 `Assets/Scripts` 现在的路径为准。注入、强化、九项属性加点、创角整套未做，不记偏离。护甲五段吸收、消耗次数记在玩家身上、武器按左右手与弓收背、炸弹认 `consumableBeingUsed`、法术和炸弹直接 `TakeDamage` 这几条，按已改完的现状，不再单独记成偏离。

## 大出入

### FR-法术-05 投射命中不按学派进对应伤害段

要的结果：弹体打中时，伤害种类跟这一条法术走，进魔法、火焰、雷电或暗里的一段。调研同一句话在 [魔法与道具](../调研文档/魔法与道具.md)「投射」：命中结算该种类伤害；「法术威力改什么」写明再进魔法、火焰、雷电或暗这一种吸收。

代码实际：`ProjectileSpell.SuccessfullyCastSpellWithPlayer` 只写 `spellDC.fd = baseDamage`。`SpellDamageCollider.OnCollisionEnter` 只调用 `TakeDamage(..., fd: fd)`。`SpellType`（`miracle` / `pyromancy` / `sorvery`）在结算里不读。现有弹体资产只有火球（`spellType` 为火焰），这一发碰巧进火段；同一套代码没有魔法、雷电、暗的入口。

为何算大：需求要的是打中之后走哪一段吸收，代码把所有投射都送进火段。换一条非火焰的投射法术，仍然按火吸收扣血。盾格挡不走近战那条结算，是直接 `TakeDamage` 的已知现状，不另列一条。

### FR-装备-02 选中护甲槽再点武器，武器离开背包但不戴上

要的结果：在背包里把近战武器装备到右手或左手。那只手出现该武器模型，接下来这只手的命中用这把武器的伤害。换成另一把后，手上换成新的模型。

代码实际：`InventorySlotUI.EquipWeapon` 只在 `selectedSlotType` 是左右手前两个槽时，才把武器写进对应下标。四个分支都不进时，后面的 `RemoveItem(weapon)` 仍然执行，然后按当前下标重载左右手。装备窗点过头、躯干或下身之后，`selectedSlotType` 是护甲槽。这时再点背包里的武器，武器从 `items` / `weapons` 里消失，不进任何手槽，手上模型仍是原来那把。

为何算大：装备是已经在跑的操作。这一下的结果不是换上新武器，而是背包里少一件、手上不动。

## 查过，没有大出入

拿错催化器不出弹，代码已经是这样，不记偏离。护符资产挂的是奇迹动作，火焰催化器挂的是火焰动作。`MagicSpellAction` 在 `currentSpell.spellType` 和这一下动作的学派不一致时直接返回，不调用 `AttemptToCastSpell`，没有弹体。火球是火焰，治疗是奇迹，对调催化器放不出去。没有法杖资产，也没有魔法弹体资产；这是还没做的内容，不是已经在跑却放错弹。
