# 0.16 技术设计：付不清的格挡会破防

> **破防仍在 `AttemptBlock`。付不清只把这一下的精力写成 0，再走现有的耗尽分支。不改 `DeductStamina` 的成败规则。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`AttemptBlock` 算出 `staminaDA` 后调用 `DeductStamina`。`CharacterStatsManager.DeductStamina` 在 `currentStamina < deductAmount` 时返回 false，数值不变。返回后只有 `currentStamina <= 0` 才清格挡、`ResetBlockingAbsorption`、播 `"Guard_Break"`。

`ResolveIncomingHit` 在 `AttemptBlock` 之后按当时的格挡吸收减伤，再 `TakeDamage`。`playHurtSound` 在 `currentStamina <= 0` 时为 true。正好扣到 0 时，吸收已先被清成 0，这一击按没挡住扣血。

`PlayerStatsManager.DeductStamina` 只在基类返回 true 时刷新体力条。

## 2. 付不清

`CharacterStatsManager` 增加 `EmptyStamina`：把 `currentStamina` 写成 0。`PlayerStatsManager` 覆写它，写成 0 之后 `staminaBar.SetCurrentStamina`。敌人不覆写。

`AttemptBlock` 在 `DeductStamina` 返回 false 时调用 `EmptyStamina`，然后仍用现在的 `currentStamina <= 0` 分支破防。返回 true 时不调用 `EmptyStamina`。

不改 `DeductStamina`。不改 `ResolveIncomingHit` 里减伤和 `playHurtSound` 的顺序。

## 3. 不做

不改点积，那是 0.17。不改翻滚、跳跃、后撤、冲刺对 `DeductStamina` 的调用。不把 `WeaponItem.guardBreakM` 或 `stability` 接进消耗。不补单元测试。
