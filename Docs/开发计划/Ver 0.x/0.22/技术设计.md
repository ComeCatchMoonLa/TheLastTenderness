# 0.22 技术设计：只留以后自己写的测试

> **删掉 VRM 自带的测试目录。不新建测试程序集，不写玩法用例。规则写进可测试性。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。这些目录在 `.gitignore` 的 `Assets/Art/0 Resources/Models/` 下，删除不进 git。

## 1. 现在有的测试

`Assets/Scripts` 没有测试。磁盘上有四份别人写的测试目录，各带 `*.Tests.asmdef`：

| 目录 |
| --- |
| `Assets/Art/0 Resources/Models/Alice Chan/VRM Consortium/UniGLTF/Tests` |
| `Assets/Art/0 Resources/Models/Alice Chan/VRM Consortium/VRM/Tests` |
| `Assets/Art/0 Resources/Models/Alice Chan/VRM Consortium/VRMShaders/GLTF/IO/Tests` |
| `Assets/Art/0 Resources/Models/Alice Chan/VRM Consortium/VRMShaders/VRM10/MToon10/Tests` |

`UniGLTF/Tests` 里面还有 `UniHumanoid` 的测试。工程根上有六个 `*Tests.csproj`，由这些 asmdef 生成，`.gitignore` 忽略 `*.csproj`。

## 2. 删掉

只删上面四个目录和它们旁边的 `.meta`。不删 `VRM Consortium` 里测试目录以外的脚本和模型。

六个 `*Tests.csproj` 一并删掉。asmdef 没了之后，Unity 不应再生成它们。

## 3. 规则

改 `Docs/代码分析/可测试性.md`：

- 历史脚本这一版不补用例，也不为它们新建测试程序集。
- 下一版起，改了可观察行为的版本，只给这次改动写测试。程序集跟第一批这种测试一起出现。
- 断言用现有返回值和公开字段。粒子、镜头、动画曲线仍靠人看。

不把 `com.unity.test-framework` 写进 `Packages/manifest.json`。它仍由开发功能包带入。

## 4. 不做

不给 0.16–0.21 或更早的脚本补测试。不改玩法。不删 VRM 运行时。
