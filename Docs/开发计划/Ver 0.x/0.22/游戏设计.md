# 0.22 游戏设计：只留以后自己写的测试

> **交付目标：工程里不再跑别人带来的单元测试。历史玩法脚本这一版不补测试。以后只给该版改动里、Edit Mode 直接能断言的行为写测试。**
>
> 不改战斗、物品和镜头。不给 `Assets/Scripts` 里已有的脚本补用例。

## 1. 为什么是这一刀

`Assets/Scripts` 里没有测试。工程里能跑的测试来自导入的 VRM 模型包，测的是模型导入，不是这个游戏。不过滤程序集时，编辑器测试的退出码来自那些测试。

## 2. 谁负责

这一版删掉那些测试目录，并在 `Docs/代码分析/可测试性.md` 写下以后的规则。

规则是：0.x 不写单元测试。1.x 只给该版改动写测试，而且只写 Edit Mode 里不用 `Awake` 私有引用、也不用已初始化 Animator 就能断言的。方法里本来就会打的 Error，用 `LogAssert.Expect` 接住。断言读已经公开的返回值和字段。不看粒子、镜头和动画曲线。不另起一套战斗框架，不为了测试把方法改成 `virtual`，也不为了测试进入 Play Mode。历史的 0.x 脚本不回头补测试。

按这条留下的用例：1.2 瞄准半径，1.3 缺模型不换掉已有模型。1.0 的 `ResolveIncomingHit`、1.1 的 `MeleeAttackSegment` 先不写。

## 3. 验收

- 下面四份测试目录不在磁盘上。本机没有 `Alice Chan` 整夹，VRM 运行时代码也不在这台磁盘上。
- `Assets/Scripts` 里仍然没有 `[Test]` 或 `[UnityTest]`。
- `可测试性.md` 写明：历史脚本不补；以后只补 Edit Mode 里直接能断言的用例。1.0、1.1 先不写。
