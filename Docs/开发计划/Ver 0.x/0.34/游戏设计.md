# 0.34 游戏设计：血瓶次数在这名玩家身上

> **交付目标：喝药扣的是这名玩家这一局的剩余次数，不改物品资产上的 `currentItemAmount`。**
>
> 技术设计已写。不把资产上已经写下的 82 接进运行时。0.x 不写单元测试。

## 1. 为什么是这一刀

`TrySpendConsumable` 已经把剩余次数放在玩家的 `consumableLeft` 里，第一次从 `maxItemAmount` 记入。`currentItemAmount` 只出现在 `ConsumableItem` 的字段声明上，脚本不读也不写。血瓶资产上这个字段是 82，上限是 99。运行时从 99 起算。

这一版把这条边界写死，避免以后再从资产上的 82 起算，或喝药时把资产改掉。

## 2. 做完之后

喝药和扔炸弹仍走 `TrySpendConsumable`。次数不够仍耸肩或不能扔。重新进入播放后，次数从 `maxItemAmount` 重新记起，不继承资产上的 `currentItemAmount`。

## 3. 验收

喝一次血瓶，次数比这一局开始时少 1。退出播放再进，资产上的 `currentItemAmount` 仍是进播放之前的值。不写 Edit Mode 测试。
