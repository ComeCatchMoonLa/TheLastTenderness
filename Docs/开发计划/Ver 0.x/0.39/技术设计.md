# 0.39 技术设计：开局报出没配的武器动作

> **`WeaponItem` 增加一次必填动作检查。`CharacterInventoryManager.Start` 对左右手槽里已有的武器各调用一次。`LogWarning`，不中断。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。没有 **[待确认]** 的接口。

## 1. 检查放在武器上

[`WeaponItem`](../../../../Assets/Scripts/Items/Equipment/Weapons/WeaponItem.cs) 增加 `WarnIfActionsMissing`。

- `bow`：`oh_tap_e_action`、`oh_hold_q_action` 为空就警告。现有 `Bow.asset` 把射击放在前一个、瞄准放在后一个。
- `melee_OH_Shield`、`pyromancyCaster`、`faithCaster`、`spellCaster`：直接返回。
- 其余类型（含 `unarmed`）：`oh_tap_e_action`、`oh_hold_e_action` 为空就警告。

警告文案是资产名、字段名和「未填」，例如 `Unaremd: oh_tap_e_action 未填`。用 `LogWarning`。

## 2. 谁调用

[`CharacterInventoryManager.Start`](../../../../Assets/Scripts/Character/CharacterInventoryManager.cs) 在取出当前左右手并装上武器之后，对 `weaponsInLeftHandSlot` 和 `weaponsInRightHandSlot` 里非空的每一件调用。玩家和敌人都走这个 `Start`。槽是空的不叫。同一件武器挂在两个槽上会各警告一次。

## 3. 不做

不改 `PlayerCombatManager` 的空引用返回。不删 `ItemBasedAttackAction` 出手时已有的警告。不扫资源库。不给 `Unaremd` 填动作。不查挥刀音、双手槽、护甲、消耗品、法术。0.x 不写单元测试。不算高风险。

## 4. 验收

游戏设计第 3 节，点 Play 看 Console。
