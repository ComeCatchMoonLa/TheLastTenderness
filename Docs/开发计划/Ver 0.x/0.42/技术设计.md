# 0.42 技术设计：消耗品开局次数用 Current Item Amount

> **`RememberConsumable` 的初始剩余改成 `currentItemAmount`，并用 `maxItemAmount` 封顶。不写回资产。休息仍写回上限。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。没有 **[待确认]** 的接口。

## 1. 初始剩余

[`PlayerInventoryManager.RememberConsumable`](../../../../Assets/Scripts/Character/Player/PlayerInventoryManager.cs) 现在把 `consumableLeft` 写成 `item.maxItemAmount`。

改成：

- `currentItemAmount < 0` 时用 0。
- `maxItemAmount > 0` 且 `currentItemAmount > maxItemAmount` 时用 `maxItemAmount`。
- 其余用 `currentItemAmount`。

已经记进 `consumableLeft` 的不再重算。`TrySpendConsumable` 仍是剩余大于 0 才减 1 并返回 true。

`RefillConsumablesToMax` 仍把已有的每一件写成 `maxItemAmount`。不改 `estusLeft`、`ashLeft`。不改 `ConsumableItem.currentItemAmount`。

## 2. 已有测试

下面三份只填了上限、没填当前次数。当前次数默认是 0，改完会从 0 起算，和原来的断言对不上。各把 `currentItemAmount` 设成这份测试已经在断言的那个开局数。不新写测试文件。

- `Assets/Tests/EditMode/Consumable/ConsumableRemainingTests.cs`
- `Assets/Tests/EditMode/Consumable/QuickSlotConsumableCountTests.cs`
- `Assets/Tests/EditMode/Consumable/RestRefillConsumableTests.cs`

## 3. 不做

不把次数写到磁盘。不改血瓶和灰瓶那一行的数字来源。不把当前次数为 0 当成「改用上限」。不算高风险。

## 4. 验收

游戏设计第 3 节。改数量要退出 Play 再进，进游戏之后再改资产不会重算已经记下的剩余。
