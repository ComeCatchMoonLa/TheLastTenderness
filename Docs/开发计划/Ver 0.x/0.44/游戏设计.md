# 0.44 游戏设计：电梯旁能拉到

> **交付目标：站在 `Game` 里这块电梯上，出现「拉动」。按交互，平台从脚下竖直升降，人跟着上下，走路仍能控制，不抖，也不飞到场景另一头。再按一次回到刚才的高度。**
>
> 0.x 不写单元测试。1.58 的施工文档还在，这一版插在它前面。

来源：[FR-机关-04](../../../需求文档/功能需求/场景机关.md)。拉一次到另一层，再拉一次回到刚才离开的方向。

## 1. 为什么是这一刀

靠近检测只找第 7 层、标签是 `Interactable` 的碰撞体。这块平台在第 8 层，标签不是 `Interactable`，所以没有提示，按交互也没有反应。

`home` 是 `(0, 0, 0)`、`away` 是 `(0, 5, 0)` 时，拉动把平台的本地坐标直接写成 `away`。平台实际不在原点，所以整块连人一起飞到父物体旁边。

## 2. 做完之后

平台仍在第 8 层，站在上面仍算站在地上。运行时在平台上加一块第 7 层、标签 `Interactable` 的触发体，提示用平台上的 `interactTipText`。

平台当前的本地坐标既不是 `home` 也不是 `away` 时，两层改成从当前位置出发，高度差仍是 `away - home`。`home` 是 `(0, 0, 0)`、`away` 是 `(0, 5, 0)` 时，第一次从脚下往上升 5，第二次回到拉动前的高度。已经停在某一层上时不改这两层。

上升和下降是匀速的，不是一帧跳过去。人站在平台占地里时，只把人的高度加上平台这一帧的升降，水平速度仍由原来的走路写。人走下平台后不再被带着走。休息不改它停在哪。

## 3. 验收

0.x 不新写 Edit Mode 测试。在 `Game` 里：

1. 站上电梯，出现「拉动」。
2. 按和开门一样的交互键：平台从脚下竖直上升，人跟着上升，摇杆仍能在平台上走，不抖，也不飞到场景另一头。
3. 再按一次：平台和站在上面的人一起回到刚才的高度。
4. 休息一次：平台仍停在按完之后的那一层。
