# 0.48 技术设计：追击时人会走过去

> **追击和回家用导航的 `desiredVelocity` 写水平速度。根运动只在 `isInteracting` 时写。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。没有 **[待确认]** 的接口。

## 1. 谁推位置

[`PursueTargetState.WalkToward`](../../../../Assets/Scripts/Character/NPC/State/General%20A.I/PursueTargetState.cs) 现在先记下刚体速度，设上导航目标，再把速度写回去。追击和回家都走这里。

改成设上目标之后，用 `navmeshAgent.desiredVelocity` 的水平分量写刚体速度，竖直分量留着。不再写回设目标之前的速度。转向仍对着导航代理。

[`CombatStanceState`](../../../../Assets/Scripts/Character/NPC/State/General%20A.I/CombatStanceState.cs) 里同一段写回也改成 `desiredVelocity`。人形周旋不用这段。

[`EnemyAnimatorManager.WritesHorizontalRootVelocity`](../../../../Assets/Scripts/Character/NPC/EnemyAnimatorManager.cs) 只在 `isInteracting` 时返回真。基础层是 `Locomotion` 时不再写速度、不改阻尼。朝向仍只看 `isRotatingWithRootMotion`。

[`CombatStanceStateHumanoid`](../../../../Assets/Scripts/Character/NPC/State/Humanoid%20A.I/CombatStanceStateHumanoid.cs) 在不交互时把水平速度写成 0。交互中的根运动不在这里清。

[`构架设计.md`](../../../代码分析/构架设计.md) 里敌人根运动那一句改成：只在交互中写水平速度。

## 2. 已有测试

`Assets/Tests/EditMode/Enemy/EnemyRootMotionTests.cs`：交互中仍为真。不在交互、基础层是 `Locomotion` 时改为假。不新写测试文件。

不改发现、出手、回家距离。不改导航代理每帧拉回本地零点。不改玩家的 `OnAnimatorMove`。不算高风险。
