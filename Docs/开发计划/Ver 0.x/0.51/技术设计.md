# 0.51 技术设计：点在界面上不触发鼠标战斗键

> **来自鼠标、并且指针打在界面图形上的战斗键，不写入对应标记。键盘绑定照常写入。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。没有 **[待确认]** 的接口。

## 1. 判断

[`InputManager`](../../../../Assets/Scripts/Character/Player/InputManager.cs) 增加 `MousePressHitsUi`。设备不是鼠标时返回假。是鼠标时，用当前指针位置对 `EventSystem` 做一次 `RaycastAll`，有命中返回真。结果列表复用，不每次新分配。

下面四条的 `performed` 在 `MousePressHitsUi` 为真时直接返回，不把标记写成真：

- `RightWeaponLightAttackOrShootArrow` → `tap_e_Input`
- `CriticalAttack` → `hold_e_Input`
- `LeftWeaponLightAttack` → `tap_q_Input`
- `BlockOrAim` → `hold_q_Input`

`CriticalAttack` 和 `BlockOrAim` 的 `canceled` 仍把对应标记写成假。

## 2. 空手

[`CharacterWeaponSlotManager.LoadWeaponDamageCollider`](../../../../Assets/Scripts/Character/CharacterWeaponSlotManager.cs) 不再把 `WeaponType.unarmed` 提前返回。拳头模型和近战一样接上 `DamageCollider`。盾、弓、法杖仍提前返回，并把对应手的伤害体写成空。

[`DamageCollider`](../../../../Assets/Scripts/Damage/Damage%20Collider/DamageCollider.cs) 开关前，碰撞体已经没了就返回。[`CharacterAnimatorManager`](../../../../Assets/Scripts/Character/CharacterAnimatorManager.cs) 的开关在伤害体为空时不调用。

## 3. 不做

不改键盘绑定。不暂停。换成另一把时仍销毁旧模型。不新写测试。不算高风险。
