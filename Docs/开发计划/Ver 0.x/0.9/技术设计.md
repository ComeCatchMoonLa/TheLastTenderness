# 0.9 技术设计：战斗结算纠错

> **六处都改现有方法里的那一行或那一次调用。不新增加结算类型。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 破防动画名

`CharacterCombatManager.AttemptBlock` 在体力扣完时播放 `"Guard_Break_01"`。`Humanoid.controller` 的状态名是 `Guard_Break`。`PlayTargetAnimation` 会先把 `isInteracting` 写成 true。名字对不上时动画不切，人停在交互里。

把这一处字符串改成 `Guard_Break`。`EnemyStatsManager.BreakGuard` 播放 `"Break Guard"`，全库没有调用方。同一版把这处也改成 `Guard_Break`，避免以后接上时再用错名字。

不改 `PlayTargetAnimation` 的参数顺序。状态名不存在时不锁交互，是 0.10。

## 2. 背刺和处决

`GetBackStabbed` 和 `GetRiposte` 跑在受击者身上，取的是 `character.cInventory.rightWeapon`，也就是受击者自己的右手武器，然后立刻 `TakeDamage`。

`CriticalAttackAction.AttempBackStab` 和 `AttempRiposte` 另外把攻击者右手五段之和乘 `criticalAttackDM`，写入受击者的 `pendingCriticalDamage`。`CharacterAnimatorManager.ApplyPendingDamage` 再把它当成物理伤害扣一次。可搜索的 `.anim` 里没有这个函数名；事件若在导入片段上，就会第二次扣血。

改成：

- `GetBackStabbed` 用 `characterPerformingBackStab.cInventory.rightWeapon`。`GetRiposte` 用 `characterPerformingRiposte` 的右手武器。五段仍各乘该武器的 `criticalAttackDM`。动画名保持 `"Back Stabbed"` 和 `"Riposted"`。
- `CriticalAttackAction` 不再写入 `pendingCriticalDamage`。
- `ApplyPendingDamage` 在 `pendingCriticalDamage` 为 0 时直接返回，不调用 `TakeDamage`。

攻击者没有右手武器时，这两处不扣血。位置和朝向的协程不动。

## 3. 左手盾

两处把盾算到了右手：

- `PlayerCombatManager.Handle_Hold_Q_Input` 在左手是 `melee_OH_Shield` 时调用 `UpdateWhichHandCharacterIsUsing(usingRightHand: true)`。改成 `usingRightHand: false`。
- `CharacterCombatManager.SetBlockingAbsorptionFromBlockingWeapon` 的左手分支，五段吸收已经来自 `leftWeapon`，`blockingStabilityRating` 来自 `rightWeapon`。改成 `leftWeapon.blockingStabilityRating`。

`BlockAction` 仍把 `isInteracting` 传 false。按住 Q 松开时仍每帧清掉格挡，这一版不把按住 Q 收成只触发一次。

## 4. 按住 E 和点按 E

`InputManager` 里 `CriticalAttack.canceled` 已经把 `hold_e_Input` 写成 false。按住期间没有任何地方清掉它，所以每个 `Update` 都进入 `Handle_Hold_E_Input` 里的 `PerformAction`。

在读到 `hold_e_Input` 为 true 时立刻写成 false，再决定是否调用动作。和点按 E 一样，只消费一次。按住 Q 不这样清。

`Handle_Tap_E_Input` 先读 `leftWeapon.weaponType`，后判断 `leftWeapon != null`。改成先判断存在，再看是不是弓。不存在时走右手分支。

同一类里这些提前 return 也在判空之前读 `leftWeapon.weaponType`，一并先判断存在，不存在就不当成弓：

- `Handle_Hold_E_Input`
- `Handle_Tap_R_Input`
- `Handle_Tap_Q_Input`
- `Handle_Hold_Q_Input` 里双手且 `weaponType != bow` 的那一处
- `Handle_Tap_Z_Input`

不改按键顺序。不把玩家改去读 `th_*`。

## 5. 重击段号

`HeavyAttackAction.HandleHeavyAttackCombo` 在各分支播完动画之后，无条件 `attackType = heavy_2`。重播第一段时也是第二段系数。

照 `LightAttackAction.HandleLightAttackCombo`：播 `*HeavyAttack2` 的分支写 `heavy_2`，播 `*HeavyAttack1` 的分支写 `heavy_1`。`HandleHeavyAttack` 里已有的 `heavy_1` 不动。不把两个 Action 合成一个类。

## 6. 炸弹溅射

`BombDamageCollider.OnCollisionEnter` 对碰到的 `CharacterStatsManager` 调用 `TakeDamage`，然后 `Explode` 的 `OverlapSphere` 再对半径内每个人调用一次。

`Explode` 增加参数：这次已经直击过的 `CharacterStatsManager`。循环里同一个引用直接 `continue`。直击不是角色时传 null，溅射仍打半径内的其他人。

不给近战加「已经打过」的名单。不让炸弹进入 `DealDamage` 的格挡和韧性。

## 7. 不做

不改 `TakeDamage` 的护甲公式。不改下落和 `HandleEmptyState`。不改药瓶数量和护甲吸收字段。不新建结算函数。不补单元测试。
