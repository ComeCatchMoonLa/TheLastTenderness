# 1.11 游戏设计：查询助手收成一处

> **交付目标：锁定和两处待机共用一段「装满才加倍」的球形查询。半径、层和初始容量与现在相同。**
>
> 技术设计和 TODO 进入本版再写。不改伏击状态。伏击仍每次分配新数组，那是 0.30。

## 1. 为什么是这一刀

`PlayerCameraManager`、`IdleState`、`IdleStateHumanoid` 各写了一份 `CollectOverlaps`：`OverlapSphereNonAlloc`，结果个数等于数组长度就加倍再查。0.29 故意各写一份。

锁定用 `maxLockOnDist`、层遮罩 `~0`，数组从 32 起。两处待机用 `detectionRadius`、层 `LayerMask.player`，数组从 16 起。

## 2. 做完之后

三处调用同一段查询。半径、层、初始容量和装满才加倍不变。察觉、追击和锁到谁不因本版改变。

## 3. 验收

开锁定时仍能锁到范围内的人。人形待机仍能在视角里发现玩家。通用待机的脚本行为与改之前相同；当前构建场景的近战不挂这组状态。伏击状态仍每次 `OverlapSphere`。

Edit Mode 不测查询命中了哪些碰撞体，也不为了测试把查询改成 `virtual`。半径、层、初始容量和装满才加倍靠人看。
