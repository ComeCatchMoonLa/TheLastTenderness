# 1.19 技术设计：入伤结果留在可读字段上

> **结算结束前把挡住、破韧和五段合计写到公开字段。分支顺序不改。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`ResolveIncomingHit` 先把五段乘上 `multiplier`。`applyBlockAndPoise` 为假时直接 `TakeDamage` 并返回。否则在举盾且点积大于 0.3 时走 `AttemptBlock`，再按格挡吸收缩放五段。没挡住时先扣 `totalPoiseDefence`，再按剩余韧性是否仍大于这次的 `poiseDamage` 决定播不播受击动画。

这些结果都是局部变量。

## 2. 留下结果

在 `CharacterCombatManager` 上增加三个公开字段：`lastHitWasBlocked`、`lastHitBrokePoise`、`lastHitDamageTotal`。

每次即将调用 `TakeDamage` 之前写入：

- 不处理格挡和霸体：没挡住，没破韧，合计是乘完倍率的五段。
- 挡住：挡住为真，没破韧，合计是再乘完格挡吸收的五段。
- 没挡住：挡住为假。`totalPoiseDefence > poiseDamage` 时没破韧，否则破韧。合计是扣韧性之前的五段。

`if` 的条件和 `TakeDamage` 的参数不改。玩家和敌人不另写一套。

## 3. 单元测试

`Assets/Tests/EditMode/IncomingHitResultTests.cs`。

同一物体上放 `CharacterManager`、`CharacterStatsManager`、`CharacterCombatManager`、`CharacterSoundFXManager`。`cStats`、`cCombat`、`cSoundFX` 指回这些组件。两个私有 `character` 用反射写入。受伤音数组设成空，不创建 Animator。

- `applyBlockAndPoise` 为假，倍率 1，物理 10：`lastHitWasBlocked` 为假，`lastHitBrokePoise` 为假，`lastHitDamageTotal` 为 10，生命下降 10。
- `applyBlockAndPoise` 为真，不举盾，韧性 0，霸体伤害 5，物理 10：`lastHitWasBlocked` 为假，`lastHitBrokePoise` 为真，`lastHitDamageTotal` 为 10。

## 4. 不做

不改 0.3 的正面阈值。不改破防动画。不改 `isBlocking` 的写入点。
