# 1.27 技术设计：待结算处决伤害不再留第二段入口

> **删掉 `ApplyPendingDamage` 和 `pendingCriticalDamage`。处决仍只走 `ResolveIncomingHit`。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`CharacterCombatManager.pendingCriticalDamage` 是公开字段。全仓库没有给它赋值。`CharacterAnimatorManager.ApplyPendingDamage` 在它不为 0 时，用这个数再 `TakeDamage` 一次。动画资源里没有这个事件名。

`GetBackStabbed` 和 `GetRiposte` 各自调用一次 `ResolveIncomingHit`，`applyBlockAndPoise` 为假。

## 2. 收掉

删掉 `ApplyPendingDamage` 方法。删掉 `pendingCriticalDamage` 字段。`GetBackStabbed` 和 `GetRiposte` 不改。

## 3. 单元测试

`Assets/Tests/EditMode/PendingCriticalDamageRemovalTests.cs`。

反射断言 `CharacterAnimatorManager` 上没有 `ApplyPendingDamage`，`CharacterCombatManager` 上没有 `pendingCriticalDamage`。不创建角色，不调用处决，不创建 Animator。

## 4. 不做

不改背刺和弹反的位移。不改 `criticalAttackDM`。
