# 1.28 技术设计：设置窗口按档位拆开

> **四档的表在同目录的四个静态类型里。按钮和套用仍在 `SettingsWindowManager`。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`FrameRateLimitLabel`、`FrameRateLimitValue`、`NextFrameRateLimit`、`PreviousFrameRateLimit`，以及画质、后处理、特效的同类方法，都是 `SettingsWindowManager` 的公开静态方法。套用方法读这些结果，写入序列化的文本，并设置 `Application.targetFrameRate` 或 `QualitySettings.SetQualityLevel`。后处理和特效没有上一档。按钮方法是 `FrameRateLimit_SetNextOption`、`FrameRateLimit_SetPreviousOption`、`DisplayQuality_SetNextOption`、`DisplayQuality_SetPreviousOption`、`PostTreatmentQuality_SwitchOption`、`SpecialEffectQuality_SwitchOption`。

## 2. 拆出

同目录增加四个静态类，不继承 `MonoBehaviour`：

- `FrameRateLimitTable`：`Label`、`Value`、`Next`、`Previous`
- `DisplayQualityTable`：`Label`、`Level`、`Next`、`Previous`
- `PostTreatmentQualityTable`：`Label`、`Next`
- `SpecialEffectQualityTable`：`Label`、`Next`

返回值与现在的 `switch` 相同。`SettingsWindowManager` 删掉原来的公开静态方法，套用和按钮改为调用这四个类。按钮方法名不改。垂直同步的方法留在设置窗。

## 3. 单元测试

`Assets/Tests/EditMode/SettingsTierTableTests.cs`。

帧率四档的文案是 60、90、120、无限制，数值是 60、90、120、-1。`max120` 的下一档是 `unlimited`，`unlimited` 的上一档是 `max120`。画质 `veryLow` 的文案是「非常低」、等级是 0，`Ultra` 的文案是「最高」、等级是 5。后处理和特效的 `low` 文案是「低」，下一档是 `high`；`high` 的文案是「高」，下一档是 `low`。不创建 `SettingsWindowManager`，不加载预制体。

## 4. 不做

不改预制体。不把按钮方法搬到别的组件。不拆垂直同步。不改 `GameSettingsData`。
