# 1.29 技术设计：改掉已经写进预制体的三个字段

> **只改这三个字段的名字，并改写已经出现它们的预制体。枚举 `unaremd` 不动。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`CharacterManager.isPerformingBackSttbbed` 表示正在背刺。`CharacterInventoryManager.unaremd` 是空手武器。`WeaponFX.noramalWeaponTrial` 是挥刀拖尾。`WeaponType.unaremd` 是枚举，不在这一版。

除计划里点名的近战预制体和四把武器外，`Player.prefab` 和 `Default Story NPC.prefab` 也写了前两个字段。不改它们的话，玩家身上的空手武器引用会丢。

## 2. 改名

C# 和上述预制体里：

- `isPerformingBackSttbbed` 改为 `isPerformingBackStabbed`
- 字段 `unaremd` 改为 `unarmed`。`WeaponType.unaremd` 不改
- `noramalWeaponTrial` 改为 `normalWeaponTrail`

预制体只替换字段名，数值和 fileID 不改。

## 3. 单元测试

`Assets/Tests/EditMode/SerializedFieldRenameTests.cs`。

反射断言 `CharacterManager`、`CharacterInventoryManager`、`WeaponFX` 上有新字段、没有旧字段。`WeaponType` 仍有 `unaremd`。

读游戏设计第 3 节列出的预制体文本，断言新字段名和原来的 fileID 还在。不创建角色，不进播放。

不改目录 `Perfabs`。不改 `InputAcitons`、`DestoryAuto`、`CharacterInvontoryManager.cs` 的文件名。不改枚举 `unaremd`、`sorvery`、`nearset`、`armor_Toros_Slot`。不改 `SucessfullyGetArrow`、`SucessfullyUsedConsumable`、`instantialtedFXModel`。
