# 1.44 游戏设计：攻击和周旋收成一套

> **交付目标：选招计分只写一处。人形仍把选中的 `ItemBasedAttackAction` 交出去，Boss 转阶段后仍读自己的第二阶段列表。发现、追击、出手的可见结果不变。**

## 1. 为什么是这一刀

1.41 把待机、追击、转向收进 General。攻击和周旋仍各写一份 `Tick`、一份 `GetNewAttack`。三份计分（人形列表、General 列表、Boss 第二阶段列表）是同一套加总再随机，写了三遍。

两种出手不能收成一个字段。人形走 `ItemBasedAttackAction`，General 和 Boss 走 `EnemyAttackAction`。并成一个字段会改掉其中一种出手。攻击时的转向也不是同一个数：General 用 `rotationSpeed / Time.deltaTime`，人形用 `rotationSpeed * Time.deltaTime`。连击一个换成 `comboAction`，一个再调一次 `PerformAttackAction`。

## 2. 做完之后

计分循环只留在 `AttackScore.PickIndex`。三处 `GetNewAttack` 都调用它，各自传入现在用的距离、角度和列表。

人形周旋仍挂 `CombatStanceStateHumanoid`，人形出手仍挂 `AttackStateHumanoid`。`GetComponent` 仍按现在的具体类型找。Boss 的 `sencondPhaseAttacks` 仍在 `BossCombatStanceState` 上。`AmbushState` 仍在。

人形近战仍会发现、追到攻击距离后周旋，冷却结束仍按现在的列表出手。格挡、闪避、弹反、弓，以及 General 的导航转向，仍留在原来的 `Tick` 里。

## 3. 验收

Edit Mode：给定同一组窗口和同一个随机数，三处都停在第一次超过该数的那下。已经有招时，General 和 Boss 返回不改；人形仍可以换成这一下。三种列表的字段类型仍分开。不创建导航网格，不播动画。
