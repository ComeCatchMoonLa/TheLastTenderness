# 1.47 技术设计：入伤结算的五段和倍率收成一组参数

> **只把 `ResolveIncomingHit` 的倍率和五段收成 `IncomingDamage`。不改 `TakeDamage` 的护甲公式，不改 `AttemptBlock` 的参数列表。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`ResolveIncomingHit` 的参数是攻击者、动画名、`multiplier`、是否走格挡和韧性、韧性伤害、破防系数、五段 `float`。方法开头把五段各乘倍率。不走格挡和韧性时直接 `TakeDamage`。挡住时先 `AttemptBlock`，再按格挡吸收减五段。没挡住时扣韧性，够则无受击动画，不够则把动画名传给 `TakeDamage`。

调用在 `DamageCollider.DealDamage`、`GetBackStabbed`、`GetRiposte`，以及 `IncomingHitResultTests`。

## 2. 改法

`IncomingDamage` 放在 `DamageSegments.cs`。字段是 `Multiplier` 和 `Segments`。

`ResolveIncomingHit` 改为 `ResolveIncomingHit(CharacterManager attacker, string damageAnimation, IncomingDamage incoming, bool applyBlockAndPoise, float poiseDamage, float guardBreakModifider)`。

方法里先把 `incoming.Segments` 的五段各乘 `incoming.Multiplier`，后面的格挡、韧性和 `TakeDamage` 仍用乘完的数。`AttemptBlock` 仍接收五个 `float`。

`DealDamage` 的参数列表不改，调用处装进 `IncomingDamage`。背刺和反击用武器的 `criticalAttackDM` 当倍率，五段用武器上的数。

## 3. 单元测试

改 `Assets/Tests/EditMode/IncomingHitResultTests.cs` 的两处调用。不走格挡和韧性时，伤害合计是 10，血少 10，两次旗标都是假。韧性为 0 且这次走韧性时，破韧为真，格挡为假，合计仍是 10。

再断言倍率 2、物理 10、不走格挡和韧性时，合计是 20，血少 20。不创建相机。

## 4. 不做

不改 `CombinedArmorRate`。不改 `AttemptBlock` 的参数列表。不改破防动画名 `"Guard_Break"`。不改 `PlayTargetAnimation` 和 `MeleeAttackSegment.Play`。
