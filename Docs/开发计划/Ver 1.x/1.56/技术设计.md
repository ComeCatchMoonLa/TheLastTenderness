# 1.56 技术设计：攻击中朝向只写一处

> **只把攻击中朝向目标收成 `AttackFacing`。插值系数仍由两个攻击状态各自传入。不合并两套 `Tick`。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`AttackState.RotateTowardsTargrtWhilstAttacking` 和 `AttackStateHumanoid` 里的同名方法，都是：`canRotate` 且 `isInteracting` 时，`targetDir` 为零就写成 `transform.forward`，再 `Slerp`。系数分别是 `rotationSpeed / Time.deltaTime` 和 `rotationSpeed * Time.deltaTime`。

周旋的 `HandleRotateTowardsTarget` 条件不同：General 看 `isPreformingAction`，否则跟导航网格；人形周旋不看 `canRotate`。这两处不收。

## 2. 改法

`AttackFacing.Apply(Transform body, ref Vector3 targetDir, bool canRotate, bool isInteracting, float slerpFactor)`。条件不满足就返回。方向为零时写成 `body.forward`。然后把 `body.rotation` 写成朝该方向的 `Slerp`。

两个攻击状态改成调用它，并传入原来的系数。`Awake` 里的 `GetComponent` 不改。

[`可维护性与性能.md`](../../../代码分析/可维护性与性能.md) 里「一种近战 AI 行为」和「AI」两句改成：攻击中朝向在 `AttackFacing`，系数仍由调用方传入；周旋仍是两套 `Tick`。

## 3. 单元测试

`Assets/Tests/EditMode/AttackFacingTests.cs`。

用临时物体断言：不能转或不在交互时朝向和方向不变；方向为零时变成前方；系数为 1 时转到给定方向。读两个攻击状态的源码，断言 General 仍是除法、人形仍是乘法。测完销毁临时物体。不从预制体加载敌人。

## 4. 不做

不合并攻击或周旋的 `Tick`。不改 `GetComponent` 的具体类型。不让人形周旋继承 `CombatStanceState`。不并两种出手字段。不删 `AmbushState`。不重做 `AttackScore.PickIndex`。不改 Boss 第二阶段列表。
