# 1.56 游戏设计：攻击中朝向只写一处

> **交付目标：General 和人形在攻击中朝向目标，不再各写一遍。朝向结果与现在相同。周旋的两套 `Tick` 不合并。**

## 1. 为什么是这一刀

1.44 已把选招计分收成 `AttackScore.PickIndex`。攻击和周旋的 `Tick` 仍各写一套。对照过两套正文：合进一个 `Tick` 会改掉这些结果。

- General 攻击不看 `enableAI`，人形攻击先看。人形另有弓，出仇恨时会关掉 `aimingMode`。
- 人形近战在未交互时才出手；General 出手不看这一条。连击判定一个用 `<=`，一个用 `<`，失败时清不清当前招也不一样。
- General 出手播 `actionAnimation`。人形出手走 `ItemBasedAttackAction.PerformAttackAction`。
- 周旋里，General 交互中先写入缓动再清掉；人形先清掉再返回。人形还有格挡、闪避、弹反，冷却中小于 `3f` 后退。General 周旋在非施法时用导航网格转向。
- 攻击中转向的插值，General 是 `rotationSpeed / Time.deltaTime`，人形是 `rotationSpeed * Time.deltaTime`。

两边相同的只有这一段：`canRotate` 且 `isInteracting` 时，`targetDir` 为零就改成自身前方，再按调用方给的系数 `Slerp`。

## 2. 做完之后

这段收到 `AttackFacing`。General 仍传入 `rotationSpeed / Time.deltaTime`。人形仍传入 `rotationSpeed * Time.deltaTime`。

`GetComponent` 的具体状态类型不变。`EnemyAttackAction` 和 `ItemBasedAttackAction` 不并。`BossCombatStanceState.sencondPhaseAttacks` 仍在。不删 `AmbushState`。人形周旋不改成继承 `CombatStanceState`。选招计分不重做。

## 3. 验收

Edit Mode：不能转或不在交互时，朝向和 `targetDir` 不变。方向为零时改成自身前方。系数为 1 时转到该方向。`AttackState` 仍用除法，`AttackStateHumanoid` 仍用乘法。不创建敌人。

要人看的一条：人形近战仍会发现、追、打。这一条不进 Test Runner。

状态挂在敌人预制体上。收尾前 reviewer 的结论是「通过」或「有保留通过」。
