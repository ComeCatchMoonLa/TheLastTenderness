# 1.7 游戏设计：帧率上限收成一处

> **交付目标：帧率上限的前进、后退、套用，共用一份档位。四档对应的上限与现在相同。**
>
> 技术设计已写。不改垂直同步、画质、后处理和特效质量。

## 1. 为什么是这一刀

`FrameRateLimit_SetNextOption`、`FrameRateLimit_SetPreviousOption`、`FrameRateLimit_ApplyCurrentOption` 各写了一份四档。文案和 `Application.targetFrameRate` 已经一致，没有画质那种前后用词不同。

## 2. 做完之后

前进和后退只改当前档，再交给套用。文案和 `targetFrameRate` 只写在套用里。

对应保持为：60、90、120、无限制（`-1`）。到顶再前进仍回到 60，到 60 再后退仍回到无限制。

## 3. 验收

四档各向前、向后点一次，上限与改之前相同。重新打开设置，文案仍是「60」「90」「120」「无限制」。垂直同步、画质、后处理、特效质量不重测成另一套。

Edit Mode 单元测试断言四档的文案和 `targetFrameRate` 用的数字，以及前进、后退的环绕。测试不调用 `Application.targetFrameRate`，避免改掉编辑器当前帧率。
