# 2.11 技术设计：状态页能读已有等级和灵魂

> **读数在 `StatusPageLines`。`StatusWinManager` 只把这段文字写进状态页。分页仍由 `TapWindowsManager` 切换。不改等级，不改灵魂。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`TapWindowsManager` 有装备、背包、技能、地图。技能按钮在 `UI.prefab` 上，文案是「技能」，`onClick` 是空的。`SelectSkillWin` 只加粗标题，不打开子窗口。

等级在 `CharacterStatsManager`。`soulCount` 在 `PlayerStatsManager`。没有体力和幸运字段。

## 2. 改法

`TapWinType` 末尾加 `status`。已有 `selectedWin: 0` 仍是装备。

`StatusPageLines.Format` 按这个顺序拼九行：生命、精力、专注、韧性、力量、敏捷、智力、信仰、灵魂。只读传入的九个整数。

`StatusWinManager` 放在 `Tab Windows` 下的新物体 `Status Window` 上，默认关掉。`Open` 用玩家的 `pStats` 调用 `Format`，写进页上的文本，再打开自己。`Close` 关掉自己。文本或玩家为空时打出物体名和字段，不写数字。

`SelectStatusWin` 先卸掉当前子窗口，再打开状态页，并把原技能按钮的标题加粗。离开这一页时标题改回普通、关掉状态页。`SelectSkillWin` 留着，预制体改成调用 `SelectStatusWin`。

`UI.prefab`：技能按钮文案改成「状态」，`onClick` 接到 `SelectStatusWin`。加上 `Status Window`，挂 `StatusWinManager` 和一段正文文本。不改装备、背包、地图按钮。

[`可测试性.md`](../../../代码分析/可测试性.md) 的用例名单加上 2.11 这一条。

## 3. 单元测试

`Assets/Tests/EditMode/StatusPageLinesTests.cs`。

断言九行文本和给定数字一致，并且没有「体力」「幸运」「加点」。读 `UI.prefab`，断言技能按钮文案是「状态」，并且调用 `SelectStatusWin`。不创建窗口。

## 4. 不做

不显示体力、幸运。不写灵魂等级、负重、攻击力、吸收、下一级所需灵魂。不提供加点。不改 `SelectSkillWin` 的方法名。不改地图按钮。
