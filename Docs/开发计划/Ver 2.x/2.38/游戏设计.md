# 2.38 游戏设计：需求不足时更慢，打中也更弱

> **交付目标：力量或敏捷低于武器需求时仍能挥。这一下比需求满足时更慢，打中的伤害更低。满足后回到较高的那一档。**

来源：[不引入美术开-不引入人工开-非高风险开-1个以上FR开-五小时内关.md](../../../版本候选池/不引入美术开-不引入人工开-非高风险开-1个以上FR开-五小时内关.md)。

## 1. 为什么是这一刀

前置已解锁。力量和敏捷需求已能读（2.37）。武器伤害和挥击已有。需求前置是无。[FR-属性-05](../../../需求文档/功能需求/属性与升级.md) 写伤害更低且仍能挥出。[FR-注入-06](../../../需求文档/功能需求/注入与强化.md) 写挥击更慢。下降的系数调研标了待核对，这一版不写死，由调用方传入。智力、信仰、幸运，以及双手力量怎么取整，本条不选。

## 2. 做完之后

没填的那一项需求不参与比较。填了的力量或敏捷有一项低于需求时，速度系数和伤害都按传入的系数变低。两项都满足，或都没填时，速度系数是 1，伤害不变。系数空着时打出资产名并停住，不给出一个更弱的数。

## 3. 验收

Edit Mode：需求 14、等级 10、系数 0.5 时速度是 0.5、伤害是原来的一半。等级 14 时速度是 1、伤害不变。系数空着时不变，并打出错误。不创建 Animator，不改挥击动画。

要人看的一条：挥击看起来更慢，打中的数字更低。这一条不进 Test Runner。
