# 2.5 技术设计：休息把回复次数写回上限

> **次数只由 `PlayerInventoryManager` 写回。`RestoreVitalsToMax` 在三条资源写成上限之后调用它。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`CampFireInteractable.Interact` 在 `hasBeenActived` 时调用 `player.pStats.RestoreVitalsToMax()`。该方法把生命、精力、专注写成上限并刷新 HUD。`consumableLeft` 不在这里改。

`RememberConsumable` 只在字典还没有这件物品时写入 `maxItemAmount`。`TrySpendConsumable` 负责减一。

## 2. 写回

`PlayerInventoryManager` 增加 `RefillConsumablesToMax`。字典里已有的每一件，剩余次数写成该物品的 `maxItemAmount`。不新增键。字典还没建时直接返回。

`RestoreVitalsToMax` 把三条资源写成上限之后、刷新 HUD 之前，若 `player.pInventory` 已接上，调用 `RefillConsumablesToMax`。篝火交互不改。

## 3. 单元测试

`Assets/Tests/EditMode/RestRefillConsumableTests.cs`。

同一物体上放玩家、属性、背包。三条条用带 `Slider` 的血条、精力条、专注条接上，避免刷新 HUD 时碰到空引用。不创建篝火，不创建 Animator。

一件 `FlaskItem` 的 `maxItemAmount` 为 3。`TrySpendConsumable` 两次后，`ConsumableRemaining` 为 1。调用 `RestoreVitalsToMax` 后为 3。

## 4. 不做

不改扣次。不把次数写回资产上的 `currentItemAmount`。不复活敌人。不改未点燃时的点火。
