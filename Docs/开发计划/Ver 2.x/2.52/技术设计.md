# 2.52 技术设计：呼救被打断则同伴不来

> **同组看发现。远处只看呼救有没有做完。硬直把还在进行的呼救打断。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

待机发现只给自己写下 `currentTarget`。没有呼救，也没有同组连锁。硬直是韧防被打穿后带受击动画的那一下。

## 2. 改法

`AllyCall.Enters`：同组时，已经发现才进入。不是同组时，只有呼救做完才进入。

`AllyCall.Begin`、`Interrupt`、`Finish` 改两个旗标。没在呼救时，打断和做完都不把「做完」写成真。

`EnemyManager` 上有 `instantGroup`、`distantAllies`、`isCalling`、`callFinished`。`BeginCall` 和 `FinishCall` 给动画事件调用。发现目标后 `WakeGroup` 只写同组里还没有目标的人。`Finish` 只写远处名单里还没有目标的人。

`EnemyStatsManager.TakeDamage` 在这一下带了受击动画时调用 `Interrupt`。名单是空时不写任何人。

## 3. 单元测试

`Assets/Tests/EditMode/Enemy/AllyCallTests.cs`。

同组发现就进入。远处做完才进入。打断后再做完不进入。不创建敌人。

## 4. 不做

不新做呼救动画。不改没有配进名单的发现和追击。不把同组的人改成等呼救。
