# 2.7 技术设计：快捷栏能看见回复剩余次数

> **次数文本在 `QuickSlotsUI`。数字只读 `PlayerInventoryManager.ConsumableRemaining`。`RefillConsumablesToMax` 仍把剩余写成 `maxItemAmount`。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`consumableLeft` 在 `PlayerInventoryManager`。`ConsumableRemaining` 能读，`TrySpendConsumable` 能减，`RefillConsumablesToMax` 能写回上限。`QuickSlotsUI` 只有四个 `Image`，`UpdateCurrentConsumableIcon` 只换图。灵魂数已经用 `TextMeshProUGUI` 写在 `SoulCountUI.SetSoulCountText`。

快捷栏挂在 `Assets/Perfabs/#/UI.prefab`。

## 2. 文本

`QuickSlotsUI` 增加 `TextMeshProUGUI consumableCountText`，以及 `SetConsumableCount(int remaining)`。文本写成这个整数。引用为空时 `Debug.LogError("consumableCountText == null")`，不写一个假数字。

刷新只走这三处：

- `UpdateCurrentConsumableIcon`：物品不为空时，写入 `ConsumableRemaining`。物品为 null 时按现在的写法返回，不改次数文本。
- `TrySpendConsumable`：扣成功，且扣的就是 `currentConsumable`，并且 `player.ui.hud.quickSlotsUI` 已接上时，再写一次剩余。
- `RefillConsumablesToMax`：字典写完之后，若 `currentConsumable` 不为空且快捷栏已接上，把文本写成写回后的剩余。

`player` 或快捷栏没接上时不调用，避免没有 HUD 的调用碰到空引用。写回仍然是 `consumableLeft[item] = item.maxItemAmount`，不改这个赋值。

`Assets/Perfabs/#/UI.prefab` 的消耗品格上加一个 `TextMeshProUGUI`，接到 `consumableCountText`。不新做贴图，不改另外三个图标的引用。

## 3. 单元测试

`Assets/Tests/EditMode/QuickSlotConsumableCountTests.cs`。

同一物体上放玩家和 `PlayerInventoryManager`。快捷栏上接一个 `TextMeshProUGUI`。一件 `FlaskItem` 的 `maxItemAmount` 为 3，并设成 `currentConsumable`。

扣一次，文本是 `2`。再扣到剩余为 0，文本是 `0`。调用 `RefillConsumablesToMax` 后文本是 `3`。不创建篝火，不创建 Animator，不调用 `RestoreVitalsToMax`。

## 4. 不做

不改扣次条件。不改休息写回的上限。不显示法术或武器的次数。不改 `AmmoRemaining`。
