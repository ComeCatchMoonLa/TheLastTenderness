# 2.8 技术设计：瓶碎片加总次数，骨片按表加一口

> **总次数、血瓶口数、灰瓶口数和骨片档在 `PlayerInventoryManager`。每一口的回复只读 `FlaskRecoveryTable`。不改共享 `FlaskItem` 上的回复字段，也不写 `consumableLeft`。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。表与 [`角色与养成.md`](../../../调研文档/角色与养成.md) 的药瓶一致。

## 1. 现在

`FlaskItem` 上的 `healthRecoverAmount` 和 `focusPointsRecoverAmount` 是资产字段。`SucessfullyUsedConsumable` 用这两个数调用 `AddHP` / `AddMP`。`flaskType` 已有 `estus` 和 `ashen`。字典里的剩余次数仍是 `consumableLeft`，上限仍是 `maxItemAmount`。

没有总次数，没有骨片档，没有灰瓶口数。

## 2. 玩家身上的数

`PlayerInventoryManager` 增加这四个字段，初值如下：

| 字段 | 初值 |
| --- | --- |
| `flaskTotal` | 3 |
| `estusShare` | 3 |
| `ashShare` | 0 |
| `boneTier` | 0 |

`ObtainAshFlask`：`ashShare` 已经大于 0 时直接返回。否则在 `flaskTotal` 小于 15 时，`flaskTotal` 加一，`ashShare` 写成 1。开局调用一次得到总次数 4、血瓶 3、灰瓶 1。

`AddFlaskShard`：`flaskTotal` 小于 15 时加一，否则不变。不改 `estusShare`、`ashShare`，不写 `consumableLeft`。

`AddBoneShard`：`boneTier` 小于 10 时加一，否则不变。

三个方法都不读瓶子资产。

## 3. 回复表

新类型 `FlaskRecoveryTable`，放在 `Assets/Scripts/Items/Consumables/FlaskRecoveryTable.cs`。资产放在 `Assets/Data/Items/Consumables/Flask Recovery Table.asset`。`PlayerInventoryManager` 用一个字段引用它。

表是长度 11 的行，下标就是骨片档。每一行两个整数：`health`、`focus`。资产按这张表填，代码里不写这些数：

| 档 | health | focus |
| --- | --- | --- |
| 0 | 250 | 80 |
| 1 | 335 | 95 |
| 2 | 410 | 110 |
| 3 | 470 | 125 |
| 4 | 515 | 140 |
| 5 | 535 | 150 |
| 6 | 550 | 160 |
| 7 | 565 | 170 |
| 8 | 580 | 180 |
| 9 | 590 | 190 |
| 10 | 600 | 200 |

`TryGetFlaskSip(FlaskType flaskType, out int amount)`：表引用为空、行数不是 11，或当前档那一格的 `health` 或 `focus` 小于等于 0 时，`Debug.LogError` 带上资产名和字段（没接上引用时带上 `PlayerInventoryManager` 的字段名），返回 false，`amount` 为 0。通过时，`estus` 取出 `health`，`ashen` 取出 `focus`。

`FlaskItem.SucessfullyUsedConsumable` 改为先调用 `TryGetFlaskSip`。返回 false 时不调用 `AddHP` / `AddMP`。返回 true 时用取出的数，不再读 `healthRecoverAmount` 和 `focusPointsRecoverAmount`。粒子和模型仍按现在的写法生成。

## 4. 单元测试

`Assets/Tests/EditMode/FlaskChargeTests.cs`。

开局 `flaskTotal`、`estusShare`、`ashShare` 是 3、3、0。`ObtainAshFlask` 一次后是 4、3、1，再调用一次不变。不拿到灰瓶时连续 `AddFlaskShard`，总次数到 15 后不再增加。`AddBoneShard` 到 10 后不再增加。

内存里建一张表，0 档写成 250 和 80，10 档写成 600 和 200，其余档写成大于 0 的数。`boneTier` 为 0 时血瓶读出 250、灰瓶读出 80；档为 10 时读出 600 和 200。同一件 `FlaskItem` 的 `healthRecoverAmount` 写成 1 时，读出的仍是表上的数。

表引用为空时 `TryGetFlaskSip` 返回 false，并用 `LogAssert.Expect` 接住带字段名的错误。

这些测试不调用 `ConsumableRemaining`，不调用 `RefillConsumablesToMax`。

## 5. 不做

不写铁匠划分血瓶和灰瓶。不新做灰瓶模型，不新做瓶子预制体。不把总次数写进 `FlaskItem`。不在交片或烧骨片时改 `consumableLeft`。新的一口何时进入当前剩余，不在这一版。
