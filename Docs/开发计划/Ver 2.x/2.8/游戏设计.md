# 2.8 游戏设计：瓶碎片加总次数，骨片按表加一口

> **交付目标：瓶碎片提高血瓶加灰瓶的总次数，最多十五口。未死人骨片按表提高每一口的固定回复，最多十档。**

来源：[不引入美术开-不引入过多人工开-非高风险关-质量大于2关-完整度约1开-五小时内开或关.md](../../../版本候选池/不引入美术开-不引入过多人工开-非高风险关-质量大于2关-完整度约1开-五小时内开或关.md)。

## 1. 为什么是这一刀

喝药和剩余次数已经在这名玩家的字典里。总次数还不会因为瓶碎片变多，每一口回复还停在瓶子资产上的固定数。需求是 [FR-篝火-06](../../../需求文档/功能需求/篝火菜单.md) 和 [FR-篝火-07](../../../需求文档/功能需求/篝火菜单.md)。每一档的数字在 [角色与养成](../../../调研文档/角色与养成.md) 的药瓶表。

## 2. 做完之后

总次数和骨片档写在这名玩家身上。开局总次数 3，都在血瓶，灰瓶是 0。拿到灰瓶只发生一次：总次数变成 4，其中 1 口在灰瓶，血瓶仍是 3。每交一片瓶碎片，总次数加一，到 15 为止，再交不变。

骨片档从 0 到 10。喝成功时这一口的回复读策划资产上的表，不读瓶子资产上的回复字段，也不改那份共享资产。0 档是 250 点生命和 80 点蓝，第十档是 600 和 200。再烧一片，档位停在 10。

不写铁匠处把总次数划给血瓶或灰瓶的菜单。不新做瓶子模型。

交完新的一口是马上进当前剩余，还是下次休息才进，仍见 [未入池](../../../版本候选池/未入池.md)。这一版不写这个结果。

## 3. 验收

Edit Mode：开局总次数 3、血瓶 3、灰瓶 0。拿到灰瓶后是 4、3、1，再拿一次不变。从开局连续交瓶碎片，总次数到 15 后不再增加。骨片档到 10 后不再增加。

表按调研填好时，0 档读出 250 和 80，第十档读出 600 和 200。瓶子资产上的回复字段改成别的数，读出的仍是表上的数。表没接上、行数不是 11，或某一格小于等于 0 时，进入读取前报出资产名和字段，不给出回复。

不调用 `ConsumableRemaining` 来证明交片当次或下一次休息的剩余次数。
