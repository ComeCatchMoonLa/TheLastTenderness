# 2.9 技术设计：智力或信仰不够时法术放不出

> **属性门槛在 `SpellItem` 上。`MagicSpellAction` 在看蓝之前先看门槛。不够就耸肩，不调用 `AttemptToCastSpell`。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。

## 1. 现在

`SorcerySpellAction`、`PyromancySpellAction`、`MiracleSpellAction` 都调用 `PerformSpellAction`。学派对上之后，蓝够就 `AttemptToCastSpell`，不够就播放 `Shrug`。智力和信仰不参与。

`intelligenceLevel` 和 `faithLevel` 在 `CharacterStatsManager`。

## 2. 门槛

`SpellItem` 增加 `requiredIntelligence` 和 `requiredFaith`，初值都是 0。0 表示不看这项。

`MagicSpellAction` 增加公开静态方法 `AttributesAllowCast(SpellItem spell, int intelligence, int faith)`。法术为 null 时返回 false。要求大于 0 且等级更低时返回 false。两项都通过时返回 true。

`PerformSpellAction` 在学派对上之后、比较蓝之前调用它。返回 false 时播放 `Shrug` 并返回，不调用 `AttemptToCastSpell`，不改 `currentMP`。返回 true 之后，蓝不够仍是现在的耸肩，蓝够仍进入施放。学派不对时仍不进入这个分支。

## 3. 单元测试

`Assets/Tests/EditMode/SpellAttributeGateTests.cs`。

一件法术要求智力 20、信仰 0。智力 19 时 `AttributesAllowCast` 为 false，智力 20 时为 true。另一件要求信仰 15、智力 0。信仰 14 为 false，信仰 15 为 true。两项都是 0 时，智力 1、信仰 1 为 true。

不创建 Animator，不调用 `PerformSpellAction`，不改 `currentMP`。

## 4. 不做

不改学派判断。不改扣蓝。不画属性界面。不给已有法术资产填门槛。
