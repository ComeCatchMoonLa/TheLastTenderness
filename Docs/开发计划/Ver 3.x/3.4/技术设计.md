# 3.4 技术设计：一口只回一种

> **按瓶种只改一条。灰瓶改专注，其余改生命。**
>
> 需求以 [`游戏设计.md`](游戏设计.md) 为准。没有 **[待确认]** 的接口。

## 1. 只改一条

[`FlaskRestore.Apply`](../../../../Assets/Scripts/Items/Consumables/FlaskRestore.cs)：`FlaskType.ashen` 时只把专注加上这一口，不超过上限。其余类型只把生命加上这一口，不超过上限。另一条原样返回。

[`FlaskItem.SuccessfullyUsedConsumable`](../../../../Assets/Scripts/Items/Consumables/FlaskItem.cs)：这一口的量仍来自 `TryGetFlaskSip`。灰瓶调用 `AddMP`，其余调用 `AddHP`。不读 `healthRecoverAmount` 和 `focusPointsRecoverAmount`。

## 2. 测试

[`Assets/Tests/EditMode/Flask/FlaskRestoreTests.cs`](../../../../Assets/Tests/EditMode/Flask/FlaskRestoreTests.cs)。

生命 100、上限 150、专注 40、上限 80、这一口 30：血瓶后生命 130、专注 40；灰瓶后生命 100、专注 70。到顶时该条不变。

## 3. 不做

不改次数在哪扣。不改回复表。不删物品上的两个回复量字段。不算高风险：只决定这一口进哪一条。

## 4. 验收

游戏设计第 3 节。粒子和喝药模型不测。
