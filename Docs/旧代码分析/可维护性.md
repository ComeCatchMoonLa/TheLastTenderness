# 可维护性

> **文件夹能看出模块，一个行为仍常常要同时看旗标、动画名和某个 Manager。** 下面用还在跑的代码说明可读性、改一处要看的地方，以及加一种东西要动哪里。不另设计框架。

## 可读性

目录 `Perfabs`、文件 `CharacterInvontoryManager.cs`（类名 `CharacterInventoryManager`）、字段 `isPerformingBackSttbbed` 留着，因为改名会牵场景和预制体。同类已经进序列化的还有 `unaremd`、`sorvery`、`nearset`、`armor_Toros_Slot`、`DestoryAuto`、`noramalWeaponTrial`、`instantialtedFXModel`、`SucessfullyGetArrow`、`SucessfullyUsedConsumable`。

`CharacterManager` 上的公开布尔值没有单一所有者。读 `HandleMove` 要先知道 `isInteracting` 是刚才哪一次 `PlayTargetAnimation` 写下的，还是 `HandleEmptyState` 已经清掉。冲刺在输入里写，滞空在物理里写，跳跃和翻滚要等动画状态机。

名字和内容对不上的地方：

- `rollFlag` 的注释像「正在翻滚」，实际是短按。真正的翻滚是 `isRolling`。
- `horizontal` / `vertical` 的字段注释写反了。
- `CharacterEffectsManager.Ammo` 的注释写飞行弹药，实际是手里的上弦模型。飞行箭是另一份 `liveItemModel`。
- `PlayWeaponTrialFX` 播的是粒子，不是 `TrailRenderer`。
- `takingDamageSounds` 现挂的是弓的肉体打击声。
- 专注点有三套名字：类 `FocusPointsBar`，HUD 字段 `manaBar`，属性字段 `currentMP`，等级 `focusLevel`。
- `HipModelChanger` 是单数，护甲字段是 `Hips`。装备槽枚举是 `armor_Toros_Slot`。

注释已是 UTF-8。多数注释复述下一行在做什么。`HandleMove` 里的坡度系数 `2/sin(θ)-1` 只在注释里说了下坡加速。

`Debug.LogError` 很多，缺槽、缺组件都会打。Console 的 Error Pause 开着时，一条空引用会把 Play 按停。快捷栏物品图标为空已经不再报错；图标为空时格子留着上一张图。UI 槽位引用本身没接上时仍会报。

## 改一处要看的地方

**冲刺。** 0.5 之后只在 `InputManager.HandleRollInput` 写。格挡和瞄准仍是这次写入的条件，要看 `cCombat.isBlocking` 和 `aimingMode`。

**下落。** `HandleFall` 的射线、`PlayTargetAnimation("Falling", true)`、没有出口的 `Falling`、以及 `HandleEmptyState` 清 `isInteracting`，是同一件事的四段。`"Land"` 不看 `isInteracting`，落差条件一直成立就会每个物理步再切一次，并再次把交互写成 true。`rayStartPointHeight` 只在 `Start` 采样一次。上半身 Empty 也会清全身交互，和全身层停在哪一拍无关。

**一次轻击。** `PlayerCombatManager` 的按键顺序、武器上的 `oh_tap_e_action`、`LightAttackAction` 选动画字段、控制器状态上的 `HandleAttackState`、片段上的 `OpenDamageCollider`、`DamageCollider.DealDamage`、`TakeDamage`。左右手由调用前的 `UpdateWhichHandCharacterIsUsing` 决定。轻击和重击各写一份双手/左右手分支。轻击连击按上一击改 `attackType`。重击连击方法末尾把 `attackType` 写成 `heavy_2`，和实际播的是不是第二段无关。

**瞄准有两个旗标。** 相机、移动和冲刺读 `PlayerManager.aimingMode`。动画状态 `HandleAimingState` 写的是 `cCombat.isAiming`，并把玩家胶囊半径改成 0.4，离开时不改回。准星要两个都为真才显示。翻滚和跳跃进入都会清 `isAiming`。

**玩家按键和 AI 槽不是同一套。** 玩家双手仍读 `oh_*`。`th_tap_*` 只给 `ItemBasedAttackAction`。按住 E 松手不清，会每帧再进 `PerformAction`。点按 E 在判空之前读 `leftWeapon.weaponType`。

**一次法术。** 武器槽上的学派 Action、`currentSpell.spellType`、`SpellItem` 资产、动画事件、`SpellDamageCollider`。三个学派类只转发枚举。伤害进哪一段由投射物脚本写死为 `fd`，不由学派决定。`WeaponType` 的法杖枚举不参与这次核对。

**一次喝药或扔炸弹。** X 键不看 `isInteracting`。数量先减。效果在动画事件。炸弹结算读的是当时的 `currentConsumable`，不是按下时的 `this`。血瓶资产上的 `isInteracting` 为 0，喝药不锁移动；炸弹把交互写死为 true。

**穿一件甲。** `EquipArmor`、`EquipAllArmorModels`、子物体名字与 `transformName`、三格 `physicalDA`。属性面板上的火、魔、雷、暗吸收没有写入，`TakeDamage` 里那四路一直按 0 吸收算。头、躯干、下身的分支在库存、换模、UI 下标、属性字段上各写了一份。

**举盾。** `BlockAction` 传 `isInteracting: false`。松开 Q 的分支每个 `Update` 清 `isBlocking`。盾在左手时，这次输入仍把使用手标成右手，稳定率也从右手武器抄。正面格挡的朝向判断在 `DealDamage`。格挡命中仍会进 `TakeDamage`，因此仍会播受伤音。破防动画名 `"Guard_Break_01"` 和控制器状态 `Guard_Break` 不一致，旗标会先被写成交互中。

**背刺。** `GetBackStabbed` 用的是受击者右手武器。`pendingCriticalDamage` 用的是攻击者右手五段之和。两条若都走到 `TakeDamage`，会各扣一次，通道拼法也不一样。

**对话。** `Talk` 停掉大部分输入，不写 `isInteracting`。四条推进（自动/手动 × 逐字/逐句）是两两复制的。文案、说话人、时长在 `DialogueTextData`；自动和跳过在 `GameSettingsData`。

**设置。** 改相机速度输入框只写数据，要等到下次 `ApplyCameraSpeedSetting` 才进镜头，而那只在 `PlayerUIManager.Start`。垂直同步没有 `QualitySettings.vSyncCount`。死亡之后 `PlayerUIManager.Update` 先返回，已经打开的菜单无法用 Back 关掉，`timeScale` 留在 0。

**敌人双手。** 玩家先改 `isTwoHandingWeapon` 再装武器。敌人先 `LoadWeaponsOnBothHands`，再根据右手类型写双手标记。同一套槽代码，两边的第一次装载结果不同。

**空引用的武器模型。** `LoadWeaponModel` 在 `modelPrefab` 为空时已经销毁旧模型再返回。近战随后对空模型取碰撞体。提前 return 的类型（空手、法术、弓、盾）不把上一把的 `WeaponFX` 清掉。

## 可扩展性

现有挂钩就是下面这些。加一种东西要改的位置是固定的，没有注册表。

| 想加的东西 | 现在要动的地方 |
| --- | --- |
| 一种新的轻击或重击 | 新的 `WeaponItemAction` 资产，在 `PerformAction` 里调用已有的 `PlayTargetAnimation`，武器槽填上这个资产。控制器里要有同名状态 |
| 一种新的攻击段（第三下） | `AttackType`、`LightAttackAction` 或 `HeavyAttackAction` 的连击分支、`DamageCollider` 按 `attackType` 取阶段系数的地方、动画字段 |
| 一个新法术学派 | `SpellType` 末尾加成员，再写一个只转发枚举的 Action 子类，做成资产填进武器槽。新效果还要新的 `SpellItem` 子类。复用 `ProjectileSpell` 时伤害仍进 `fd` |
| 一种消耗品 | 新的 `ConsumableItem` 子类。不能挂进 `PerformAction`。结算仍从 `PlayerAnimatorManager.SuccessfullyCastConsumable` 进来 |
| 一个护甲部位 | `ArmorType`、`EquipmentSlotType`、空的物品子类、空的 `ModelChanger` 子类、`PlayerArmorManager` 分支、`EquipArmor`、`armorSlotsUI` 下标、`CharacterStatsManager` 上每个伤害类型一列，以及 `TakeDamage` 里写死的 60/30/10 |
| 一种伤害碰撞体 | 走触发器并调用基类：得到弹反、格挡、韧性和阶段系数，也必须接受 `Start` 把碰撞体设成 Trigger。走碰撞：要自己重写 `Start` 且不调基类，队伍判断和 `TakeDamage` 参数再抄一遍 |
| 一种伤害属性 | `TakeDamage` 已有五段。护甲只有物理段被穿戴写入。新段要在穿戴、格挡吸收、每个伤害体的赋值上各接一次 |
| 一种新的移动 | Input Actions 订阅、`InputManager` 字段、一个 `Handle*`、通常再加一个 `StateMachineBehaviour` 写旗标，以及 `ResetCollider` 的排除条件 |
| 一种近战 AI 行为 | 在 Humanoid 那组 `State` 上加一个，从现有 `Tick` 返回它。Idle 到攻击这一圈用具体类型互相 `GetComponent`，字段类型要跟着改。General / Boss 在 `Game_Before_0.7.unity`，不是这一组的扩展点 |
| 一种相机模式 | `HandleCameraRotation`、`FollowPlayer`、`SetCameraPosOffset` 三处条件现在就不一致，三处都要加 |
| 一个画质或帧率档 | `EnumsOptions` 加上设置窗口里前进、回退、应用三套 switch |

`BossCombatFXManager` 和 `EnemyAnimatorManager.InstantiateBossParticleFX` 没有调用方。成就窗口没有解锁逻辑。这些不是现在这三只近战或当前 HUD 的扩展点。
