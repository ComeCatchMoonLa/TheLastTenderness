# 可维护性

> **现在改得动，但一个行为常常要同时看旗标、动画名和某个 Manager。** 下面三项都用还在跑的代码，不另设计框架。

## 可读性

文件夹能看出玩家、敌人、物品、伤害。难读的是名字和旗标：`Perfabs`、`CharacterInvontoryManager`、`isPerformingBackSttbbed` 这种拼写留着，因为改名会牵场景和预制体。`CharacterManager` 上一排公开布尔值，读一个函数要先知道这些字段此刻谁刚写过。

注释已是 UTF-8。多数注释复述下一行在做什么，不能靠注释知道为什么这样写。

## 可维护性

改冲刺曾经要同时看 `InputManager` 和 `BlockAction`。0.5 之后冲刺只在 `InputManager` 写，这一处已经收拢。其余旗标还没有。

动画靠字符串。`PlayTargetAnimation("Falling", true)` 和控制器里的状态名必须一致，编译器不会检查。`Falling` 在 Humanoid 控制器里没有出口，射线一旦没打中地面，`isInteracting` 会一直为 true，人停在下落姿势。

`Debug.LogError` 很多。Console 的 Error Pause 开着时，一条空引用就会把 Play 按停。快捷栏物品图标为空已经不再报错；UI 槽位本身没接上时仍会报。

## 可扩展性

再加一种轻击或重击：新的 `WeaponItemAction` 资产，在 `PerformAction` 里调用已有的 `PlayTargetAnimation`。现有入口够用。

再加一种近战行为：在 Humanoid 状态上加一个 `State`，从现有 `Tick` 返回它。General / Boss 是平行的另一套，不是给现在这三只近战用的扩展点。不要为了“以后可能有第三套”再包一层。
