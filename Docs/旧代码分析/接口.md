# 接口

> **类型之间没有单独的接口层。** 角色之间靠 `CharacterManager` 上的公开字段、动画名字符串、`TakeDamage` 的五个伤害槽，以及武器资产上的 `WeaponItemAction` 槽说话。

## 旗标

移动四个字段各有一处写入：

| 字段 | 谁写 | 谁读 |
| --- | --- | --- |
| `isRolling` | `HandleRollState` 进入 / 离开 | `HandleRotate`、`PlayerManager.ResetCollider` |
| `isJumping` | `HandleJumpState` 进入 / 离开 | `HandleFall` 为真则整段不做落地射线 |
| `isInAir` | `PlayerLocomotionManager.HandleFall` | 同一方法用上一物理步的值决定要不要加下落力 |
| `isSprinting` | `InputManager.HandleRollInput` | `HandleMove`、`HandleRotate` |

`BlockAction` 不写 `isSprinting`。举盾时若仍按住 Shift，`HandleRollInput` 里的格挡判断会把冲刺保持为 false。

其余旗标仍是公开字段，多处能改：

| 字段 | 写成 true 的典型位置 | 写成 false 的典型位置 |
| --- | --- | --- |
| `isInteracting` | `PlayTargetAnimation` 的第二个参数为 true | `HandleEmptyState.OnStateEnter` |
| `canRotate` | Empty 进入 | 同一次 `PlayTargetAnimation` |
| `isUsingLeftHand` / `isUsingRightHand` | `PlayerCombatManager` 在调用 `PerformAction` 之前 | Empty 进入时两个都写成 false |
| `cCombat.isBlocking` | 格挡动作 | 按住 Q 的松开分支，每个 `Update` |
| `cCombat.isAttacking` | `HandleAttackState` 进入 | 该状态离开 |
| `cCombat.isUsingSpell` | `HandleUseSpellState` | 该状态离开 |
| `cCombat.isUsingConsumable` | `HandleUseComsumableState` | 该状态离开 |
| `PlayerManager.aimingMode` | `AimAction` 在双手且有箭时写成 true | 没箭、正在交互、或松开 Q |
| `cCombat.isAiming` | `HandleAimingState` 进入 | 该状态离开；`HandleRollState` 进入时也会写成 false |
| `canDoCombo` | 攻击片段上的 `EnableCombo` | `DisableCombo`；轻击和重击连击方法里也会先写成 false |
| `talkWithSB` | `TalkUI.SetTalkerStatus` | `HandleTalkEnd` |

`isInteracting` 为 true 时，`HandleMove` 停写速度，`HandleRollInput` 不再处理冲刺和翻滚，`HandleFall` 不会重播 Falling。落到地面后的 `"Land"` 不看这个旗标。格挡起手传的是 false，举盾本身不锁移动。`canRotate` 还由动画事件 `EnableRotate` / `DisableRotate` 写。`isBlocking` 在人形战斗姿态里、`willPerformBlock` 为假时也会写成 false 并播 `"Block - End"`。

`cCombat` 和玩家上的 `pCombat` 是同一个 `PlayerCombatManager`。`CharacterManager.Awake` 取到的就是这个组件。

## 播动画

`PlayTargetAnimation(动画名, 是否交互, 能否转向, 是否镜像, …)` 是第二个人人都会调用的入口。调用方传入的 `true` 同时表示：这次要根运动、`HandleMove` 让路、不要再播 Falling。

写死的状态名包括 `"Jump"`、`"Rolling"`、`"Backstep"`、`"Falling"`、`"Land"`、`"Shrug"`、`"Block - Start"`、`"Parried"`、`"Riposte"`、`"Back Stab"`、`"Guard_Break_01"`、`"Damage_ForwardRight_01"`、`"Death"`、`"Left Arm Empty"`、`"Right Arm Empty"`、`"Pick Up Item"`、`"Open Chest - Start"`。箱子自己的 Animator 播 `"Chest Open"`。轻重击的名字在 `CharacterAnimatorManager` 的字段上（`ohLightAttack1` 等）。`Humanoid.controller` 里破防状态叫 `Guard_Break`，和 `"Guard_Break_01"` 对不上。`WeaponItem.offHandIdleAnimation` 的代码默认值是 `"Left_Arm_Idle_01"`，现用控制器里是 `Left_Arm_Idle`。已有武器资产写的是后者。

副手待机来自武器资产的 `offHandIdleAnimation`，默认 `"Left_Arm_Idle_01"`。法术和消耗品的施法动画是资产字段 `spellAnimation` / `consumeAnimation`。

`Falling` 没有出口，也没有 `HandleEmptyState`。`Land` 有出口，回到 NonCombat Empty 后才清 `isInteracting`。`HandleEmptyState` 还挂在 Upper Body Empty 上，喝药或瞄准结束回到这一层时，也会把全身的 `isInteracting` 和 `isAttacking` 清掉。

## 动画事件

这些方法在 `CharacterAnimatorManager` 上，供片段按方法名调用。C# 里几乎没有直接调用。改名或改签名，编译器不会改片段。

| 方法 | 随后做什么 |
| --- | --- |
| `OpenDamageCollider` | 打开当前手的伤害体，再 `PlayRandomWeaponWhoosh` |
| `CloseDamageCollider` | 关掉伤害体 |
| `EnableCombo` / `DisableCombo` | 写 `canDoCombo` |
| `DrainStamina` | 扣体力 |
| `SuccessfullyCastSpell` | 转到 `currentSpell.SuccessfullyCastSpell` |
| `SuccessfullyCastConsumable` | 转到 `currentConsumable.SucessfullyUsedConsumable` |
| `SucessfullyGetArrow` / `EndGetArrow` | 上弦模型换父节点 |
| `ApplyPendingDamage` | 把暂存伤害送进 `TakeDamage` |

左右手不由事件参数决定，只看当时的 `isUsingRightHand`。`HandleEmptyState` 会把两手都写成 false。若此时仍跑到挥刀音，条件失败，去播左手武器的音效。

## 伤害入口

`TakeDamage` 的签名是 `(string damageAnimation, float pd = 0, float fd = 0, float md = 0, float ld = 0, float dd = 0)`。五段在方法内各自乘护甲剩余率后相加。无敌和死亡在这里返回，不再扣血。

谁负责把伤害送进来：

| 入口 | 碰撞回调 | 进 `DealDamage` | 实际传入 |
| --- | --- | --- | --- |
| `DamageCollider` | `OnTriggerEnter` | 是 | 五段，再乘武器阶段系数；正面格挡再乘 `(1 - 格挡吸收)` |
| `AmmoDamageCollider` | 先调基类 | 是，与近战同一份 | 伤害规则相同；之后只决定箭是否嵌入并销毁 |
| `SpellDamageCollider` | `OnCollisionEnter` | 否 | 只传 `fd`，动画名写死 |
| `BombDamageCollider` | `OnCollisionEnter`，再 `OverlapSphere` | 否 | 直击 `explosionDamage`，溅射 `explosionSplashDamage`，都走 `fd` |
| `DamagePlayer` | `OnTriggerEnter` | 否 | 只打玩家，`fd: damage`（默认 25） |

过滤是 Tag 加 `teamID`，脚本里没有 `LayerMask`。近战要求对方身上有 `CharacterManager`。法术和炸弹要的是 `CharacterStatsManager`。`DamagePlayer` 要 `PlayerStatsManager`。队伍默认：伤害体 `teamID` 为 0，角色为 2。

近战没有「已经打过」的标记，同一窗口里再次进入会再结算，收招靠 `DisableDamageCollider`。法术和炸弹用 `hasCollided`，撞墙或撞队友也会吃掉这一发。炸弹溅射不去重，直击过的人会再结算一次。

`offensivePoiseBonus` 在这五个伤害脚本里没有读取。韧性破不破是 `DealDamage` 的事：没破则 `TakeDamage` 的动画名为 null，破了才把方向动画传进去。

## 物品三种入口

三种使用路径互不继承。

| 路径 | 基类 | 谁调用 | 完成时机 |
| --- | --- | --- | --- |
| 武器动作 | `WeaponItemAction` | `PlayerCombatManager` 按键顺序 | 动作自己播动画；命中在伤害体 |
| 法术 | 门禁用 `MagicSpellAction`，效果用 `SpellItem` | 某个武器槽填了学派 Action | 动画事件 `SuccessfullyCastSpell` |
| 消耗品 | `ConsumableItem` | X 键 → `AttemptToConsumableItem` | 动画事件 `SucessfullyUsedConsumable` |

法术门禁先比较 `currentMP >= focusPointCost`，真正减去在 `AttemptToCastSpell` 的 `DeductMP`。治疗那条忽略扣蓝失败。投射物那条在扣蓝失败时停住。

消耗品数量在 `Attempt` 里就减。血瓶和炸弹的尝试逻辑是复制的：查 `isUsingConsumable`、扣数量、卸右手、把模型挂到 `overrideParentWhileHolding`、记到 `PlayerEffectsManager.instantialtedFXModel`。

护甲没有动作类。库存格按 `ArmorType` 写三个 `current*` 字段，再换模、写三格 `physicalDA`。

## 设置与文案

玩法读设置的路径是 `player.ui.escWin.GetSettingWin().gameSettingsData`。

| 字段 | 谁读 |
| --- | --- |
| `auto`、`wordForWord`、`skip` | `Talk.Interact`、`PlayerManager.Update` |
| `enableFps` | `HUDWindowsManager.UpdateFPS` |
| `autoChangeLockOnTarget` | `PlayerCameraManager` |
| `cameraLeftAndRightSpeed`、`cameraUpAndDownSpeed` | 只在启动时 `ApplyCameraSpeedSetting` |
| `frameRateLimit_Options`、`displayQuality_Options` | 启动和切换时写到引擎 |
| `vsync_Options`、后处理、特效 | 只改窗口上的中文标签 |

`PopUpInterface` 只有 `PopUp()`。`Close` 不在接口上。对话用 `SetActive`，查看信息改 TMP 的 `enabled`，篝火用 `CanvasGroup` 淡入淡出。

文案三套来源：`DialogueTextData`、`TextData`、篝火预制体上的固定句子。没有语言表。

## 枚举

`EnumsTypes.cs` 从 0 起编号。漏配的资产会落到第一个成员。已经写进资产的拼写包括 `unaremd`、`sorvery`、`nearset`、`armor_Toros_Slot`。

有定义、分支里没有出现的成员：`WeaponType` 的三种单手持握、`AttackType.critical`（暴击走 `CriticalAttackAction`，不写这个枚举）、`ChangeLockOnTargetMode.minHP`。`NPCType` 和 `StateMachineBehaviourType` 没有调用方。`AmmoType` 和 `FlaskType` 有字段，使用逻辑不读它们。

层号以 `Layer.cs` 为准。交互检测用 `interactable`（7）。落地用环境、NPC、玩家。锁定扫描和炸弹溅射不传层。`CatchMoon.LayerMask` 与 `UnityEngine.LayerMask` 同名，落地检测的字段因此写成 `UnityEngine.LayerMask`。
