# 架构

> **一个角色是同一物体上的多个 Manager，加上 `CharacterManager` 上的公开旗标。** 没有单独的战斗核心。玩家和近战敌人共用这一层，差异在子类多出来的组件和谁来写旗标。

## 角色

`CharacterManager.Awake` 用 `GetComponent` 拿到七个 Manager：动画、战斗、特效、物品、属性、武器槽、音效。`PlayerManager`、`EnemyManager` 再各自取自己的子类。

物品类名是 `CharacterInventoryManager`，文件名是 `CharacterInvontoryManager.cs`。

### 玩家一帧

工程里没有自定义脚本执行顺序。和移动有关的阶段是：

1. `PlayerLocomotionManager.FixedUpdate`：`HandleMove` → `HandleRotate` → `HandleFall` → `HandleJump` → `HandleRoll` → `HandleBackStep`，最后把刚体速度长度写进 `currentSpeed`（只给检视器看）。
2. Input System 回调把按钮写成布尔量。`InputManager` 不调用移动或战斗。
3. `Update`：`InputManager` 先 `HandleMoveInput` 再 `HandleRollInput`；`PlayerCombatManager.HandleCombatInput` 读战斗键；`PlayerInventoryManager` 读换武器、道具、快捷栏；`PlayerManager` 做交互检测和对话推进。
4. Animator：`StateMachineBehaviour` 进入/退出，以及 `PlayerAnimatorManager.OnAnimatorMove`。
5. `InputManager.LateUpdate` 清掉方向键、交互点按、Esc。相机在自己的 `LateUpdate` 里读 `mouseX` / `mouseY`。

`moveAmount` 在 `InputManager` 上，不在角色上。`sprintFlag` 只声明，没有读写。`rollFlag` 是短按松手的一次性输入，翻滚状态是 `isRolling`。

冲刺只在 `HandleRollInput` 里写。格挡中先清掉。按住翻滚键时累加计时：体力不大于 `sprintNeedMinStamina`（10）则清掉冲刺；否则要有位移、非瞄准、非格挡才写成 true。松开时，计时器在 `(0, 0.5)` 秒内且 `moveAmount > 0` 写 `rollFlag`，否则写 `backStepFlag`。

跳跃、翻滚、后步在 `FixedUpdate` 里只清输入并 `PlayTargetAnimation`。`isJumping`、`isRolling` 要等本帧更后面的动画状态进入才变。因此起跳的同一物理步里，`HandleMove` 仍按地面速度写刚体，`HandleFall` 仍做落地射线。

`HandleFall` 在 `isJumping` 时整段返回。否则先做一条水平射线（默认层，长 0.2），再向下射线。起点是 `transform.position` 加上 `Start` 时采样的胶囊体底部高度，之后跳跃/翻滚改胶囊体，这个缓存不更新。层遮罩在 `Start` 里被覆盖成环境、NPC、玩家（层 8、9、11），检视器上的值不起作用。长度是底部高度加上 `HeightToBeginLand`（默认 0.8）。打不中就把 `isInAir` 写成 true；当时不在交互中则立刻播 `"Falling"` 并把 `isInteracting` 写成 true，所以 Falling 不会每个物理步重播。打中则贴到落点。落差达到 `rayStartPointHeight + minHeightNeedToLand` 时播 `"Land"`，这一支不看 `isInteracting`。条件一直成立，每个物理步都会再 `CrossFade` 一次。

`HandleMove` 在交互中或 `rollFlag` 仍为真时不写速度。瞄准时 `HandleRotate` 整段不转。锁定且非冲刺非翻滚时朝锁定目标转，否则朝相机合成的 `moveDir` 做 `Slerp`。

### 战斗输入

`PlayerCombatManager.HandleCombatInput` 的调用顺序决定谁能打断谁：按住 E、按住 Q、点按 E、点按 R、点按 Q、点按 Z。每一支只做一件事：选出左手或右手武器，调用该武器槽上的 `WeaponItemAction.PerformAction`。代码里没有「这是法术键」或「这是攻击键」的分支。

点按 E：先读 `leftWeapon.weaponType`，是弓才用左手的 `oh_tap_e_action`，否则用右手。左手武器为空时，这次比较发生在判空之前。玩家双手持握时仍然读 `oh_*` 槽，不读 `th_*`。`th_tap_*` 只在人形 AI 的 `ItemBasedAttackAction` 里调用。`oh_hold_r_action` 和全部 `th_hold_*` 没有玩家调度。按住 E 的布尔量松手不清，按住期间每个 `Update` 都会 `PerformAction`。按住 Q 松开的那个 `else` 每帧把 `isBlocking`、格挡吸收和 `aimingMode` 清掉。左手是盾时，按住 Q 仍把「正在使用的手」标成右手，格挡吸收按右手武器抄。消耗品不走这里，走 X 键和 `PlayerInventoryManager`。

### 敌人

`EnemyManager.Update` 在未死亡时调用 `HandleRecoveryTimer`、`HandleStateMachine`、`UpdateAICombatInfo`。状态机是：

```csharp
State nextState = currentState.Tick(this);
```

`State` 是挂在同一物体上的 `MonoBehaviour`，`Tick` 返回下一个状态。`currentState` 非空才跑。`LateUpdate` 把子物体上的 `NavMeshAgent` 本地变换拉回零；`Start` 里先把导航关掉，刚体不是运动学刚体。

`enableAI` 为 false 时 `HandleStateMachine` 仍会 `Tick`。人形各状态在开头自己 `return this`。`LateUpdate` 每个敌人都把子物体上的 `NavMeshAgent` 本地变换拉回零，不看 `enableAI`。`EnemyAnimatorManager.OnAnimatorMove` 每个动画帧用 `deltaPosition` 覆盖刚体速度，不看 `isInteracting`。玩家的根运动回调有这道闸门。

现在场景里的三只近战走 `Character/NPC/State/Humanoid A.I/`。近战预制体的 `Enemy States` 只挂待机、追击、转向、战斗姿态、攻击这五份，`currentState` 指向 `IdleStateHumanoid`。待机在 AI 开着、未死、且不在交互时，每个 `Tick` 做一次只打玩家层的 `OverlapSphere`，再按视野角和 `Linecast` 决定要不要把玩家写成 `currentTarget` 并切到追击。攻击状态在打出的同一次 `Tick` 里就返回转向状态，不在攻击状态停留；连击要再次进入攻击状态。转向状态可能在播转向动画的同一次 `Tick` 里再按距离切回追击或战斗姿态。人形追击的转向是 `rotationSpeed / Time.deltaTime`。战斗姿态近战分支还会掷格挡、闪避、弹反，这些不换状态，直接播动画。

`General A.I/` 是平行的一套：待机、追击、转向、战斗姿态、攻击、伏击。Idle、追击、转向的 `Tick` 和 Humanoid 同结构。General 的待机不看 `enableAI`。攻击数据是 `EnemyAttackAction`，不是 `ItemBasedAttackAction`。`Boss A.I/BossCombatStanceState` 继承 General 的 `CombatStanceState`，只覆写选招；半血后 `EnemyStatsManager` 把 `hasPhaseShifted` 写成 true，改读 `sencondPhaseAttacks`。当前 `Game.unity` 和近战预制体没有这两套的脚本。它们留在 `Assets/Scenes/Game_Before_0.7.unity`。场景里另有一个未激活父节点下的 `NPC - 001`，挂了人形五状态，但 `currentState` 为空、`enableAI` 为 false。

## 动画

播放入口是 `CharacterAnimatorManager.PlayTargetAnimation`。它按动画名 `CrossFade`（过渡 0.2 秒），并写下 `isInteracting`、能否转向、是否用根运动。状态名必须和控制器里的一致，方法本身不检查状态在不在。

进行中的开关在 `Assets/Scripts/Animator/HandleState/`：

| 行为 | 进入时 | 离开时 |
| --- | --- | --- |
| `HandleEmptyState` | 挂在 Combat、NonCombat、Upper Body 三个 Empty 上。进入时 `canRotate = true`，`isInteracting = false`，清无敌、左右手、攻击、背刺、弹反，镜像 bool 复位。上半身回到自己的 Empty 也会清掉全身的 `isInteracting` | — |
| `HandleRollState` | `isRolling = true`，`isAiming = false`；玩家换成翻滚胶囊体 | 只把 `isRolling` 写成 false，碰撞体不还原 |
| `HandleJumpState` | `isJumping = true`，`isAiming = false`；玩家换成跳跃胶囊体 | 只把 `isJumping` 写成 false，碰撞体不还原 |
| `HandleAttackState` | `cCombat.isAttacking = true` | 攻击结束，左右武器粒子 `Stop` 并 `Clear` |
| `HandleUseSpellState` | `cCombat.isUsingSpell = true` | 写成 false |
| `HandleUseComsumableState` | `cCombat.isUsingConsumable = true` | 写成 false |
| `HandleAimingState` | `cCombat.isAiming = true`；玩家胶囊半径改成 0.4 | `isAiming = false`，不改回半径 |
| `HandleTurnState` | — | 把 `turnAngle` 乘进敌人当前旋转 |
| `HandlePhaseShiftState` | 敌人 `isPhaseShifting = true` | 写成 false |
| `HandleChestOpenState` | — | 箱子开完 |

`LeftHandIKTarget` / `RightHandIKTarget` 挂在武器模型上。双手武器装载时从右手模型取出，交给 IK。

玩家和近战敌人预制体用的是 `Humanoid.controller`，不是 `A.I Humanoid.controller`。`Falling` 在这份控制器里没有出口，也没有状态机行为。射线后来打中且落差够，`HandleFall` 会 `CrossFade` 到 `Land`。`Land` 有出口，大约一半时长后回到 NonCombat Empty，Empty 进入时才清 `isInteracting`。射线一直打不中，或打中但落差不够，人停在 Falling。`PlayTargetAnimation` 在 `CrossFade` 之前就写旗标。状态名对不上时动画不切，`isInteracting` 已经改了。`AttemptBlock` 播的是 `"Guard_Break_01"`，现用状态名是 `Guard_Break`。`EnemyStatsManager.BreakGuard` 播的 `"Break Guard"` 只在未被引用的 AI 控制器里。`HandleChestOpenState` 在离开时 `Destroy(animator)`，而 `Chest Open` 没有出口，这段不会因为播完而发生。

`OnAnimatorMove` 在 `isInteracting` 时用 `deltaPosition / deltaTime` 覆盖刚体速度。落地用 `transform.position` 改高度，平时移动用刚体速度，转向用 `transform.rotation`。

## 武器槽

`CharacterInventoryManager.Start` 取出当前左右武器，调用 `LoadWeaponsOnBothHands`。换武器、装备确认、双手切换再走到 `LoadWeaponOnSlot`。

`WeaponHolderSlot.LoadWeaponModel` 先销毁旧模型，再 `Instantiate(weaponItem.modelPrefab)`，父节点是槽上的 `overrideParentWhileHolding`，然后 `Transform.ResetLocal`。姿态来自挂点，不读 `WeaponItem.transform`。槽位靠 `ItemSlotType`（左手、右手、背），不靠物体名叫 `Hand_L` 还是 `Hand_R`。

装完后 `LoadWeaponDamageCollider` 在模型上找 `DamageCollider` 和 `WeaponFX`。空手、三系法术、弓、盾在写伤害体之前返回。弓会换成该武器自己的 `runtimeAnimatorController`。

背槽没有单独的装备入口。右手是弓时，另一把武器的模型生成在背上，右手槽卸空。`isTwoHandingWeapon` 为真时，刚装上的左手改记到背槽，左手换成空手。敌人子类 `EnemyWeaponSlotManager` 是空的，装载逻辑与基类相同。敌人在 `base.Start` 已经装完武器之后，才根据右手类型把双手标记写成 true，所以初次装载看不到这个标记。

`UnloadWeapon` 只是 `SetActive(false)`，药瓶和炸弹临时让出右手时用它。`UnloadWeaponAndDestroy` 会 `Destroy`。两者都不清 `currentWeapon`。

`modelPrefab` 为空时，旧模型已经拆掉，随后近战分支对空模型取 `DamageCollider`。`ArrowInstantiationLocation` 是空组件，取箭代码不找它。取箭走 `CharacterAnimatorManager.SucessfullyGetArrow`：实例化到右手 Getting 节点，`EndGetArrow` 再改父节点到 Holding。

## 物品

### 武器动作

`WeaponItemAction` 是 `ScriptableObject`，`PerformAction(CharacterManager)` 是抽象方法。轻击、重击、格挡、弹反、弓的瞄准和射击、三系法术门禁，都是武器资产上 16 个槽里的不同资产。槽名是 `oh_` / `th_` × 点按 / 按住 × E / Q / R / Z。玩家战斗输入只读一部分 `oh_*`。

`LightAttackAction` 和 `HeavyAttackAction` 都按是否双手、是否左手选择动画字段，`PlayTargetAnimation(..., isInteracting: true)`，然后 `PlayWeaponTrialFX`。连击看 `canDoCombo`。轻击连击按上一击是不是第一段，把 `attackType` 写成 `light_1` 或 `light_2`。重击第一下写成 `heavy_1`；连击方法在末尾无条件写成 `heavy_2`，即使这次实际重播的仍是第一段。

`BlockAction` 播 `"Block - Start"`，`isInteracting` 传 false，所以举盾本身不锁移动。`ParryAction` 播武器战技动画。`CriticalAttackAction` 分 `"Riposte"` 和 `"Back Stab"`。

### 法术

法术分两层。武器上的 `MagicSpellAction` 子类只核对 `currentSpell.spellType` 并看蓝够不够；效果在 `SpellItem` 子类。

`SorcerySpellAction`、`PyromancySpellAction`、`MiracleSpellAction` 各传入一个枚举：`sorvery`、`pyromancy`、`miracle`。三个子类没有各自的弹道或伤害。`MagicSpellAction.PerformAction` 是空的，槽上如果挂的是基类资产，按键什么都不做。

蓝够才 `AttemptToCastSpell`，不够播 `"Shrug"`。真正生成弹体在动画事件 `SuccessfullyCastSpell` → `PlayerAnimatorManager` → `currentSpell.SuccessfullyCastSpell`。仓库里的控制器文本搜不到这个函数名，事件在导入的片段上。

`ProjectileSpell` 把 `fd` 写成 `baseDamage`，物理、魔法、雷、暗保持 0。NPC 的 `SuccessfullyCastSpellWithAI` 是空的。`HealingSpell` 不生成弹体，释放时 `AddHP`；它忽略 `DeductMP` 的返回值。现有资产是火球（`pyromancy`，`"Throw_Spell"`）和治疗（`miracle`，`"Spell_Heal_Start"`）。没有 `sorvery` 资产。

`WeaponType` 上的三种法杖和 `SpellType` 没有对应关系。装载时这三类和空手、弓、盾一样跳过近战伤害体。

### 消耗品

X 键 → `HandleUseConsumableInput` → `currentConsumable.AttemptToConsumableItem`。不看 `isInteracting`。`isUsingConsumable` 为真则整次取消。数量在播动画之前就 `--currentItemAmount`，写在这块 `ScriptableObject` 上，没有每个玩家一份计数。数量为 0 播 `"Shrug"`。

结算在动画事件 `SuccessfullyCastConsumable` → `SucessfullyUsedConsumable`。片段上没有这个事件时，数量已经扣了，回血或生成炸弹不会发生。

| | 血瓶 | 炸弹 |
| --- | --- | --- |
| 动画 | 资产字段，现为 `"Drink"`；资产上的 `isInteracting` 是 0 | 写死 `"Throw_Consumable"` 且 `isInteracting: true` |
| 结算 | `AddHP`，重装双手武器 | 实例化活体炸弹并加力，只重装右手 |
| 未使用的字段 | `flaskType`、`focusPointsRecoverAmount` | `bombMass` 没有赋给刚体 |

炸弹结算里把 `currentConsumable as BombItem`，不用 `this`。动画途中换快捷栏时，扣的是按下时那件，效果跟着当时的 `currentConsumable`。

### 护甲

穿戴从 `InventorySlotUI.EquipArmor` 进入，不看装备窗当前选中的槽，只看 `armor.armorType`。旧的同部位退回库存，新的写入 `currentHeadArmor` / `currentTorsoArmor` / `currentHipsArmor`，再 `EquipAllArmorModels`。装备窗只改图标。

换模不找 `Renderer`。`ModelChanger` 把自身直接子物体放进列表，按 `Item.transformName` 开关。头、躯干、下身是三个空子类。空的躯干和下身会再打开赤裸模型名，头只全部关掉。

`EquipAllArmorModels` 只把 `physicalDA` 写进头、躯干、下身三格。`fireDA`、`magicDA`、`lightningDA`、`darkDA` 只出现在属性面板。`armorPoiseBonus` 也不由穿戴写入。`HeadArmorItem` 等三个子类只有 `CreateAssetMenu`。

### 交互物

`PlayerManager.CheckForInteractableObject` 每个显示帧做一次 `OverlapSphereNonAlloc`。范围内有 `Interactable` 且 tag 为 `Interactable` 时，点按调用 `Interact`。

| 类 | `Interact` 做什么 |
| --- | --- |
| `PickUpItem` | 把物品放进背包 |
| `Talk` | 把玩家拽到站位点，打开 `TalkUI`，按设置四选一推进台词 |
| `ViewInfo` | 把 `TextData` 交给查看弹窗，然后销毁自己 |
| `OpenChest` | `OpenChestInteracting` 让玩家播 `"Open Chest - Start"`。已在交互时这一步返回，但箱子自己仍会再播 `"Chest Open"` 并再开协程。协程里把箱内武器赋给生成点上的 `PickUpItem` |
| `CampFireInteractable` | 未点燃时播 `"Pick Up Item"` 并弹出篝火 UI；已点燃的分支是空的 |
| `FogWall` | 不实现 `Interact`。`Start` 把自己关掉。Boss 战开始时由 `WorldEventManager` 打开名单里的雾墙 |

## 伤害

`CharacterStatsManager.TakeDamage(动画名, pd, fd, md, ld, dd)` 在已死或无敌时直接返回。五段各自乘护甲剩余率再相加。剩余率是头 60%、躯干 30%、下身 10%：`(1 - 头吸收) * 0.6 + (1 - 躯干吸收) * 0.3 + (1 - 下身吸收) * 0.1`。然后扣 `currentHP`，播受伤音，动画名非空才 `PlayTargetAnimation`。血、蓝、体力上限都是对应等级乘 10。

近战和弹药走 `DamageCollider.OnTriggerEnter` → `DealDamage`：弹反、格挡朝向、武器阶段系数、韧性都在这里。法术和炸弹重写 `Start` 且不调基类，所以不会被改成触发器；它们在 `OnCollisionEnter` 里直接 `TakeDamage`，固定动画 `"Damage_ForwardRight_01"`，只传 `fd`。炸弹随后 `OverlapSphere` 再溅射一笔 `explosionSplashDamage`，直击过的人会再吃一次。`DamagePlayer` 是环境触发器，只打 tag 为 `Player` 的对象，默认 25 点火焰伤害。

格挡扣体力在 `CharacterCombatManager.AttemptBlock`：五段之和乘碰撞体上的 `guardBreakModifider`，再乘 `(1 - blockingStabilityRating)`。`WeaponItem.guardBreakM` 和 `stability` 不参与。`DeductStamina` 只有体力够才扣。扣完小于等于 0 就清格挡和吸收，并播 `"Guard_Break_01"`（现用控制器里的状态名是 `Guard_Break`）。体力大于 0 但不够扣时，体力不变，盾吸收照样乘上。破防发生在吸收乘区之前，所以破防那一刀的格挡吸收已经是 0。左手分支的五段吸收来自左手武器，`blockingStabilityRating` 来自右手武器。

韧性不减伤。`DealDamage` 先 `totalPoiseDefence -= poiseBreak`，再和同一个 `poiseBreak` 比：减完仍大于它才不播受击动画。血两种情况都扣。`poiseLevel` 没有结算读取。`armorPoiseBonus` 不由穿戴写入。基类 `TakeDamage` 不判死；玩家和敌人的覆写在 `currentHP <= 0` 时调用 `Death`。

背刺 `GetBackStabbed` 跑在受击者的战斗组件上，五段伤害乘的是受击者自己的 `rightWeapon.criticalAttackDM`。`CriticalAttackAction` 另外把攻击者右手五段加总写入 `pendingCriticalDamage`。动画事件 `ApplyPendingDamage` 会再当成纯物理打一次。

## 特效与音效

`CharacterEffectsManager` 播当前手的武器粒子和命中处的血溅。`EnemyEffectsManager` 是空子类。`PlayerEffectsManager.Update` 在拿着箭、又不在瞄准、且上半身不是取箭或瞄准起手时，销毁手持箭模型。

拖尾是武器上的 `ParticleSystem`，字段名 `noramalWeaponTrial`。攻击动作里 `Play`，`HandleAttackState.OnStateExit` 里 `Stop`。血溅实例化后靠 `DestoryAuto` 三秒销毁。爆炸粒子五秒。`BossCombatFXManager` 的二阶段火焰没有任何调用会把它打开。

`CharacterSoundFXManager` 用角色根上的一个 `AudioSource`，`PlayOneShot` 叠放。受伤音由 `TakeDamage` 调用。挥刀音由动画事件 `OpenDamageCollider` 在打开伤害体之后调用，看当时的 `isUsingRightHand`。没有脚步方法。

## 界面

### HUD

血条、体力条、专注条不读属性。属性变化时，`PlayerStatsManager` 直接写 `Slider`。体力恢复那几秒会每帧重写。快捷栏在换武器、换法术、换消耗品时刷新。`itemIcon` 为空则直接返回，格子上留着上一张图。

小怪血条挂在敌人身上。受伤时显示约 2 秒。Boss 血条是场景里的一块，`WorldUIManager.Awake` 用 `FindAnyObjectByType` 找到。开战 `ActivateBossBar`，受伤只改当前值，结束关掉。

灵魂数要等 `AwardSoulsOnDeath` 才写文字。`AddSouls` 只改数字。

### 背包与装备窗

背包和装备窗持有的是同一批 `ScriptableObject` 引用，没有运行时副本。`PlayerInventoryManager` 的总表 `items` 没有第二处读取，窗口画的是 `weapons`、`armors`、`spells`、`consumables`。玩家预制体上总表和分类表的引用已经对不齐。点背包里的法术或消耗品会直接返回，不改快捷栏当前项。

`InventorySlotUI` 按 `ItemType` 分支：装备里的护甲走上面的穿戴，武器才看装备窗当前选中的 `selectedSlotType`。装备窗只画左右手槽的 `[0]` 和 `[1]`。玩家预制体每手有 4 把，下标 2、3 能被方向键轮换出来，装备窗看不到。换装之后不刷新背包格子。属性窗会显示五项吸收，其中四项伤害公式读不到。弹药不进 `ItemType`，也不进背包分类。

`TapWindowsManager` 只开关整块根物体，不改 `timeScale`，移动输入继续有效。技能页和地图页的打开分支是空的。

### 暂停菜单

Escape 在 `UISwitch.OpenEscWin` 里把 `ui_openEscWin_Input` 写成 true。`PlayerUIManager` 在还没打开 Esc 时调用 `EscWindowsManager.Open`：根物体打开，关掉游戏输入、打开 `UIOperation`，`Time.timeScale = 0`。同一颗 Escape 随后变成 `UIOperation.Back`，按 `openedWin` 逐层退。回到根窗口关闭时 `timeScale` 写回 1。全项目只有这两处改 `timeScale`。

设置项会改内存里的 `GameSettingsData`。帧率和画质会写到 `Application.targetFrameRate` 和 `QualitySettings`。垂直同步、后处理、特效只改标签。声音页和操作页只开关物体。`Reset` 是空的。成就卡只翻 Inspector 里的文案，没有解锁条件。

### 弹窗

`PopUpInterface` 只有 `PopUp()`。

对话文案是 `List<DialogueTextData>`。`Talk.Interact` 按 `auto` 和 `wordForWord` 四选一。手动推进和跳过在 `PlayerManager.Update`。结束走 `HandleTalkEnd`：`inputActions.Enable()` 会把全部动作图打开，包括开局关掉的 `UIOperation`，然后关掉对话 UI、清 `storyNpc`。`Talk.Interact` 自己不写 `isInteracting`。随后 `talkWithSB` 抽到的手势动画会经过 `PlayTargetAnimation`，把这个旗标写成 true。交互检测不读 `isInteracting`，对话期间半径里另一个 `Interactable` 仍会先吃掉同一次点按。

查看信息把 `TextData.text` 写到 TMP，再点一次交互关掉。篝火弹窗不改字，预制体上写死「篝火燃起」，自己淡入淡出。点燃那一下的 `isInteracting` 来自 `PlayTargetAnimation("Pick Up Item", true)`。

## 世界与相机

`WorldManager`、雾墙、开战碰撞体在 `Game.unity` 的根物体 `World` 下，该物体未激活。宝箱、篝火、拾取、查看在 `Interactables` 下，该物体未激活。剧情对话在未激活的 `NPCs - Story` 下。这些脚本还在场景里，当前运行进不去。

`WorldManager.Awake` 用 `FindAnyObjectByType<PlayerManager>`。`EventColliderBeginBossFight` 在玩家进入时调用 `ActivateBossFight`：打开 Boss 血条，并 `SetActive` 名单里的 `FogWall`。碰撞体上的 `enemy` 引用是空的。`BossHasBeenDefeated` 会关血条和雾墙，全仓库没有调用方；敌人 `Death` 不通知世界。`FogWall.Start` 会先把自己关掉。

`PlayerCameraManager` 没有单例。玩家 `Awake` 找到相机，相机 `Awake` 再找玩家。跟随、旋转、碰撞在 `LateUpdate`；锁定扫描和 F / 1 / 2 在 `Update`。

三种模式的条件并不相同。旋转把瞄准定义成「非交互且 `aimingMode`」，跟随只看 `aimingMode`，偏移在锁定时看 `curLockOnTarget != null` 而不是 `lockOnFlag`。默认跟随用 `SmoothDamp`。锁定时相机根直接放到玩家位置，朝向只保留水平。瞄准时瞬移到 `cameraTransformWhileAiming`，并把同一偏航写进玩家 `localRotation`。

非瞄准时从枢轴到相机做一次环境层 `SphereCast`。锁定打开后，每个 `Update` 做一次半径 30、无层遮罩的 `OverlapSphere`，再对候选人 `Linecast`。`ChangeLockOnTargetMode.minHP` 没有分支。`CameraRotate` 只订了 `performed`，没有在松开时把输入清零。

## 数据与公共脚本

`TextData` 只有一段 `text`，给 `ViewInfo`。`DialogueTextData` 多了 `isPlayerSaid` 和 `duration`。说话人名字在玩家时写死「你」，否则用 `npc.eStats.cName`。`GameSettingsData` 挂在 UI 预制体的设置窗口上。对话、FPS、锁定是否自动换目标、相机速度，都从 `player.ui.escWin.GetSettingWin().gameSettingsData` 读。没有 `PlayerPrefs`。

`EnumsTypes.cs` 是物品、战斗、界面共用的枚举。`Layer` / `LayerMask` 把层 7 到 11 收成交互、环境、NPC、角色阻挡、玩家。`TagManager` 里这些层的名字是空的。`Func.cs` 只有 `Transform.ResetLocal`，武器挂到手之后用一次。`DestoryAuto` 在 `Start` 里延时销毁自己，挂在血溅和爆炸预制体上。
