# 版本候选池

还没写进开发计划的候选。六个开关与 [`.cursor/rules/version-workflow.mdc`](../../.cursor/rules/version-workflow.mdc) 一致。开表示这条成立，关表示不成立。

前两档是硬条件：不引入美术；不引入过多人工（Edit Mode 能收口）。后四档（非高风险、质量大于 2%、完整度约 1%、五小时内）放在一起看，不按先后压过去。已经写进开发计划的顺序不在这里重排。

1. 不引入美术等多媒体资源。Unity 自带的 uGUI（文本、Image、已有窗口上加一格）不算。新贴图、新模型、新动画、新音效算。
2. 不引入过多人工流程。要人进游戏操作或看画面才算通过的，算人工流程。Edit Mode 能断言的不算。必须人看的验收写进游戏设计，以后再补，不因此把这一版排后。
3. 非高风险。高风险指：这次改错之后，后面的版本会站在错的结果上，而且很难拆开重来；或者错了之后运行起来不容易从字段或 Edit Mode 里看出来。常见会落到这两条上的，要在该条里写明错在哪、为什么难拆或难发现：改已经写进场景或预制体的序列化，而且旧数据会被读错或丢掉；给已经有多处读取的旗标再加一个写入方，写错会静默改掉那些读取方；一次打开会连带出别的未激活物体；战斗或 AI 只有玩过才能发现不对，并且后面的招式或阶段建在这段上。只是以后会读到这个新数字，或在已有窗口上加一格、没有旧数据被读错或丢掉的显示，不算。

一份文档 2 到 12 条。同一组六个开关超过 12 条时，文件名末尾加 `-1`、`-2`，份与份之间不比先后。只剩 1 条、并且只差「五小时内」或只差「质量大于 2%」时，并进同一份，文件名写开或关。行为没定的在 [未入池.md](未入池.md)，六个开关未定，不写进下表。

质量大于 2 才算质量开。写成 2 的仍是质量关。完整度记成的数达到 1（含记成 2）算完整度开。工时小于或等于 5 小时算五小时内开。对代码质量的提升对照 `Docs/代码分析`。单独一版到不了 2 个百分点时，质量这一档算关，和风险、完整度、工时放在一起看。完整度指让复刻《黑暗之魂 3》的进度向前约 1%。对照 `Docs/需求文档` 里还没做到的可观察结果。修一个玩家几乎碰不到的边角、或行为不变的收拢，不算。已经在 5 小时内的，不再比谁更短。

质量分母按代码分析四篇里、0.1–0.34、1.0–1.15、2.1–2.4 还没收掉的缺口，收成八组、合计 100：超长类 16（相机约 10，设置窗约 6）；四条过长签名 12；同一数值写两遍约 8 处共 16（每处约 2）；命名、拼写和错误注释 10；每帧查询与命中分配 12；三套 AI 与敌人根运动 12；三处结果读不到共 12；无读取方约五处共 10。完整度分母约 129 条还没做到的可观察编号。一条玩家正常会走到的编号记 1%，两条记 2%，行为不变记 0。
