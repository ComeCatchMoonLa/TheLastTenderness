# 版本候选池

还没写进开发计划的候选。五个开关与 [`.cursor/rules/version-workflow.mdc`](../../.cursor/rules/version-workflow.mdc) 一致。开表示这条成立，关表示不成立。

前两档是硬条件：不引入美术；不引入过多人工（Edit Mode 能收口）。后三档（非高风险、1 个以上 FR、五小时内）放在一起看，不按先后压过去。已经写进开发计划的顺序不在这里重排。

1. 不引入美术等多媒体资源。Unity 自带的 uGUI（文本、Image、已有窗口上加一格）不算。新贴图、新模型、新动画、新音效算。
2. 不引入过多人工流程。要人进游戏操作或看画面才算通过的，算人工流程。Edit Mode 能断言的不算。必须人看的验收写进游戏设计，以后再补，不因此把这一版排后。
3. 非高风险。高风险指：这次改错之后，后面的版本会站在错的结果上，而且很难拆开重来；或者错了之后运行起来不容易从字段或 Edit Mode 里看出来。常见会落到这两条上的，要在该条里写明错在哪、为什么难拆或难发现：改已经写进场景或预制体的序列化，而且旧数据会被读错或丢掉；给已经有多处读取的旗标再加一个写入方，写错会静默改掉那些读取方；一次打开会连带出别的未激活物体；战斗或 AI 只有玩过才能发现不对，并且后面的招式或阶段建在这段上。只是以后会读到这个新数字，或在已有窗口上加一格、没有旧数据被读错或丢掉的显示，不算。

一份文档 2 到 12 条。同一组五个开关超过 12 条时，文件名末尾加 `-1`、`-2`，份与份之间不比先后。只剩 1 条、并且只差「五小时内」时，并进同一份，文件名写开或关。并完之后仍只有 1 条的，单独成文。行为没定的在 [未入池.md](未入池.md)，五个开关未定，不写进下表。

单独计入的 FR 达到 2 条算 1 个以上 FR 开。条目里写明不另计、或写成同一眼的，不算第二条。只有 1 条算关。工时小于或等于 5 小时算五小时内开。对照 `Docs/需求文档` 里的 FR。行为不变的收拢不算进 FR。已经在 5 小时内的，不再比谁更短。
