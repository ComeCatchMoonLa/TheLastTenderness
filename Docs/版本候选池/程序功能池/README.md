# 程序功能池

还没写进开发计划的候选。三个开关与 [`.cursor/rules/version-workflow.mdc`](../../../.cursor/rules/version-workflow.mdc) 一致。开表示这条成立，关表示不成立。

选择优先级：不引入美术、不引入人工、非高风险。同一档里开优先于关。下表按这个顺序排。已经写进开发计划的顺序不在这里重排。

1. 不引入美术等多媒体资源。Unity 自带的 uGUI（文本、Image、已有窗口上加一格）不算。新贴图、新模型、新动画、新音效算。
2. 不引入人工。单元测试和 reviewer 能基本覆盖验收、并且不用新拼一页界面的，算开。要新拼一页，或一页里要选一排东西，算关。已有窗口上加几个字仍算开。验收盖不住的也算关。
3. 非高风险。高风险要同时满足两点。改动（主要指代码）比较复杂。并且：这次改错之后，后面的版本会依赖这些错误的实现，以后再发现时已经无法简单修复；或者正确性测试过度依赖于运行时调试。要在该条里写明复杂在哪，以及是依赖错的实现，还是只能靠运行时调试才能看出来。

同一组三个开关写在同一份里。只剩 1 条的单独成文。下表只列 M1 到 M6 会开工的版本。M7 到 M11、前置链路堵塞，以及目前不规划的，在 [未入池.md](未入池.md)。

每份文件里先列全都解锁，再列还未解锁完。全都解锁指程序前置条件和需求前置条件都以「无」起句。程序前置条件看代码和已收尾版本。需求前置条件看这条「做什么」在需求里是不是已经写成同一句；条目写明不选的待核对，不算还要等。这个分法不改上面的选择优先级。
