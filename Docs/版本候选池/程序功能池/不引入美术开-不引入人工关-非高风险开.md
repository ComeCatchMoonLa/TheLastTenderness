## 全都解锁

### 死亡后送回上次的火

- 类型：fix（0.x）
- 是否不引入美术：是，不新做死亡演出，也不新做界面。
- 是否不引入人工：否，死亡动作结束后人站回火边、又能操作，要在场里看。位置、死亡标记、两瓶次数能断言。
- 是否非高风险：是，调用已有的送回、回满和近战休息恢复，不新写死亡结算。
- FR：[`燃火休息与死亡惩罚`](../../需求文档/功能需求/燃火休息与死亡惩罚.md) FR-燃火-08
- 工时：约 2 小时。不拼界面
- 程序前置条件：无。`ReturnFromDeath`、`ForfeitSouls`、余烬熄灭和休息回满已有。死亡之后没有调用送回。
- 需求前置条件：无。死亡动作播完后回到上次坐下的火、清掉死亡、精力专注回满、两瓶补满，FR-燃火-08 已写。全图重置和清异常是 FR-燃火-09，本条不选。
- 做什么：死亡动作结束后，人回到上次坐下记下的那堆火。清掉死亡。生命补到熄灭余烬之后的上限，精力、专注回满，两瓶按当前分配补满。已经打死的近战走现在的休息恢复。不读四项菜单。从没坐下过时不另送一堆默认火。

- 是否不引入美术：是，死亡点放一个几何体，和钥匙同一档。不做绿色血光，代码里不做粒子。
- 是否不引入人工：否，几何体出现、交互后消失，要在场里看。加上的灵魂数能断言。
- 是否非高风险：是，个数仍走已有的留下和捡回，不另写一笔灵魂账。
- FR：[`燃火休息与死亡惩罚`](../../需求文档/功能需求/燃火休息与死亡惩罚.md) FR-燃火-05、FR-燃火-06、FR-燃火-07
- 工时：约 2.5 小时。几何体在死亡点生成，不另摆
- 程序前置条件：无。`ForfeitSouls` 和 `RecoverRemnant` 已有。场上没有残留物体，捡回没有调用方。
- 需求前置条件：无。带着灵魂死去会在死亡点留下可交互残留，捡回后加回那一笔，再死只留新的一笔，FR-燃火-05 至 FR-燃火-07 已写。身上是 0 时按不生成残留验收。戒指让死亡不掉魂仍待实机，本条不选。
- 做什么：带着灵魂死去，死亡点出现一个几何体。走到跟前交互，几何体消失，灵魂加回那一笔，不进背包。没捡再死，旧的消失，只留这次身上的一笔。身上是 0 时不生成。

- 程序前置条件：无。扣魂加级和三项预览已有（2.27、2.83）。没有对话去调用。
- 需求前置条件：无。防火女对话里够魂才加一级，光标停在生命、蓝或精力上时确认后的上限等于预览，FR-养成-05、FR-属性-04 已写。篝火四项里没有升级。负重预览不在，本条不选。

### 三条上限变了满格跟着变长

- 类型：fix（0.x）
- 是否不引入美术：是，拉长已有的生命、精力、专注三条，不新做火焰贴图，不做出角色身上的火星。
- 是否不引入人工：否，满格变长要在画面上看。上限数字变了能断言，满格该拉多长没有写死的像素。
- 是否非高风险：是，只改这三条满格的长短，不改上限怎么算。
- FR：[`属性与升级`](../../需求文档/功能需求/属性与升级.md) FR-属性-01、FR-属性-04，[`周目与结局`](../../需求文档/功能需求/周目与结局.md) FR-周目-01。余烬条上的火和角色火星仍待裁定，本条不选
- 工时：约 4 小时
- 程序前置条件：无。三条都已把滑动条最大值写成上限。外框宽度不动，所以上限变了，满格看起来仍一样长。
- 需求前置条件：无。生命、精力、专注的上限变高时满格变长，变低时变短，FR-属性-01 已写。余烬把生命上限提高后条变长，是同一句，不是单独一条。
- 做什么：生命、精力、专注这三条，各自的最大值变高时满格变长，变低时变短。当前值仍按这条新的满格去填。加点、余烬和以后改上限的装备都走这一处。不新做条上的火，不做出角色身上的火星。

### 开战不再绕 World 父链

- 类型：refactor（1.x）
- 是否不引入美术：是，不换雾门、血条和声音，只把已有雾门改挂到地图下。
- 是否不引入人工：否，战斗进行和雾门开关能断言。雾门挂在地图下、挪地图时一起动，要在场景里看。血条填充仍给人看。
- 是否非高风险：是，玩家看见的开战、退不出、死亡收雾门和收血条不变。
- FR：[`场景机关`](../../需求文档/功能需求/场景机关.md) FR-机关-05，[`头目`](../../需求文档/功能需求/头目.md) FR-头目-03、FR-头目-06
- 工时：约 5 小时
- 程序前置条件：无。开战状态已在 `WorldEventManager`。`BossFightGate` 和 `NewCycle` 已按类型找它。
- 需求前置条件：无。走进雾门出血条、战斗中退不出、死亡后雾门撤掉并收起血条，这三句已写。雾门挂在哪一层不是需求里的另一句。
- 做什么：碰撞体和头目按类型找到这一处开战，不再经过 `WorldManager`。血条的打开和收起从 `WorldUIManager` 并进这一处。雾门和开战碰撞体改挂到地图下，挪地图时一起动。血条画布不跟着地图。战斗进行时雾门开着、血条开着，死亡后都关掉。不把雾门改成交互物，不为 `World BGM` 新建播放，不把场地机关和协助加厚拆出这次开战。不把这根屏幕血条并进 `Global UI`，见「头目血条并进 Global UI」。

### 头目血条并进 Global UI

- 类型：refactor（1.x）
- 是否不引入美术：是，不换血条样子，只把已有的屏幕血条改挂到 `Global UI`。
- 是否不引入人工：否，开场不出现、开战出现在屏幕血条上、死亡收起，要在画面上看。滑条开关能断言。
- 是否非高风险：是，走进雾门出血条、死亡收起不变。退不出仍读战斗进行，不读这根条挂在哪。
- FR：[`头目`](../../需求文档/功能需求/头目.md) FR-头目-03
- 工时：约 4 小时
- 程序前置条件：无。`UIBossHealthBar` 已按类型查找。与「开战不再绕 World 父链」互不前置，两版不要并成一版。
- 需求前置条件：无。走进雾门后出现带名字的头目血条，打中下降，死亡收起，FR-头目-03 已写。
- 做什么：`Boss Health Bar` 从 `World Canvas` 改挂到 `Global UI`。`World Canvas` 是屏幕空间画布，不是场景界面；头顶短血条仍挂在角色身上。开场这根长条不出现。开战时打开，死亡时关掉。不能只靠 `World` 整块关着来隐藏，因为 `Global UI` 一直开着。`UIBossHealthBar.Start` 会关掉滑条，而 `SetUIHealthBarToActive` 没有调用方，开战要真正把滑条打开。
