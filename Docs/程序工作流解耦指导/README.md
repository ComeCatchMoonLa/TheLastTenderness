# 程序工作流解耦指导

> 程序写运行规则和动词。对方下一次会改的内容放在他们能打开的资产上。空着的必填不能变成一个能玩的结果。

原则在 [`.cursor/rules/authoring-boundary.mdc`](../../.cursor/rules/authoring-boundary.mdc)。本文是通用合同，不写某一个项目有哪些字段。

编译等待和自研工具的维护不能交给策划或美术。它们为什么算时间占用、为什么交不出去，见 [`时间占用.md`](时间占用.md)。本文不展开构建流程，也不要求为了解耦先做一套编辑器。

## 四问

每次加一个行为，先看对方下一次要改的是哪一类：

1. 数值、引用、曲线、表 → 策划资产。见 [`策划数据.md`](策划数据.md)。
2. 层级、样式、模型、材质、特效、灯光 → 美术资产。见 [`美术与界面.md`](美术与界面.md)。
3. 片段时间点、混音、台词、已有动词的排列 → 动画、音频、文案或关卡资产。见 [`动画声音与文案.md`](动画声音与文案.md)、[`行为与关卡.md`](行为与关卡.md)。
4. 新的结算或新动词 → 留在代码里，收成可复用动词，不按这一条内容写死。

前三类还要同时满足下面两条，缺一条就还没有交出去：

- 非法值在进入该内容前被拒绝，报错带资产名和字段路径。
- 对方还没交文件时，程序能靠空位继续写动词；空位过不了校验。

例子：改攻击力是第 1 问，挪按钮是第 2 问，换脚步声或改一句台词是第 3 问，新的伤害公式是第 4 问。

## 对着这次改动核对

1. 对方下一次要改的字、数、引用、外观、时间点、排列，是否还写在代码字面量里。
2. 缺了必填时，入口是否报出资产名和字段，然后停住。
3. 新代码是一个可复用动词，还是只服务这一条内容。
4. 没被当前任务点到的旧字段，有没有为了统一被改掉。

第 4 问的内容若被写进无界的图或脚本，结算、存档和公式就回到程序身上，而且更难读。动词名单保持闭合。见 [`行为与关卡.md`](行为与关卡.md)。
