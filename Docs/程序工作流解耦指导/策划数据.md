# 策划数据

> 数值、引用、曲线和表放在策划能改的资产上。程序留下结算和校验。漏填要在进入该内容前被拒绝，不能靠一个看起来合理的默认值混过去。

配置校验是这条合同的一环，不是全部。改攻击力不应改代码；新的伤害公式仍然改代码。

## 对方改什么

策划改的是结算已经确定之后的内容：

- 标量：攻击力、冷却、价格、权重。
- 引用：这条效果用哪份资产、这个刷新用哪张表。
- 曲线：加速、手感、随等级变化的系数。采样公式在代码里，形状在资产上。
- 表：掉落、刷新、商店、遭遇参数。代码按行执行，不把每一行写成一个分支。

对方下一次若要改的是「怎么结算」（暴击改成另一套公式、存档多一个字段），那是新动词或新结算，留在代码里，收成以后还能被表调用的形式。

11 bit 在《Frostpunk》的 GDC 演讲里把这件事定成生产目标：非程序成员要能加内容。Lasengle 的 Yusuke Iida 在 2023 年游戏开发报告里补充了形式：数据要能批量改，免得为了一个数把资源全部重新导出。

## 程序留下的合同

进入该内容，指开始使用这份资产的玩法：加载关卡、生成这个角色、打开这份表所驱动的系统。不是要求启动时扫完整库，除非这份资产在启动时就会被用到。

### 三类字段

| 字段 | 默认值 | 做法 |
| --- | --- | --- |
| 必填（id、名称、数值、引用、引用列表、必填曲线、必填表） | 校验会拒绝的值。不写初始化器：数值为 0、引用为 null、列表为空、曲线为空。0 本身合法时，用 -1 表示未填 | 漏填在进入该内容前被拒绝 |
| 模板（每个实例相同，有设计出处） | 可以写设计值 | 出处写在字段旁，不写在散落的兜底分支里 |
| 可选 | 默认就是不启用 | 空列表、false、空引用只表示没启用 |

分不清是模板还是占位时，按必填处理。

曲线和表用同一套，不单独开例外：

- 必填曲线不能留着引擎默认的空曲线通过。设计就是一条直线时，把这条直线写在资产上，并在字段旁写明出处，按模板处理。
- 必填表不能是空表。空表只有在字段是可选、且空表示「不启用这套表」时才合法。
- 表内每一行的必填格同样区分未填和合法值。未知 id 不跳过。

### 枚举

默认 0 会落在第一个成员上，校验拦不住。新枚举从 1 开始，或把 0 留给不合法的哨兵。已有枚举不改编号。要改编号时，资产迁移和代码放在同一次提交。

### 报错

校验信息带资产名和字段路径，让人能在 Inspector 里定位。表内错误还要带上行号或行 id。

```csharp
// 漏填被吞掉：非法配置继续跑
if (weapon == null) return;

// 进入该内容前拒绝，并带上资产名和字段
if (weapon == null)
    throw new InvalidOperationException($"{assetName}.weapon 未填");
```

上面是示意，不是要求每份资产都抛同一种异常。入口要停住，并且人能从信息里找到资产和字段。

## 空位

空位是为了程序不被策划的进度卡住。可以先写结算和动词，引用先空着。

空着的必填不得变成一个能玩的结果。进入该内容前报出资产名和字段，然后停住。可选字段的空表示不启用，不能被读成一套默认玩法。

## 做与不做

| 做 | 不做 |
| --- | --- |
| 结算读资产上的数、曲线和表 | 把会改的数写成代码字面量 |
| 未填和合法值能分开，进入前拒绝未填 | `if (x == null) return`、未知 id 跳过、取不到就用默认值 |
| 0 合法时用哨兵表示未填 | 用 0 同时表示「没填」和「设计就是 0」 |
| 模板值写在资产上，出处写在字段旁 | 在代码分支里塞一个「忘了配就用这个」 |
| 改资产上的数不再为这个数改代码 | 为了这个数做热重载框架；本文不要求运行中改完立刻生效 |

## 何时仍要改代码

- 新的结算方式、新的存档字段、新的比较规则。
- 表需要一个以前没有的列，且这列会改变怎么结算。先加动词或字段模式，再让策划填。
- 枚举要新增一种设计上的类别。新增成员可以；把 0 号成员的含义改掉，必须连资产一起迁。

改完之后，策划下一次调参仍走资产，不把这一条内容的数字留在新代码里。

## 改字段时核对

1. 未配置必须能和合法值区分开。曲线和表同样适用。
2. 必填字段的 null、空列表、空曲线、空表、默认数值、默认枚举不能通过校验。
3. 可选字段的默认值只表示不启用。
4. 非法配置在进入对应内容前被拒绝。`if (x == null) return`、未知 id 跳过、取不到就用默认值，都算把错误吞掉。
5. 对方下一次要改的数，不在代码字面量里。
