# 美术与界面

> 层级、样式、模型、材质、特效和灯光是美术资产。程序按稳定名字绑定，并在必填空着时停住。程序不新建这些文件来凑能跑。

挪一个按钮、换一张贴图、改一个特效的外观，不应改 C#。

## 对方改什么

- 界面：控件树、位置、样式、贴图引用。uGUI 用预制体或场景里的对象；UI Toolkit 用 UXML 和 USS。两套都可以，同一块界面选定一套，不要在代码里再搭一遍层级。
- 模型、贴图、字体、材质：导入后的资产。程序只保留引用。
- 特效：粒子系统或 VFX Graph 是资产。玩法在约定的时机设置已约定的属性名（强度、颜色、位置），不在代码里搭粒子层级，也不在代码里选贴图。
- 灯光和后处理：放在场景或体积里。程序不写死灯的位置和颜色来凑一版画面。

Unity UI Toolkit 手册写明：可以用 C# 搭界面，但推荐 UXML。UI Builder 给美术和设计在不写代码的情况下改层级和样式。Unity 关于运行时 UI Toolkit 的说明把协作写成：美术改 UXML 和 USS，C# 按名字查询控件并写逻辑，这样改外观和改逻辑不打在同一个文件上。

Griffin 与 Rendered VC 的 2023 报告里，美术的日常痛点包括校验提交、转换格式、管理大库，而不是「再雕一刀」。74% 的美术认为 3D 内容制作成本在变高。所以非法导入和缺资源要在进入该内容前失败，不要等程序打开资源逐个看缩放和压缩。

## 程序留下的合同

- 稳定名字。界面控件、特效属性、材质里玩法会写的参数，各有一份名字。代码按名字取，不按层级顺序取第几个子物体。改名等于改合同，要和引用一起改。
- 逻辑留在代码：点了之后做什么、数据填进哪个控件、特效属性何时写入。外观不留在这段代码里。
- 导入默认值用 Preset，并由 Preset Manager 按导入器类型和目录套用。同一目录下的模型用同一套缩放、动画压缩和材质导入，不把「每个新资源都要程序改一遍导入设置」当成流程。
- 玩法要读的外观参数（受击闪白、溶解程度）做成材质或特效上已有的属性名。新的一种外观算法才改代码；换贴图、改曲线不改代码。

```csharp
// 按合同上的名字取控件，逻辑留在代码里
var confirm = root.Q<Button>("confirm");
if (confirm == null)
    throw new InvalidOperationException($"{assetName}.confirm 未填");
```

上面是 UI Toolkit 的示意。uGUI 用预制体上约定好的引用字段，空引用同样在进入该界面前拒绝。

## 空位

模型、贴图、字体、动画片段、声音、特效预制体可以先空着，程序继续写动词和绑定。

空着的必填不得变成一个能玩的结果。进入该界面、生成该角色或播放该特效前，报出资产名和字段，然后停住。缺字体时不要静默退回某套内置字体把界面显示出来。可选装饰可以没有，没有就表示不显示这件装饰。

程序不新建模型、贴图、字体、动画或声音文件来代替空位。

## 做与不做

| 做 | 不做 |
| --- | --- |
| 层级和样式放在预制体或 UXML/USS | 在代码里 `new` 出按钮、面板和布局来凑界面 |
| 按稳定名字绑定，缺了就停 | 按子物体序号取控件；缺了就跳过这段 UI |
| 特效资产负责外观，代码只写已约定的属性 | 在玩法代码里创建粒子、指定贴图和持续时间来代替特效资产 |
| 同一目录用 Preset 统一导入设置 | 每进一个模型就改一次缩放或压缩 |
| 灯和后处理放在场景里 | 在代码里写死灯光参数来出一版画面 |

## 何时仍要改代码

- 新的控件种类、新的绑定方式、新的玩法要写的材质或特效属性。
- 导入规则本身要变（例如这一类模型必须换一套压缩）。改的是 Preset 或校验，不是逐个资源改完再提交。
- 界面行为变了：确认之后多做一步结算。结算进代码；按钮的位置仍在资产上。
