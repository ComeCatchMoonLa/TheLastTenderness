# 调研：《黑暗之魂 3》本体与两部 DLC

> **调研对象是《黑暗之魂 3》本体与两部 DLC 的可感知玩法系统。** 交付是玩家能操作、能看到结果的系统规则。

## 阅读顺序

1. [`范围.md`](范围.md)：这一轮写哪些系统规则，正文停在玩家能操作、能看到的结果；排期仍看开发计划。
2. [`角色与养成.md`](角色与养成.md)：属性、等级与升级，以及生命、精力和蓝怎样随养成变化。
3. [`装备与建造.md`](装备与建造.md)：武器、防具与戒指的装备，以及注入和强化。
4. [`移动与镜头.md`](移动与镜头.md)：走、跑、冲刺、闪避和跳跃，以及自由镜头、锁定和瞄准。
5. [`战斗系统.md`](战斗系统.md)：近战、远程与施法，以及霸体、硬直和背刺处决。
6. [`魔法与道具.md`](魔法与道具.md)：魔法、奇迹、火焰，以及药瓶等消耗品。
7. [`世界与篝火.md`](世界与篝火.md)：篝火休息、死亡惩罚、余烬和周目。
8. [`界面与场景交互.md`](界面与场景交互.md)：菜单与战斗界面，以及门、机关、拾取一类场景交互。
9. [`敌人与头目.md`](敌人与头目.md)：普通敌人的行为，以及头目的阶段和专属表现。
10. [`角色交互与联机.md`](角色交互与联机.md)：NPC 对话与任务、盟约，以及召唤、入侵和留言。

## 和需求、计划的关系

需求编号在 [`../需求文档/README.md`](../需求文档/README.md)。旧编号是先前那一轮较窄的切片，新编号把完整游戏里还没写入的系统补进需求。

排期入口仍是 [`../开发计划/README.md`](../开发计划/README.md)，这次不改计划。调用链细节在 [`../代码分析/README.md`](../代码分析/README.md)。现有路径上的技术债候选仍以 [`../开发计划/Ver 1.x/README.md`](../开发计划/Ver%201.x/README.md) 为准，调研不把那些修法再排一遍。

正文里的 **待核对** 是信息待验证。两处确定句不一样、或还没写成句子因而挡住排期的，标在 [`../版本候选池/程序功能池/未入池.md`](../版本候选池/程序功能池/未入池.md)。全部待核对项的处置（已核实 / 资产位 / 待实机 / 联机长线）集中在 [`待核对总表.md`](待核对总表.md)；行内标记与总表冲突时以总表为准。
