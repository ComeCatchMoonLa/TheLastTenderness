# 范围

> **调研交付的是完整《黑暗之魂 3》（本体与两部 DLC）的代码相关功能：玩家能操作、能看到结果的系统规则。** 分篇按系统写这些规则。本仓库已有脚本的对照在 [`本仓库对照.md`](本仓库对照.md)，那篇不定义本范围。

新行为挂到已有入口上：角色 Manager、`State.Tick`、`WeaponItemAction`、`TakeDamage`、`StateMachineBehaviour`。结构仍是 `MonoBehaviour`、Animator 的 `StateMachineBehaviour`、`ScriptableObject`。

## 正文写到哪

正文写玩家操作之后进入的状态、扣掉的资源、看到的结果。美术资源、关卡布局、剧情文本、每把武器的数值表各自留在资源、关卡和数据里。调研按系统写规则，数值停在分档和有无。

## 排期

> **排期仍看开发计划，这次调研不改计划顺序。**

入口是 [`../开发计划/README.md`](../开发计划/README.md)。0.x 不加玩法，收的是工程边界和纠错。1.x 候选不加玩法，收的是现有战斗和物品路径的职责，大纲见 [`../开发计划/Ver 1.x/README.md`](../开发计划/Ver%201.x/README.md)。完整游戏里多出来的系统要进排期时，按该入口的开工方式另开版本。本目录不另起版本号。

调用链细节仍在 [`../代码分析/README.md`](../代码分析/README.md)。现有路径上的技术债候选仍以 1.x 大纲为准，调研不把那些修法再排一遍。
