# 非目标

> **本需求交付可操作、可观察的系统行为。** 完成时对照 [项目目标](项目目标.md) 和 [验收方式](验收方式.md)。下面这些留在交付边界外。

## 交付边界

| 玩家能验收的 | 留在边界外 |
| --- | --- |
| 移动、锁定、攻击、施法、受击、处决、死亡、休息、传送、开门、对话和召唤这些行为 | 角色模型精细度、武器外形、场景光照和特效品质 |
| 菜单、状态页、篝火选项、注入菜单里能读到的数字变化 | 关卡怎么铺、哪些房间相连、每面幻影墙和每个箱子的位置 |
| 任务旗标立起之后，对话、商店或敌对跟着变 | 剧情文本、分支台词、每名 NPC 的故事走向 |
| 盟约、召唤、入侵、留言和别人的血渍能被操作并看见结果 | 线上服务器运维、账号、反作弊和匹配服务的部署 |
| 灵魂增减、属性加减、药瓶次数、强化加号、注入后的伤害种类 | 每件装备、每条法术、每只头目的数值大全和招式表 |
| 沿用角色 Manager、物品动作、伤害碰撞体、敌人 `State`、现有 HUD | 另一套战斗核心、事件总线、依赖注入、实体组件系统 |

资料片《艾雷德尔的灰烬》《环印城》要验收的是它们带进来的同类行为（例如教堂枪兵的头目血条）。地图路线和剧情文本同样留在边界外。

## 数值

伤害、精力消耗、恢复速度、负重分档、法术栏门槛、周目倍率、盟约上交数量的具体数字，与调研中待核对项一致，写在资产和检视器上。需求只固定玩家能看见的结果：扣血、回精力、翻滚档位彼此分得开，旗标和菜单项彼此分得开。换一套系数，只要档位和有无消耗仍符合对应编号，就不算需求变更。

## 已有编号的场景前提

已有编号仍在 `Game` 里看。燃火条目的验收允许只把已有的 `CampFireInteractable` 激活后再看。雾墙、头目阶段和未激活物体上的脚本，按新编号 FR-机关、FR-头目验收；旧的 FR-敌人仍用当前场景里的三只近战。
